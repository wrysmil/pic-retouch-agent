## 2. 提交 2：支撑改造

批量要在「一张还没跑完」时就推送逐项状态，且前端要把任务结果透出，这些是本里程碑依赖、但对既有链路无行为变更的小改造：

- `services/runs.py`：`report()` 新增可选 `result` 形参，非空时写 `run.result` 再提交并发布事件；`snapshot()` 增 `result` 字段，SSE 因此能带上逐项快照。既有调用方（营销图、投放尺寸）不传 `result`，行为不变。
- `schemas/run.py`：`RunOut` 增 `result: dict = {}`，`of()` 回填 `run.result`。
- `edits/pixels.py`：`encode(data, image_format)`——jpg 铺白底转 RGB 存 JPEG(quality=92)，其余走 PNG。批量按格式产出用。
- `services/exports.py`：`PackedExport.manifest` 改为 `| None = None`。批量 ZIP 不带 manifest，复用同一数据类。

## 3. 提交 3：批量工具、服务与接口

### 3.1 `app/schemas/batch.py`（新增）

- `BatchOpIn{tool: Literal[六种], params: dict}`——工具名用 `Literal` 死锁，越界直接 422，天然满足「只支持六种」。
- `BatchIn`：`asset_ids`（1–20）、`operations`（1–6）、`formats`（1–2，默认 png）。
- `BatchItemOut{source, status, error, outputs}`、`BatchOut{run, items, created_at}`。

### 3.2 `app/services/batch.py`（新增）

核心是 `apply_op(data, operation)`：把一种处理映射到与单张工具同源的入参模型，再落到纯像素/ provider 操作——

- `remove_background`：`asyncio.to_thread(remove_background, data)`。
- `adjust_image`：`AdjustIn` 校验后 `pop("layer_id")`、滤掉 0 值，`to_thread(adjust, data, **values)`。
- `upscale_image`：`UpscaleImageIn` 取 `scale`，provider `upscale`。
- `replace_background` / `expand_canvas`：`ReplaceBackgroundIn` / `ExpandCanvasIn` 校验后 provider `edit`。
- `prepare_delivery_sizes`：`PrepareDeliverySizesIn` 取比例去重，逐比例 `letterbox`。
- 其余抛 `ValueError`。

`process_asset` 是链式推进：`frames=[原图]`，每步把所有帧展开成下一批帧，最后对每帧按每个格式 `encode`，`_store` 成导出素材。

`execute(session, run)` 是任务 handler：

```python
items = _blank_items([...])           # 每项 {source_id, status, error, output_ids}
await runs.report(..., 8, "准备批量任务", {"items": deepcopy(items)})
for index, item in enumerate(items):
    item["status"] = "running"
    await runs.report(..., 进度, "处理第 i/n 张", {"items": deepcopy(items)})
    source = await assets.get_for_user(...)   # None → failed "素材不存在"
    try: outputs = await process_asset(...)
    except Exception as exc: item["status"]="failed"; item["error"]=str(exc); continue
    item["status"] = "succeeded"; item["output_ids"]=[...]; await runs.report(...)
if all(failed): raise ToolError(items[0]["error"])   # 全失败才判整轮失败
return {"items": items}
```

每落一步 `deepcopy` 一份条目快照写进 `run.result`，SSE 实时反映逐项状态；单张异常被 `try` 兜住只标该条目，整批不中断。

其余：`require_assets`（越权抛 `UnknownBatchAsset`）、`list_for_user`（按 `tool=="batch_process"` 倒序）、`detail`（优先读 `run.result` 的 items，回退按 params 造 pending 项）、`pack`（非成功或无产出抛 `EmptyBatch`，ZIP 内 `images/NN-wxh.ext`）。

### 3.3 `app/tools/batch.py`（新增）

`BATCH_PROCESS`：`queued=True`、`session_required=False`（关键：不绑会话，会话外也能批量），`handler` 转发 `batch.execute`。`app/tools/__init__.py` 在 `PREPARE_DELIVERY_SIZES` 后登记。`app/main.py` 挂 `batches` 路由。`app/agent/graph.py` 加两条批量提示。

### 3.4 `app/routers/batches.py`（新增）

四个端点均带 `summary/description`（对齐本仓库 OpenAPI 风格）：`POST /batches`（归属校验 404、`InvalidParams` 422、成功 202），`GET /batches`（列表），`GET /batches/{id}` 与 `GET /batches/{id}/export`（非 `batch_process` 任务一律按 404，打包空结果 409，成功回 `application/zip`）。

### 3.5 测试 `tests/test_batch.py`（新增）

覆盖：两张去背景各出 1 个导出结果、投放尺寸出三尺寸且 ZIP 含三张、非支持工具 422、他人素材 404、列表可查回。

## 4. 提交 4：批量页面与导航

### 4.1 API 与 hooks

- `api/runs.ts`：`Run` 增 `result: Record<string, unknown>`；`hooks/useRun.ts` 的 `Progress` 纳入 `result`，返回体 `result: current?.result ?? run?.result ?? {}`，与 `candidates` 同款防御（SSE 快照可能缺字段）。
- `api/batches.ts`（新增）：`Batch/BatchItem/BatchInput` 类型与 `batchesApi`（create/list/get/export），`export` 走原生 `fetch` 解 `Content-Disposition` 取文件名回 `ExportPack`。
- `hooks/useBatch.ts`（新增）：`useBatches`、`useBatch`（用 `useRun` 的实时状态决定 `refetchInterval`，未结束 1200ms 轮询、终态触发失效）、`useCreateBatch`、`useExportBatch`。

### 4.2 `lib/batch.ts`（新增）

`BatchTool/BatchOp`、`BATCH_STEPS` 六步的中文标签与提示、`EXPAND_RATIOS`、`BatchDraft` 与 `EMPTY_DRAFT`；`operationsOf` 把草稿按所选步骤编译成 `BatchOp[]`（各步只带自己需要的参数），`draftReady` 给出提交前的中文阻断原因。

### 4.3 `components/ImageDropzone.tsx`

新增 `multiple` 开关：拖放与选择时按 `multiple` 决定单张还是多张 `accept`，提示文案与 `input[multiple]` 随之变化；不传即维持原单张行为，既有调用方不受影响。

### 4.4 `pages/BatchPage.tsx`（新增）

`/batch` 为 `Compose`（多选上传 ≤20、历史素材快选、`Pipeline` 勾选六步并内联其参数、导出格式、`draftReady` 阻断、提交后跳 `/batch/:id`、最近任务列表），`/batch/:runId` 为 `Watch`（顶部总进度 + `live` 状态，逐项卡片显状态/失败原因/结果缩略，仅终态且有成功项时放开打包下载，走 `URL.createObjectURL`）。

### 4.5 路由与导航

`App.tsx` 用 `BatchPage` 替换 `/batch` 占位并加 `/batch/:runId`，移除不再使用的 `PlaceholderPage` 导入；顶部「批量」导航（M2 之前已在 `WorkbenchLayout`）此时指向实页。

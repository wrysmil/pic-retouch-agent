# 对话修图体验实施计划

设计依据：用户已确认的独立聊天 Demo（本机 7326）。本轮直接实施，不增加设计审批。

目标：将 Demo 的任务卡、结果预览、图片上下文输入框和窄屏切换接入现有 React 编辑器；保留真实 API、流式事件、画布工具与额度规则。不引入模拟状态、展示模型选择器或修改后台。

1. 在 `frontend/src/lib/agentPresentation.ts` 集中处理开放轮次判断与真实任务结果图片归属，先写定向测试，防止把当前画布或其他轮次图片误标成历史结果。
2. 拆分 `AgentTaskCard.tsx`、`AgentTurnResults.tsx`，改造 `AgentConversation.tsx`。统一呈现草稿、待确认、执行、完成、失败、取消和需要处理状态；完成后用原生 details 收起步骤；结果只来自对应 run。
3. 改造 `SessionSidebar.tsx`、`MessageComposer.tsx`：暖白墨绿视觉、当前图片上下文、建议填入草稿、输入框内发送按钮。执行期间允许编辑草稿但不发送；请求失败保留草稿；切换会话不串草稿。
4. `EditorPage.tsx` 增加窄屏对话/画布切换，保持画布挂载与已有编辑功能。`ImageWall.tsx` 整理为带文字信息的素材条。
5. 仅在编辑器作用域增加 CSS；确认/取消/重试请求失败可见。运行定向测试、前后台构建、lint，并在浏览器验证真实页面及受控状态夹具。受控夹具只用于验证，不进入生产运行时。

验证重点：真实图片归属、草稿不丢失、不重复提交、流式增量更新、完成折叠、失败重试、取消后续、375/768/1024/1440px 无页面横向溢出、后台构建不受影响。

交付边界：不自动提交或推送。真实模型调用可用性与页面验证分别记录，避免将夹具测试描述为模型实测。

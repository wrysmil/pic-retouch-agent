## 2. `8e75a6a` fix: 拍平保留透明通道

**问题**：像素工具只认一张图，执行前要拍平多层画布，而 `flatten()` 一直硬编码白底。去背景产出的是透明 PNG，经拍平后透明区被压成不透明，后续调色拿到的已经不是原来那张图。

**改动**

| 文件 | 变更 |
|---|---|
| `backend/app/edits/render.py` | 新增 `WHITE` / `TRANSPARENT` 常量；`flatten()` 增 `background` 关键字参数 |
| `backend/app/tools/context.py` | `flatten_session()` 透传 `background` |
| `backend/app/tools/retouch.py` | 只有 `adjust_image_exec` 传 `TRANSPARENT`；去背景仍走白底 |
| `backend/app/edits/pixels.py` | `adjust()` 改 `split + merge` 逐通道处理并原样写回 alpha；晕影 `ImageOps.multiply` → `ImageChops.multiply` |
| `frontend/.../LayerPanel.tsx` | 调色面板点「应用」后滑杆归零 |
| `backend/tests/test_edits.py` | +3 用例：透明像素保持、晕影压暗四角、透明底拍平 |

去背景链路必须留白底——四角采样依赖背景色取 mask，改透明会让抠图失效。这条约束只写在函数 docstring 里，没有断言保护。

### 审查要点

- `ImageOps.multiply` 是按比例混合两张图，暗角被糊成灰；`ImageChops.multiply` 才是逐通道相乘压暗。这是独立的第二个 bug，靠同一个测试发现。
- 前端「应用后归零」是行为变更：若后端失败，用户参数已被清空，无法重试。
- 新增用例是像素级断言（`(2,2)` 处 alpha == 0），依赖 `_png()` 辅助函数构造的固定图，属于白盒断言，后续换素材构造方式需同步改。

## 3. `797ae95` feat: 修图交互跟手化

本批次最大的一笔，24 个文件。核心是把「按住—拖动—松手」的过程从无反馈改成连续反馈。

**3.1 视图手感 — `stores/canvasView.ts`（+118）**

把手势与按钮拆成两类操作：

- 手势/拖拽：直接 `set`，不插值
- 按钮（缩放按钮、适应画布）：260ms ease-out 缓动，`glide()` 用 `requestAnimationFrame` 驱动
- 两类操作入口都先 `stopGlide()`，避免缓动与手势互相打架

滚轮灵敏度重写：此前按固定倍率处理，触控板每帧 delta 只有几个像素、鼠标滚轮一格上百，手感差一个数量级。改为 `capped = clamp(delta, ±50)` 后 `Math.exp(-capped * 0.0035)`，两种设备对齐。⌘/Ctrl+滚轮缩放、普通滚轮平移，缩放仍以指针为不动点。

`setViewport` 在视口尺寸变化时按差值一半补偿位移（`x + grown.width/2`），面板开合与窗口缩放不再让画面跑偏。`fit()` 新增 `options.animate`，首次进入传 `animate: false` 不做适应动画，之后画幅变化才平滑归位。

`ZOOM_STEP` 由 1.2 调到 1.25。

**3.2 调色实时预览 — 新增 `lib/adjustPreview.ts`（124 行）**

按屏幕量级（`PREVIEW_PIXEL_RATIO`）缓存位图后跑 Konva 滤镜，算法与后端 `pixels.adjust` 对齐：

- 亮度、对比度走 256 项查表（`brightnessLut`），对比度轴心取整图平均灰度，与后端一致
- 色彩用三条 `toneLut` 分别处理 highlights/shadows/temperature/tint
- 饱和度、鲜艳度、晕影逐像素算
- **只覆盖九项逐像素运算**，锐化与清晰度是卷积，明确留给「应用」时后端处理
- 全部为 0 时 `toAdjustPreview()` 返回 `null`，画布跳过缓存与滤镜

`hooks/useCanvasImage.ts` 增 `safe` 标记：先按 `crossOrigin='anonymous'` 加载，读不到像素时 `onerror` 退回普通加载，画面照常显示，只是不做实时滤镜。换源时保留上一张图以消除闪白（删掉了原先 `loaded.url === url` 的过滤）。

**3.3 画布交互 — `components/editor/CanvasStage.tsx`（+275）**

滚轮事件分流（⌘/Ctrl 缩放、否则平移）、`CompareDivider` 组件（画布上可拖的分隔线取代原生 range）、裁剪框拖动过程实时贴边且手柄与虚线按倍率反向补偿、图层滑杆改为拖动中写预览松手才提交、跨域读不到像素时安静降级。

**3.4 提示与观感**

新增 `stores/toasts.ts`（49 行）+ `components/ToastHost.tsx`（25 行）：最多同时 3 条、3200ms 自动消失、先标记 `leaving` 播完 180ms 退场动画再移除。新增 `components/editor/CanvasHint.tsx`（9 行）画布上下文提示条。`index.css` +107 行统一滑杆、滚动条、面板滑入动画。

**3.5 数据失效**

StepCard 改为「确实跑过一次才刷新」，并补上 `history` 与 `messages` 的失效。`useRun.ts` / `useSessions.ts` / `useAgent.ts` / `useElementSize.ts` 同步调整。

### 审查要点

- **前后端两份调色算法**：前端 `adjustPreview.ts` 是后端 `pixels.adjust` 的独立副本，任何一侧改公式另一侧就会漂移，且没有一致性测试。这是本批次最大的长期维护债。
- **`useCanvasImage` 换源保留旧图**：为消除闪白，代价是新图解码慢时会短暂显示上一张内容。当前无「当前图与 url 不匹配」的提示，若解码失败且不触发 `onerror`（如超时），会一直显示旧图。
- **超分与改尺寸不是真超分**（见 §5）：`upscale` 走模型重绘，前端展示的「4 倍」实际会被 2048 上限压回。
- 调色面板滑杆拖动中写预览、松手才提交，与 §2 的「应用后归零」是两处不同的交互语义，注意不要混读。

## 4. `9d788ea` fix: 对话回滚后白屏

两处问题叠加，症状都是「撤销一步后编辑区整块空白」。

1. **`CanvasStage.tsx`**：`useEffect(() => setViewport(size), deps)` 写成表达式体，React 会把 effect 回调的返回值当清理函数存下。当前 `setViewport` 返回 void 所以无害，但调用方返回值一旦不是函数，症状与 `AgentConversation` 那处（已在 `3a457e9` 修）完全相同。改为块体。
2. **`EditorPage.tsx`**：原本 `if (isError)` 早返回。撤销触发 `invalidate`，后台刷新短暂失败时 `isError` 为真而 `data` 仍有缓存，旧代码把整个工作台换成整页提示。合并为 `if (!session)`，再在里面按 `isError` 二选一。

### 审查要点

- 合并后，若 `isError` 为真但缓存里有数据，会**继续用缓存渲染且不显示任何错误提示**。这是刻意的取舍（缓存优于整页报错），但用户会看不到刷新失败。需要确认这是期望行为。
- 第 1 处是预防性修复，当前无实际症状；仓库里是否还有其它 `useEffect(() => expr, deps)` 简写建议全局扫一遍。

## 5. `7ea1529` feat: 换背景、扩图、超分

图像服务此前只有文生图一种能力。

**5.1 服务抽象 — `providers/base.py`**

`ImageProvider` Protocol 从 1 个方法扩到 3 个：

- 新增 `EditRequest`（`prompt` / `image` / `count` / `width` / `height` / `negative_prompt`）
- `edit()`：按提示词改已有图。**`width`/`height` 选填是关键**——换背景与局部替换要保持原画幅，扩图要改画幅，同一个接口靠这两个字段区分
- `upscale()`：提高分辨率，不改构图

**5.2 DashScope 实现 — `providers/dashscope.py`（+85）**

编辑接口走 `/api/v1/services/aigc/multimodal-generation/generation`，**不支持异步任务**，只能同步等结果，超时放宽到 180s（文生图仍是 300s 轮询）。`_submit()` 泛化为接收 path + payload。边长约束 `[512, 2048]`，`_fit_edit_size()` 调用前夹到合法区间：先保证短边 ≥512（只放大不缩小），再按长边超限整体等比缩小。`upscale()` 复用 `edit()`，只多一步算目标尺寸。

**5.3 画幅计算 — `ratios.py`**

新增 `cover_size()`：取刚好包住原图的目标比例尺寸，扩图时主体不必被裁切。

**5.4 工具 — 新增 `tools/enhance.py`（125 行）**

三个 `ToolSpec`（`queued=True`、`session_required=True`）共用 `_store()` 产物入库逻辑，差别只在要不要自动采用：

| 工具 | 参数 | 产物 | 是否自动采用 |
|---|---|---|---|
| `replace_background` 换背景 | `prompt`(1-500) / `count`(1-4) / `negative_prompt` | count 张 | `count == 1` 直接切画布；`count > 1` 只进图片墙等点选 |
| `expand_canvas` 扩图 | `ratio` / `prompt` | 1 张 | 是 |
| `upscale_image` 超分 | `scale`(2 或 4，默认 2) | 1 张 | 是 |

两种都写编辑记录、都能撤销。换背景的 `agent_hidden=("negative_prompt",)` 对 Agent 隐藏该字段。`replace_background` 的提示词会加前缀约束「只替换背景，保持主体、光线和边缘不变」。

**5.5 占位实现 — `providers/mock.py`（+63）**

`edit()` 按 prompt 哈希取色相合成：同尺寸当作换背景（主体缩到 0.88 露出新底），异尺寸当作扩图（原大居中）。`upscale()` 用 LANCZOS 真实放大。抽出 `_png()` 复用。

**5.6 前端**

新增 `components/editor/GenerateEdits.tsx`（112 行）：`BackgroundForm`（描述框 + 1/2/4 张选择）与 `ExpandForm`（五档比例选择）。工具栏加「换背景」「扩图」「超分」三个按钮，`editorUi` 的 `panel` 联合类型扩两个值。`ACTION_LABELS` 补三条中文标签。图片墙 tooltip 由「切到这张」改为「采用这张」，与多候选语义对齐。

**5.7 测试基建 — `tests/conftest.py`（+13）**

补上缺失的 `mock_provider` session 级 autouse fixture。此前测试读本机 `.env` 的 `IMAGE_PROVIDER`，在配了真实密钥的机器上直接打线上接口：慢、产生调用费用，且换背景/扩图/超分这类断言精确尺寸的用例天然不稳定。补上后**整轮测试 229 秒 → 23 秒**。fixture 内改完 `settings.image_provider` 必须 `get_image_provider.cache_clear()`，因为 `get_image_provider` 带 `lru_cache`。

新增 8 个用例：`_fit_edit_size` 边界、`cover_size` 三种方向、三个工具各自断言画布尺寸与 `current_asset_id` / `revision` 变化、未登录 401。

### 审查要点

- **4 倍超分实际只有 2 倍**：1024×1024 选 4 倍 → 目标 4096×4096 → `_fit_edit_size` 按 2048 上限等比压回 2048×2048。工具描述写「scale 为 2 或 4」，实际受模型边长上限约束。建议在 UI 上标注实际尺寸或直接限制 scale 2。
- **mock 与 dashscope 的 `upscale` 语义不一致**：mock 是真 LANCZOS 放大，dashscope 是「用提示词让模型重绘到目标尺寸」。这意味着超分测试（断言 640×480）测的是 mock 行为，**生产路径完全没被覆盖**。
- `_edit_payload` 里 `if request.width and request.height`——两者必须同时有值，只传一个会被静默忽略。
- `cover_size` 取「刚好包住原图」意味着原图内容在新画幅中只占一部分，模型需要重绘整张（含原图区域）。这是设计选择，若模型重绘后主体与原图对不齐会有观感问题。
- `mock_provider` 改的是全局 `settings` 对象，session 级 autouse。当前测试串行执行没问题，若将来并行化会有共享状态竞争。
- 新工具全部 `queued=True`，高分辨率编辑同步等待最长 180s，队列串行时单会话可能排队较久。

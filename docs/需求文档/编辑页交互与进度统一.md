# 需求文档：编辑页交互与进度统一

> 项目：pic-retouch-agent（AI 修图智能体）
> 主题：把编辑页的报错文案、切图过渡、选区即时预览、生成进度、按钮态统一到一套体验上
> 日期：2026-10-12
> 前置：拆层后的分层与选区操作、营销图与物料导出、批量像素处理

## 1. 背景与目标

前几个里程碑把工具、图层、选区、导出、批量都补齐了，但把整条链路串起来用一段时间后，编辑页暴露出一批**体验层的裂缝**：它们不是缺功能，而是同一个动作在不同入口里说法不一、进度不一、反馈不一。本里程碑不新增业务能力，专治这些不一致，让「一次编辑」从头到尾观感统一。按性质归为四组：

### 1.1 报错与文案不一致
- 后端接口 422 校验失败的 `detail` 是 `{loc, msg, type}` 数组，前端直接当字符串渲染成 `[object Object]`，用户看不到到底哪里不对；pydantic 自定义校验还带着「Value error,」这种内部前缀。
- 上传 / 打包走原生 `fetch`，错误处理各写各的，和 JSON 请求的文案格式不统一。
- 多步计划里两次翻转在步骤卡片上只显示「翻转」，分不清先横后竖。
- 注册页只在前端提交后才知对错，用户名 / 密码格式没有浏览器原生拦截。

### 1.2 裁切与「只上墙」的历史语义
- 裁剪只缩小画幅、不换素材；此时在图片墙点这张被裁过的图，应当回到它的**原生画幅**，而不是维持裁切后的样子。
- 已拆层（或多图像层）时，换背景 / 扩图 / 超分等整图生成**只进图片墙、不写回画布**，但界面没说清「结果去哪了」，用户以为没生效。
- 这类「画布没变、只多了张墙图」的操作，过去被当成空操作丢弃，编辑记录里找不到这次生成。

### 1.3 选区与切图过渡
- 点选抠图要先算整图 embedding，冷启动时首点后明显卡顿。
- 局部笔刷 / 橡皮、点选在真正落遮罩前没有即时预览，用户看不出圈到了什么。
- 会话切图（切当前图 / 切历史 / 上墙采用）时画布会闪、旧选区残留、加载态缺失。
- 缩放（拖角改图层大小）与「裁切」手势混淆，拖角被误判成在切图。

### 1.4 进度观感
- 排队 / 生成中的百分比是阶梯跳变，观感突兀；provider 侧 RUNNING 阶段进度恒定不动。
- 生成类按钮在别的工具运行时也显示「生成中」，看起来像每个都在跑。
- 进度条、按钮、Toast 的样式与过渡散落在各处，没有统一基元。

## 2. 用户与场景

| 角色 | 场景 |
|---|---|
| 创作者 | 提交换背景失败时，看到「请填写新背景描述」这类中文原因，而不是 `[object Object]` |
| 创作者 | 裁过一张图后在图片墙再点它，画布回到未裁的原生尺寸 |
| 创作者 | 已拆层时点「扩图 / 超分 / 换背景」，界面写明「结果只进图片墙，画布不变」 |
| 创作者 | 一次跑多步「水平翻转再垂直翻转」，步骤卡片分别显示两个方向的文案 |
| 创作者 | 进入点选模式后首个点击几乎即时出遮罩（embedding 进模式已预热） |
| 创作者 | 画笔涂选区时实时看到高亮覆盖，松手才落定 |
| 创作者 | 切会话 / 切图时画布平滑过渡，旧选区不残留 |
| 创作者 | 拖动角点缩放图层不会被当成进入裁切；生成进度平滑爬升 |
| 新注册用户 | 用户名密码格式错误在提交前就被浏览器拦下并提示规则 |

## 3. 功能需求

### 3.1 错误文案与校验拦截 F1

- **F1.1** 所有接口错误（含原生 fetch 的上传 / 打包下载）经统一入口构造，`detail` 为数组时逐项取 `msg`/`message` 用中文「；」连接，并剥掉 pydantic 的「Value error,」前缀；拿不到可读信息时回落到该动作的默认中文文案。
- **F1.2** 翻转按 `direction` 参数细分标签（水平翻转 / 垂直翻转），单步计划、多步计划卡片与口头播报三处同源。
- **F1.3** 注册表单在浏览器侧按后端同源规则（用户名 3–32 位字母数字下划线、密码 6–64 位）先行拦截；登录侧不限长度，便于老账号进入。

### 3.2 裁切回原图与只上墙语义 F2

- **F2.1** 图片墙点回「被裁过的当前图」时，恢复到该素材原生画幅并产生一条可撤销记录；未被裁过则维持当前画布不产生空记录。
- **F2.2** 画布未变但新增了图片墙素材的操作（候选图、拆层后的整图生成）也要留一条编辑记录，避免这次工作在记录里凭空消失。
- **F2.3** 已拆层 / 多图像层时，换背景、扩图、超分的界面文案与悬浮提示说明「结果拍平只进图片墙、画布与图层不变」。
- **F2.4** 离开选择 / 裁切 / 对比模式时，依赖当轮选区的局部替换表单自动收起，不残留遮挡画布。

### 3.3 选区预热与即时预览 F3

- **F3.1** 进入点选前先调一个「准备」接口预热整图 embedding（`matting_provider=corner` 时跳过；`rembg` 下预热失败按错误上抛），真正点击只跑 decoder。
- **F3.2** 画笔 / 橡皮 / 点选在落遮罩前提供本地即时预览层，松手或确认后与后端结果对齐。
- **F3.3** 会话切图（切换当前图、切历史、采用墙图）统一走一致的过渡：旧修订的选区 / 遮罩随修订失效，加载态明确，画布不闪。
- **F3.4** 图层缩放（拖角）与裁切手势解耦，拖角缩放不得被识别为进入裁切 / 选区。

### 3.4 进度与状态观感 F4

- **F4.1** provider 生成阶段进度按时长平滑爬升而非恒定；前端对排队 / 运行百分比做插值缓动，避免阶梯跳变。
- **F4.2** 一次工具运行期间，只有发起它的那个按钮显示进行态；其余按钮同样禁用但不显示「进行中」。
- **F4.3** 进度条、按钮变体、Toast 收敛到统一基元与样式表，页面挂载过渡统一。

## 4. 非功能需求

- **NFR1** 均为体验层修复，不改动工具的业务结果、数据契约与既有接口成功路径。
- **NFR2** 错误文案统一不吞栈：状态码保留，仅规整呈现文本。
- **NFR3** 即时预览为纯前端本地渲染，不新增后端往返；预热是一次额外轻量 POST，失败不阻断正常选择。
- **NFR4** 进度插值只影响观感，最终值与后端上报终值一致。

## 5. 验收标准

- [ ] 提交缺描述的换背景，前端显示中文校验原因，页面不出现 `[object Object]`。
- [ ] 计划「水平翻转再垂直翻转」，步骤标签依次为「水平翻转」「垂直翻转」，播报含「水平翻转、垂直翻转」。
- [ ] 裁成 1:1（240×240）后在图片墙点回该图，画幅回到 320×240 且 revision 加一；未裁时点回不产生新记录。
- [ ] 已拆层时执行换背景 / 扩图，文档与 revision 不变，但编辑记录新增对应动作，界面文案提示「只进图片墙」。
- [ ] 局部替换表单打开后进入裁切模式，表单收起。
- [ ] 注册时用户名 2 位被浏览器原生拦截，登录不拦截。
- [ ] 生成类任务运行时，仅发起按钮显示进行态；进度百分比单调平滑无回退。
- [ ] 拖角缩放图层不触发进入裁切；点选进入前已调用选择准备接口。

## 6. 范围与非范围

**在范围内**：错误文案统一、翻转标签细分、注册前端校验、裁切回原图、只上墙记录与文案、选区 embedding 预热与即时预览、切图过渡统一、缩放与裁切手势解耦、进度插值与按钮进行态、UI 基元收敛。

**不在范围内容**：新增或修改任何工具算法、改变接口成功返回结构、重做整体视觉设计、引入服务端并发 / 缓存新机制。

## 7. 后续依赖

- 本里程碑把编辑页的进度与交互基元收敛统一，后续「拆出文字层可抠原字并编辑文案」可直接复用统一后的按钮 / 进度 / 选区预览组件。
- 只上墙语义（画布未变仍留记录）为后续批量与营销页的进度呈现提供了同一套 `result` 快照约定。

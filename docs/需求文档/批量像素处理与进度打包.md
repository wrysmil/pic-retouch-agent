# 需求文档：批量像素处理与进度打包

> 项目：pic-retouch-agent（AI 修图智能体）
> 主题：对多张图套同一套像素处理链，逐项回报进度并打包下载
> 日期：2026-10-12
> 前置：营销图与物料导出（投放尺寸留白缩放、按会话打包）

## 1. 背景与目标

到这一步，单张图的像素处理（去背景、换背景、调色、超分、扩图、投放尺寸）都已具备，且营销图/投放尺寸把「出物料」串了起来。但电商运营的真实负担是**重复**：一批几十张商品图要走同一套「去背景 + 调色 + 出三个投放尺寸」，逐张在编辑器里点既慢又容易漏步骤。

此前的缺口：

1. **没有批量入口**。所有工具都作用于「当前画布」，一次只能处理会话里的一张图。
2. **进度只有单任务粒度**。既有 SSE 进度是「一个 run 一条百分比」，无法表达「这 20 张里第 7 张失败、第 8 张正在跑」这种逐项状态。
3. **产出散落**。批量跑完的几十张结果没有集中查看与打包的去处。

本里程碑新增一个**面向素材集合、不依赖会话**的批量处理工具：把一组已上传素材按同一条处理链跑完，逐项回报进度，产出统一收进导出素材，并提供整批打包下载。

## 2. 用户与场景

| 角色 | 场景 |
|---|---|
| 电商运营 | 拖入多张商品图，勾选「去背景 + 投放尺寸」，一次提交批处理 |
| 电商运营 | 提交后进入进度页，看到每张图各自的状态：等待中 / 处理中 / 已完成 / 失败 |
| 电商运营 | 某张失败显示中文原因，其余不受影响继续处理 |
| 电商运营 | 全部跑完后点「打包下载」，把整批结果连同尺寸命名打成一个 ZIP |
| 电商运营 | 同一批再套一层「调色」，链式处理：先去背景再调色再出尺寸 |
| 电商运营 | 首页「最近任务」列表回到任一历史批量任务，查看结果并再次打包 |
| 创作者 | 在对话里说「把这批图都去背景出投放尺寸」，Agent 用批量工具而非逐张 |

## 3. 功能需求

### 3.1 批量工具与处理链 F1

- **F1.1** 提供 `batch_process` 工具，作用于**一组素材 id**，不绑定编辑会话，可在会话外调用。
- **F1.2** 支持的处理步骤限定六种：去背景、换背景、调色、超分、扩图、投放尺寸；其余工具（营销图、局部编辑、拆层等）不接受。
- **F1.3** 一次批量至少一张、至多 **20 张**素材；处理链至少一步、至多六步，**按给出顺序链式**：上一步的每张输出都会作为下一步的输入。
- **F1.4** 每步参数由服务端按其对应的入参模型校验，与界面/单张工具同源；换背景缺描述、扩图缺比例等按校验失败处理。
- **F1.5** 结果按所选导出格式（png / jpg，至少一种）分别编码；jpg 铺白底去透明通道。
- **F1.6** 所有产出统一记为导出类素材，写入图片墙，不改动任何会话画布。

### 3.2 逐项进度与容错 F2

- **F2.1** 任务按「每张素材」为一个条目推进，条目状态取 `pending`/`running`/`succeeded`/`failed` 之一。
- **F2.2** 进度事件携带整批条目快照，随处理实时更新，前端据此渲染逐项状态与总进度。
- **F2.3** 单张处理失败只标记该条目 `failed` 并记中文原因，**不中断整批**；其余条目继续。
- **F2.4** 仅当**全部条目失败**时整个任务判失败，回第一条失败原因。
- **F2.5** 条目引用的素材若不存在（越权或已删），记 `failed`，原因「素材不存在」。

### 3.3 批量接口 F3

- **F3.1** 提交接口：先校验素材归属，含非本人素材返回 404；参数校验失败返回 422；成功入队返回 202 与任务信息。
- **F3.2** 列表接口：按创建时间倒序返回当前用户最近的批量任务（默认 20，上限 50）。
- **F3.3** 详情接口：返回任务状态与逐项结果；只接受批量类任务，其它工具的任务一律按「不存在」返回 404。
- **F3.4** 打包接口：把该任务的全部产出打成 ZIP 返回；任务未成功或暂无产出返回 409；非本人或不存在的任务返回 404。

### 3.4 结果打包 F4

- **F4.1** ZIP 内每张产出命名 `images/序号-宽x高.扩展名`，扩展名按素材实际格式。
- **F4.2** 文件名带「批量导出」与日期，用 RFC 5987 编码支持中文。

### 3.5 对话触发 F5

- **F5.1** 系统提示词补充：对多张图做同一套去背景/换背景/调色/超分/扩图/改尺寸时用批量工具；单张精修、营销图、局部编辑与拆层不用它。

### 3.6 批量页面 F6

- **F6.1** 新增路由 `/batch`（编排）与 `/batch/:runId`（进度），顶部「批量」导航由占位改为实页。
- **F6.2** 编排页支持拖拽多张上传（上限 20）并从历史素材快速添加；去重与超限自动忽略。
- **F6.3** 处理链勾选六种步骤，选中后内联展开其参数（换背景描述、调色三滑杆、超分倍数、扩图比例、投放尺寸多选），底部选导出格式。
- **F6.4** 提交前置校验（未选图、未选步骤、换背景缺描述等）给出中文提示并禁用提交；成功后跳转进度页。
- **F6.5** 进度页显示总阶段与百分比、逐项状态与失败原因与结果缩略图；运行中按间隔轮询刷新，终态后停止。
- **F6.6** 进度页仅在全部结束且有成功项时放开「打包下载」，触发浏览器下载 ZIP。
- **F6.7** 编排页展示最近任务列表，点击回到对应进度页。

## 4. 非功能需求

- **NFR1** 批量为排队任务，HTTP 只负责投递与查询，处理在 worker 完成，不阻塞请求。
- **NFR2** 逐项进度复用既有 SSE 与任务快照，不新增推送通道；进度载荷写入任务的 `result` 字段。
- **NFR3** 单张失败隔离，绝不因一张图的异常使整批崩溃或回滚已成功项。
- **NFR4** 参数校验与对应单张工具同源，避免「界面能过、批量过不了」或反之。

## 5. 验收标准

- [ ] 提交两张图的「去背景」批任务，跑完后详情为 `succeeded`，每项恰 1 个导出类结果。
- [ ] 「投放尺寸」批任务单张产出三个尺寸 {1080×1080,1080×1350,1080×1920}，打包 ZIP 恰含 3 张图。
- [ ] 提交含他人素材的批任务返回 404；含不支持工具（如拆层）返回 422。
- [ ] 列表接口能查到刚提交的批任务，`run.id` 与提交返回一致。
- [ ] 未成功的任务打包返回 409；非本人任务详情/打包返回 404。
- [ ] 单张处理异常时该条目 `failed` 带原因，其余条目正常完成，整批判成功。

## 6. 范围与非范围

**在范围内**：面向素材集合的批量处理工具、逐项进度与容错、列表/详情/打包接口、编排页与进度页。

**不在范围内**：跨任务的素材去重与增量处理、批量任务的暂停/续跑/重试单条、把批量结果直接投放到某个会话画布、服务端并发分片（当前按条目串行推进）。

## 7. 后续依赖

- 批量与营销图共用「留白缩放 + 排队进度」基础设施，后续若要出「批量套模板」可复用本里程碑的处理链。
- 后续批量任务的失败重试可依赖本里程碑已落库的逐条 `result` 快照定位断点。

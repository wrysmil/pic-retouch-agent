# 需求文档：评测指标与部署地址

> 项目：pic-retouch-agent（AI 修图智能体）
> 主题：给本地确定性像素工具补一套离线评测口径，并把「容器内互访 / 浏览器访问」两类地址分开，补齐启动与部署说明
> 日期：2026-10-12
> 前置：营销图与物料导出、批量像素处理（投放尺寸留白缩放、格式编码、逐比例产出）

## 1. 背景与目标

到这一步，去背景、调色、留白缩放（letterbox）、投放尺寸、格式编码等**本地确定性像素函数**都已具备，且被营销图、投放尺寸、批量处理复用。但有两处一直缺口：

1. **工具质量无法量化**。改一版抠图或留白算法后，好坏只能靠肉眼看图，没有可回归的分数，也没有「拿自己素材跑一遍看看行不行」的入口。CI 里跑的是接口连通性，不是像素正确性。
2. **部署地址只有一套**。`S3_ENDPOINT` 既被后端容器用来读写 MinIO，又被用来给浏览器签发图片直链。部署 profile 里把 `S3_ENDPOINT` 改成 `http://minio:9000`（容器内网名）后，签名 URL 也变成 `http://minio:9000/...`，浏览器根本打不开；不改又会导致容器之间连不上。二者必须拆成「内网互访地址」和「浏览器可访问地址」。

顺带地，仓库缺一份能照着做的启动 / 部署 / 测试说明。

本里程碑做三件事：一套**面向用户自备素材、纯本地、不入库不联网**的评测口径；把 MinIO 的**两套地址**拆开；补齐 **README** 启动说明。

## 2. 用户与场景

| 角色 | 场景 |
|---|---|
| 开发者 | 改完抠图算法，拿一批自己的商品图跑评测，看 alpha 重合度分数是否不退化 |
| 开发者 | 调整投放尺寸留白逻辑，用「主体是否仍在画幅内」的比例做回归 |
| 开发者 | 只关心输出尺寸对不对，用尺寸命中率指标校验 letterbox / resize |
| 运维 | `docker compose --profile deploy` 起全栈，前端能正常加载 MinIO 图片（签名 URL 指向浏览器可达地址） |
| 新成员 | 照着 README 从零把本地开发栈和容器部署跑起来 |

## 3. 功能需求

### 3.1 评测任务与用例 F1

- **F1.1** 提供命令行入口 `python -m app.eval <数据集目录>`，读取该目录下的 `cases.json` 与素材，输出指标表格。
- **F1.2** 评测只覆盖**本地确定性像素函数**，不调用图片生成 provider、不联网、不落库：去背景、调色、留白缩放、投放尺寸、格式编码、缩放。任务名到像素函数的映射固定。
- **F1.3** 每个用例包含：唯一 `id`、`task`（任务名）、`input`（相对数据集根目录的素材路径）、可选 `expect`（期望图或期望图目录）、`params`（该任务参数，与同名工具入参同源）、`metrics`（至少一个指标）、`thresholds`（可选，覆盖各指标默认阈值）。
- **F1.4** `cases.json` 须为非空数组；出现未知任务名或格式非法，报中文错误并以退出码 2 结束，同时提示参考示例文件。
- **F1.5** 投放尺寸类任务的期望尺寸由比例反查标准画幅得到；留白缩放 / 缩放类任务的期望尺寸直接取 `params` 的宽高；其余任务的期望尺寸取参考图尺寸。

### 3.2 指标与判定 F2

- **F2.1** 提供像素级指标：平均绝对误差 `mae`、峰值信噪比 `psnr`、Alpha 掩膜交并比 `alpha_iou`、尺寸命中 `size`、留白包含度 `contain`（源图主体外接框 letterbox 后仍落在输出画幅内的比例）。
- **F2.2** 指标有明确**方向**：`mae` 越小越好（判定取「≤ 阈值」），其余越大越好（判定取「≥ 阈值」）。方向写死，避免用例误配导致「越差越通过」。
- **F2.3** 每个指标有默认阈值；用例可按指标覆盖。缺期望参考图而指标又必需它时，该用例记为错误而非默认通过。
- **F2.4** 预测图与期望图尺寸不一致时，先把预测图最近邻缩放到期望尺寸再比对，保证逐像素指标可比。

### 3.3 结果呈现与退出码 F3

- **F3.1** 逐用例、逐产出（投放尺寸会一用例多出多个比例）打印一行：用例名（非同名任务带 `/比例` 后缀）、任务名、各指标分值、`ok`/`fail`。
- **F3.2** 末尾打印 `通过数/用例数 passed`；出错用例整行指标显示占位符并附错误原因。
- **F3.3** 全部用例通过返回退出码 0，存在失败返回 1，用例文件本身有问题（找不到 / 格式错）返回 2。

### 3.4 部署地址拆分 F4

- **F4.1** 新增配置 `S3_PUBLIC_ENDPOINT`（默认空）。语义为「浏览器打开签名 URL 的地址」；为空时回落 `S3_ENDPOINT`，本地开发行为不变。
- **F4.2** 后端读写 MinIO 继续走 `S3_ENDPOINT`；**仅签名 URL 的签发**改用 `S3_PUBLIC_ENDPOINT`（空则同 `S3_ENDPOINT`）。二者互不影响。
- **F4.3** compose 的 `app` 与 `worker` 服务在 `.env` 之上用 `environment` 覆盖容器内网地址：数据库/Redis/MinIO 指向服务名（`postgres`/`redis`/`minio:9000`），而 `S3_PUBLIC_ENDPOINT` 固定为浏览器可达的 `http://localhost:7313`。用户无需为容器部署再手改 `.env` 里的 localhost。

### 3.5 启动与部署说明 F5

- **F5.1** README 覆盖：依赖、环境变量（含新拆分的 `S3_PUBLIC_ENDPOINT` 与 `MATTING_PROVIDER`/`OCR_PROVIDER` 说明）、端口一览、本地启动步骤、`--profile deploy` 部署步骤与「容器内地址由 compose 覆盖」说明、测试与评测命令。
- **F5.2** 评测目录约定写入 README：需含 `cases.json` 与自备素材，格式见示例文件，素材不入库。
- **F5.3** 用户评测素材目录（`evals/`）加入版本忽略；评测集示例文件随代码入库，真实素材不入库。

## 4. 非功能需求

- **NFR1** 评测是纯本地计算：同一输入恒得同一分数，可在无网络、无 provider key、无数据库的环境运行。
- **NFR2** 地址拆分对本地默认配置零行为变更（`S3_PUBLIC_ENDPOINT` 空即回落），仅部署 profile 生效差异。
- **NFR3** 评测不改动任何既有工具与接口，是旁路能力；参数口径复用同名工具的入参，避免「评测能过、线上不能过」或反之。
- **NFR4** 评测集与真实素材不入库，示例文件充当契约文档。

## 5. 验收标准

- [ ] `python -m app.eval <目录>` 对缺 `cases.json` 的目录返回 2 并在 stderr 提示 `cases.json`。
- [ ] 自备一个含「投放尺寸 + 调色」两用例的数据集，全通过时退出码 0，表格含 `2/2 passed`。
- [ ] 相同图比对 `mae` 为 0、`psnr` 为满分上限；`mae` 阈值判定取「≤」而 `alpha_iou` 取「≥」。
- [ ] 投放尺寸用例产出比例与请求顺序一致，且尺寸命中指标对标准画幅为 1。
- [ ] 留白缩放的 `contain` 对居中等比内缩输出为 1；`alpha_iou` 对已知交/并掩膜等于手算值。
- [ ] 设 `S3_PUBLIC_ENDPOINT` 后签名 URL 指向该地址且带 `X-Amz-Signature`；清空后回落 `S3_ENDPOINT`。
- [ ] compose deploy profile 下 `app`/`worker` 均带四项 `environment` 覆盖，`S3_ENDPOINT=http://minio:9000`、`S3_PUBLIC_ENDPOINT=http://localhost:7313`。

## 6. 范围与非范围

**在范围内**：本地确定性像素工具的离线评测口径（任务映射、指标、阈值方向、表格与退出码）、MinIO 内外网两套地址拆分、compose 部署地址覆盖、README 启动/部署/评测说明、评测素材目录忽略与示例契约。

**不在范围内**：对生成类工具（文生图、换背景、超分等走 provider 的）的自动评测（结果非确定，需人评或外部模型）；把评测跑进 CI 门禁；评测分数持久化与历史对比看板；对象存储 CDN / 反代域名的更细粒度配置。

## 7. 后续依赖

- 评测口径为后续「拆层抠字质量」「营销图构图质量」等非确定性指标的接入留了统一的用例格式与呈现层，届时只需扩展任务映射与指标。
- 地址拆分为后续接入 CDN / 反向代理的签名基址打好了口子，`S3_PUBLIC_ENDPOINT` 可平滑换成公网域名。

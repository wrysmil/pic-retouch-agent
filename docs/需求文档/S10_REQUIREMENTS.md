# S10 需求文档：像素链路修正、交互跟手化、生成工具扩展、区域编辑

> 项目：pic-retouch-agent（AI 修图智能体）
> 里程碑：S10
> 日期：2026-09-28
> 前置里程碑：S9（编辑会话、画布骨架）、S10 之前已接入工具注册表与确定性修图工具

## 1. 背景与目标

S9 交付了「编辑会话 + 画布骨架」，画布能看、图层能列、工具能调，但真实使用中暴露出五类问题：

1. **调色结果发黑**：像素工具只认一张图，执行前要把多层画布「拍平」。拍平一直固定铺白底，去背景得到的透明 PNG 因此被压成不透明白底，透明区域的信息在链路里丢失，后续调色拿到的底图已经不对。
2. **交互不跟手**：缩放靠固定倍率跳变、滑杆要松手才生效、面板开合让画布跳位、对比滑杆是一个突兀的原生 range，所有「按住—拖动—松手」的过程都没有连续反馈。
3. **对话回滚后白屏**：撤销后触发会话刷新，编辑区整块被空提示顶掉，画面看起来就是白屏。
4. **生成能力只有文生图**：换背景、扩图、超分三类高频需求没有工具入口；换背景出多张时也没有「候选进图片墙、用户点选采用」的路径。
5. **没有区域编辑**：擦除、替换只能整图进行，用户无法指定「只改这里」。

S10 一次性收敛这五项：

- 让像素链路保住透明通道，调色在正确底图上进行。
- 把画布与面板的交互改成连续、可预期、无跳位的。
- 修掉编辑区白屏，让有缓存数据时照常渲染。
- 接入换背景 / 扩图 / 超分三个工具，统一走「多候选进图片墙、点选采用」。
- 接入点选与笔刷两种选区方式，并在此基础上提供局部消除与局部替换。

## 2. 用户与场景

| 角色 | 场景 |
|---|---|
| 创作者 | 对去背景后的透明图调色，出来的图仍保持透明，不会整体发黑 |
| 创作者 | 拖动调色滑杆时画布实时变化，松手才真正写入画布 |
| 创作者 | 反复缩放平移看细节，滚轮捏合与按钮缩放都连续顺滑，窗口大小变化时画布不跑偏 |
| 创作者 | 撤销一步后编辑区继续显示画布，不闪空白 |
| 创作者 | 换背景一次出 4 张候选，在图片墙里挑一张采用 |
| 创作者 | 把 1:1 的图扩成 16:9，主体完整保留在画面内 |
| 创作者 | 图太小，发到详情页糊了，用超分放大到两倍 |
| 创作者 | 画面里有个路人，用笔刷涂掉他，其它部分一点不动 |
| 创作者 | 选中杯子，用一句话把它换成陶瓷马克杯，选区外完全不变 |
| 创作者 | 已经点选好区域，直接对 AI 说「把这里的天空换成晚霞」，AI 不再追问选区 |

## 3. 功能需求

### 3.1 像素链路的透明通道 F1

- **F1.1** 拍平（把多层画布合成一张图交给像素工具）必须支持指定画布底色，默认白底，另有透明底可选。
- **F1.2** 调色链路必须在透明底上拍平。理由：去背景的产物是透明 PNG，拍平若铺白底会把它压成不透明，后续所有调色参数都作用在一张错误的底图上。
- **F1.3** 其它像素工具（去背景、换背景、扩图、超分、局部编辑）仍按白底拍平——它们需要模型能看清完整画面。
- **F1.4** 调色必须逐通道处理并原样写回 alpha：透明像素的 alpha 保持 0，不因任何调色项（尤其是大幅压暗的亮度与对比度）而改变可见性。
- **F1.5** 晕影按逐像素相乘实现，不得使用会做插值混合的算子——否则暗角会糊成一片灰而不是压暗。
- **F1.6** 调色面板点「应用」后滑杆归零，避免同一组参数被连续叠加。

### 3.2 编辑器交互跟手化 F2

- **F2.1 连续缩放**：按钮触发的缩放与「适应」走缓动动画（约 260ms，ease-out），手势（捏合、拖拽）直接跟手不插值。
- **F2.2 滚轮语义**：⌘/Ctrl + 滚轮为缩放（触控板捏合与 ⌘ 滚动都走这一支），普通滚轮为平移，与主流画布一致。
- **F2.3 滚轮灵敏度自适应**：触控板每帧只有几个像素，鼠标滚轮一格上百；先夹住增量再取指数，两种设备手感一致，且缩放以指针为锚点，画面不漂移。
- **F2.4 视口变化锚定中心**：面板开合或窗口缩放导致画布容器尺寸变化时，位移按尺寸差的一半补偿，画面中心保持不动。
- **F2.5 首次落位不动画**：初次进入不做适应动画；后续画布尺寸变化（如裁剪、扩图）平滑归位。
- **F2.6 调色实时预览**：拖动调色滑杆时画布即时反映亮度、对比度、饱和度、高光、阴影、色温、色调、自然饱和度、晕影九项；锐化与清晰度属卷积运算，不进预览，留给应用时后端处理。
- **F2.7 预览必须够快**：滤镜结果按屏幕分辨率量级缓存，参数数值不变时保持同一份滤镜实例，平移缩放不重算。
- **F2.8 跨域降级**：对象存储未放开跨域导致位图不可读像素时，安静退回普通加载——画面照常显示，只是不做实时滤镜预览，不得报错或白屏。
- **F2.9 图层滑杆即时预览**：透明度、缩放、旋转在拖动过程中直接作用于画布，松手才调用工具写入文档；缩放预览需保留原有翻转方向。
- **F2.10 裁剪跟手**：裁剪框拖动过程中实时回写位置与尺寸并夹取到画布内；手柄、描边、虚线按当前倍率反向补偿，缩放后点按面积与线宽在屏幕上保持一致。
- **F2.11 对比分隔线可拖**：对比滑杆从底部原生 range 换成画布上的可拖分隔线，随画布一起缩放平移，手柄与线宽保持屏幕尺寸不变。
- **F2.12 面板与提示**：图层面板改为覆盖在画布右侧的浮层并带滑入动画；画布上方提供一行上下文提示（处理进度 / 裁剪说明 / 对比说明 / 选区说明），随当前模式切换。
- **F2.13 视图快捷键**：`0` 适应窗口、`1` 实际像素、`+`/`-` 缩放；画布内双击同样适应窗口。快捷键不带修饰键时不得与浏览器自身缩放冲突。
- **F2.14 控件观感统一**：滑杆统一为细轨道 + 浮起滑块，hover/active 有过渡；面板滚动条弱化处理。
- **F2.15 全局提示**：需要即时反馈的操作结果（失败原因等）走统一的轻提示，3.2 秒自动消失，最多同时保留 3 条，可点击提前关闭。

### 3.3 编辑区渲染健壮性 F3

- **F3.1** 副作用回调必须以块体书写、显式不返回值。React 会把回调的返回值当作清理函数存下并在下次重跑时调用；若返回值不是函数（如新版浏览器 `scrollIntoView()` 返回的 Promise），调用即抛错；项目没有 ErrorBoundary，整棵组件树被卸载，表现为白屏。因此 effect 一律写成块体，不依赖被调函数的返回值。
- **F3.2** 会话详情的错误态与加载态合并判断：**只有在确实没有数据时**才渲染占位。撤销等操作触发的后台刷新可能让请求短暂报错，此时若已有缓存数据必须照常渲染工作台，不得把编辑区替换成整页提示。

### 3.4 生成类工具扩展 F4

- **F4.1 换背景 `replace_background`**：入参 `prompt`（1–500 字）、`count`（1–4，默认 1）、可选 `negative_prompt`。保留主体、光线与边缘，只替换背景。
- **F4.2 扩图 `expand_canvas`**：入参 `ratio`、可选 `prompt`（默认「自然延伸画面边缘，保持主体完整」）。把画布扩到目标比例并补全新区域，**主体不得被裁切**——目标画幅须刚好包住原图。
- **F4.3 超分 `upscale_image`**：入参 `scale`（2 或 4，默认 2）。只提分辨率，不改构图与内容。
- **F4.4 多候选采用规则**：`count == 1` 时产物直接切成当前画布图；`count > 1` 时产物只进图片墙，不自动上画布，由用户点选采用。无论哪种都写编辑记录、都能撤销。
- **F4.5 模型能力扩展**：图像服务需同时提供「按提示词改已有图」与「提高分辨率」两种能力；编辑接口的输出边长有下限约束，调用前需把尺寸夹到合法区间。
- **F4.6 本地占位实现**：不调真实模型时，上述两个能力也要有确定性占位版本，保证链路与测试可跑通。
- **F4.7 界面入口**：工具栏新增「换背景」「扩图」「超分」。换背景与扩图各配一个面板（写描述 / 选比例），超分直接按两倍执行。

### 3.5 区域选区与局部编辑 F5

- **F5.1 选区两种方式**：
  - **点选**：点击物体建立选区，可连续点选累积标点；标点按顺序编号并在画布上以徽标显示。
  - **笔刷**：按住涂抹画出选区，笔刷半径可配置。
- **F5.2 坐标约定**：选区坐标一律用画布内的归一化值（0–1），与视图缩放平移无关。
- **F5.3 选区与修订号绑定**：选区记录建立时的 `revision`；画布一旦变化（采用新图、裁剪、任何编辑）旧选区立即失效，读写都按当前 `revision` 判定，不匹配即拒绝。
- **F5.4 选区存储**：遮罩以素材形式落库并附一份轻量指针（修订号 + 遮罩素材 ID + 标点列表），指针带 24 小时过期时间，避免长期堆积。
- **F5.5 选区可视化**：画布上以半透明着色显示遮罩，点选标点显示编号徽标，笔刷涂抹过程中实时画出草稿笔画。
- **F5.6 局部消除 `erase_region`**：消除选区内物体并用周围背景自然填补，无提示词时使用默认指令。
- **F5.7 局部替换 `replace_region`**：入参 `prompt`（必填）。指令必须显式约束「只改选中区域，选区外的画面保持原样」。
- **F5.8 合并策略**：模型返回的整图结果按遮罩合成回原图，遮罩边缘做轻微羽化；模型输出尺寸与原图不一致时先缩放到原图尺寸再合成。
- **F5.9 失败可读**：修订号不匹配提示「画布已更新，请重新选择」；没有选区提示「请先点选或涂抹要修改的区域」。
- **F5.10 执行后清空选区**：局部编辑成功后选区作废，避免同一选区被连续作用于两张不同的图。
- **F5.11 界面入口**：工具栏进入选区模式后提供「消除」「替换」「清除」「完成」；无选区时相应按钮禁用并给出原因。
- **F5.12 对话感知选区**：给规划模型的画布摘要需说明当前有无选区及其类型；摘要标明已有选区时，模型可直接调用局部消除/替换，不得再要求用户重选。
- **F5.13 模式互斥**：裁剪、对比、选区三种模式互斥，进入其一自动退出其余；`Esc` 退出当前模式。

## 4. 非功能需求

| 编号 | 类别 | 描述 |
|---|---|---|
| NFR1 | 正确性 | 像素链路不得破坏已有图的透明通道；局部编辑不得改动选区外像素 |
| NFR2 | 性能 | 实时预览与手势渲染不得掉帧；预览滤镜需缓存，参数未变时不重算 |
| NFR3 | 交互一致 | 同类控件的过渡时长、缓动、按下反馈在全局统一 |
| NFR4 | 健壮性 | 任一前端 effect 不得返回非清理函数的值；有缓存数据时不得因刷新失败丢界面 |
| NFR5 | 状态正确性 | 选区与画布修订号强绑定；画布变化后旧选区必须失效 |
| NFR6 | 可撤销性 | 新增的换背景/扩图/超分/局部编辑全部进入编辑历史，可撤销 |
| NFR7 | 降级可用 | 跨域受限、模型不可用时以明确提示或安静降级呈现，不白屏、不崩溃 |
| NFR8 | 隔离 | 选区接口与素材一样按用户隔离，未登录 401，他人会话 404 |
| NFR9 | 前端工程 | `tsc -b` 与 oxlint 通过；后端 pytest 通过 |

## 6. 范围与非范围

**本里程碑范围**：

- 后端：拍平背景可指定；调色透明通道修正；图像服务的编辑/超分能力与协议；换背景/扩图/超分三个工具；选区存储与点选/笔刷两条建立路径；局部消除/局部替换两个工具；选区 REST 接口；规划模型的选区感知。
- 前端：画布手势与缓动、滚轮语义、视口锚定；调色与图层滑杆实时预览；裁剪跟手；画布内对比分隔线；画布提示条；Toast 提示；选区模式与选区叠加层；换背景/扩图/局部替换面板。
- 无数据库迁移：选区遮罩复用既有 `assets` 表，指针存 Redis 并带 TTL。

**本里程碑非范围**：

- 图层拆分（把主体与背景拆成独立图层）
- 选区的存储型编辑（不落 `LayerDocument`，仅作为一次工具执行的输入）
- 局部调整（只对选区调色）
- 批量修图
- 导出下载与营销物料
- 前端组件测试（仍无单测框架，视觉与交互以手动核对为准）

## 7. 后续依赖

- 选区目前是**一次性输入**：局部编辑成功后即清空，不写进 `LayerDocument`。后续做「连续对同一区域反复调整」时，需要把选区纳入画布文档并参与撤销快照。
- `revision` 递增是选区失效的唯一依据。若后续引入不递增 `revision` 的画布变化（如纯视图态），需重新审视该机制是否仍然充分。
- 拆层能力落地后，选区需要支持「按图层」而非「按整张画布」求交，届时 `region` 工具的拍平策略要相应调整。

# S11 需求文档：拆层成层、图层单独操作、素材库收拢

> 项目：pic-retouch-agent（AI 修图智能体）
> 里程碑：S11
> 日期：2026-09-29
> 前置里程碑：S10（像素链路修正、交互跟手化、生成工具扩展、区域编辑）

## 1. 背景与目标

S10 让画布「能看、能选、能局部改」，但画布本质上仍是一张底图加几个变换参数。三类问题在真实使用中暴露出来：

1. **改一处就动全图**。调色、去背、局部消除全部先拍平整张画布再处理。想只把主体调亮一点，或者只换背景，模型看到的却是连主体带背景的整张图，调完主体也跟着变色；局部编辑的结果被写回成新的整张底图，图层结构被抹平。
2. **拆层只能靠模型画**。想把商品从背景里拿出来单独摆，没有「把主体抠成独立图层、原位置补背景」这条确定性路径，只能反复用提示词碰运气。
3. **拆出来的层不能动**。即便拿到多层，画布上也只能看，不能直接选中、拖动、缩放；图层面板只有一行文字，没有缩略图、没有显隐开关，图层与画布之间的对应关系建立不起来。

另外创作页的历史素材是一张平铺的卡片墙：遮罩、抠图中间产物、同一张图反复调出来的几十个版本全混在里面，用户找不到「上次修到哪儿的那张」。

S11 收敛这些：

- 提供两条确定性拆层路径：整图 `split_layers`、选区 `promote_object_to_layer`。
- 让所有像素类工具按图层读写，结果写回指定图层而不是拍平成新底图。
- 画布上直接选中、拖动、缩放图层，图层面板补齐缩略图、显隐、拆层与成层入口。
- 创作页素材按会话收拢，中间产物不再淹没历史。
- 修掉两个被拆层暴露出来的缺陷：撤销连发与空历史写入、拆层时模型把主体又画回背景。

## 2. 用户与场景

| 角色 | 场景 |
|---|---|
| 创作者 | 一张商品图点「拆层」，得到背景与主体两个图层，主体可单独调亮、去背、换位置 |
| 创作者 | 点选画面里的某件商品后点「成层」，它变成独立图层，原位置由背景自然补齐 |
| 创作者 | 在图层面板勾选「同时拆出文字」，拆层后标题文案成为独立文字层 |
| 创作者 | 拆层后点「换背景」，只有背景层被替换，主体像素完全没动 |
| 创作者 | 拆层后在画布上直接拖动主体图层，或拖角缩放，松手即可撤销 |
| 创作者 | 在画布上点选某个图层，图层面板同步高亮，能单独隐藏它看效果 |
| 创作者 | 调色时只想动主体，在面板里选中主体层再应用，背景层不受影响 |
| 创作者 | 回到创作页，看到的是按会话分组的项目列表，而不是一堆混在一起的缩略图 |

## 3. 功能需求

### 3.1 图层文档模型 F1

- **F1.1** 图层文档除底图（`base`）外，需要两个固定图层标识：背景（`background`，锁定）与主体（`subject`）。
- **F1.2** `Layer` 扩展四个字段：`source_hash`（该层由哪份遮罩/主体蒙版产生，用于幂等判定）、`text` / `font_size` / `fill`（文字层内容与排版）。
- **F1.3** 画布变换新增 `set_visible`（绝对显隐）与 `move`（`x`/`y` 绝对坐标、`dx`/`dy` 相对位移，两者至少给一个）。
- **F1.4** 文字层默认锁在图层表末尾，绘制在最前；无 `asset_id`，只由文字内容渲染。

### 3.2 拆层 F2

- **F2.1 `split_layers`**：把整张画布拆成背景层与主体层。入参只有 `include_text`（默认 `false`）。
- **F2.2** 主体由现有抠图能力产出（`remove_background`），其 alpha 通道同时作为主体蒙版复用。
- **F2.3** 背景必须在**挖空之后再修补**：先把主体轮廓外扩若干像素形成空洞，用修复算法（优先 OpenCV inpaint，无 OpenCV 时用边界平均色铺底 + 反复高斯模糊兜底）填上，得到一张确定不含主体的底图。
- **F2.4** 把外扩后的空洞交给生成模型做一次自然衔接时，提示词必须明确「只修补已有缺口，不要新增物体，不要改动其它部分」；模型结果按空洞遮罩合成回修补图，**空洞以外一个像素都不改**。这是拆层后「主体又出现在背景里」的直接对策。
- **F2.5** `include_text` 为真时额外识别文字，每个文字框生成一个 `text-{n}` 文字层；OCR 不可用或被关闭时静默返回空列表，不影响拆层本身。
- **F2.6** 已拆层的画布再调 `split_layers` 直接返回当前文档，不重复执行、不写历史。
- **F2.7** 拆层不切换当前图、不拍平，只改图层文档并新增两份素材。

### 3.3 选区提升为图层 F3

- **F3.1 `promote_object_to_layer`**：把当前选区抠成独立图层，原位置用与 F2.3/F2.4 相同的方式补齐背景。
- **F3.2** 抠出的物体按遮罩包围盒裁剪，图层尺寸为裁剪后尺寸，`transform.x/y` 为包围盒左上角在画布中的位置。
- **F3.3** 图层 id 为 `object-{遮罩哈希}`。同一份遮罩重复提升时命中幂等，直接返回当前文档。
- **F3.4** 未拆层的画布上提升：底图替换为背景层 + 物体层；已拆层的画布上提升：背景层写入补齐结果，其余图像层按各自原点把选区打成透明（`punch`），再把物体层追加到最前。
- **F3.5** 选区为空、遮罩过期、遮罩没覆盖到任何像素时给出可读提示，不落任何素材。
- **F3.6** 执行成功后清空选区。

### 3.4 工具按图层读写 F4

- **F4.1** 像素类工具（去背景、调色、局部消除、局部替换）新增可选 `layer_id`，未指定时取最上层可见图像层。
- **F4.2** 处理结果写回该图层的 `asset_id`，不再拍平成新底图；只有画布上仅剩一个图像层时才顺带把新图切成当前图。
- **F4.3** `replace_background` 在存在背景层时只读背景层像素，替换后写回背景层，主体层完全不动；未拆层时沿用整图拍平的行为。
- **F4.4** 局部编辑的遮罩是画布坐标，执行前要按目标图层原点换算成图层本地坐标；换算后选区与图层无交集时报「选区没有覆盖到该图层」。
- **F4.5** 未显式指定 `layer_id` 时，局部编辑按「选区覆盖到的最上层图像层」自动定位，覆盖不到时退回默认图层。
- **F4.6** `layer_id`、`mask_asset_id`、`revision` 一律对模型隐藏，由界面与服务端上下文填充。

### 3.5 画布直接操作图层 F5

- **F5.1** 图层可点击选中，选中态在画布上描边、在图层面板高亮；选中项与画布保持双向同步。
- **F5.2** 未锁定图层可直接在画布上拖动，松手写入 `move_layer`；拖动阈值内不触发提交。
- **F5.3** 选中图层后拖四角缩放，等比、限幅 0.1×–8×，保留原有翻转方向，松手写入 `scale_layer`。
- **F5.4** 图层拖动/缩放期间画布平移手势临时关闭，松手恢复；裁剪、对比、选区模式下图层不可交互。
- **F5.5** 文字层在画布上按 `text`/`font_size`/`fill` 渲染，可选中、可拖动、可缩放，不可像素处理。
- **F5.6** 图层预览（拖动中的临时位置与倍率）在文档追上后自动撤下，避免图层被拽回原位。

### 3.6 图层面板 F6

- **F6.1** 每层显示缩略图、名称、副标题（文字层显示文案、图像层显示锁定状态或「图像」）、不透明度百分比。
- **F6.2** 每层带显隐开关，调用 `set_layer_visible`。
- **F6.3** 面板顶部提供「拆层」「成层」两个二次确认动作，确认后才执行，避免误触。
- **F6.4** 提供「同时拆出文字」勾选框，决定 `split_layers` 的 `include_text`。
- **F6.5** 调色与局部替换面板自动带上当前选中图层，图层切换时目标随之切换。
- **F6.6** 工具栏的翻转、去背景同样带上选中图层。

### 3.7 历史与撤销 F7

- **F7.1** 一次工具调用若没有实际产生任何东西（文档与当前图都没变，也没新素材入墙），不写编辑历史、不递增修订号、**不截断已有的重做分支**。仅产出候选图的工具仍要留记录。
- **F7.2** 空操作之外的一切产出都进编辑历史。
- **F7.3** 前端 `undo`/`redo` 加并发闸：上一次未落定前忽略新的连点，按住 ⌘Z 重复触发同样忽略；工具执行期间不响应撤销快捷键。

### 3.8 素材库 F8

- **F8.1** 创作页历史素材改为按会话分组：每组是某个编辑会话的图墙集合，标题取会话名，展示封面、数量与更新时间；点击组封面直接回到该会话。
- **F8.2** 没有进过任何会话的上传/生成素材归入「未归入会话」一组，点击则新建会话。
- **F8.3** 遮罩、主体、背景这类会话内部中间产物不出现在素材库里。
- **F8.4** 编辑器图片墙同样不展示遮罩与主体/背景中间层（当前图除外）。

## 4. 非功能需求

| 编号 | 类别 | 描述 |
|---|---|---|
| NFR1 | 正确性 | 修补背景不得把主体画回空洞内；空洞外像素必须逐像素不变 |
| NFR2 | 正确性 | 拆层/成层结果必须幂等：同一遮罩重复调用不产生第二层、不写第二条历史 |
| NFR3 | 像素安全 | 按层处理时只有目标图层的 `asset_id` 变化，其余图层素材原样保留 |
| NFR4 | 可撤销性 | 拆层、成层、显隐、移动、按层处理全部进编辑历史且可撤销 |
| NFR5 | 性能 | 抠图与修补属 CPU 密集操作，必须放到线程池，不得占住事件循环 |
| NFR6 | 降级可用 | 未装 OpenCV、未装 OCR 时分别退回模糊填补与「不拆文字」，主链路仍可用 |
| NFR7 | 交互一致 | 拖动图层与画布平移互斥；任何不可用操作给出原因而非静默失效 |
| NFR8 | 隔离 | 素材库按用户过滤；按层读素材仍走 `get_for_user` 归属校验 |
| NFR9 | 前端工程 | `tsc -b` 与 oxlint 通过；后端 pytest 全部通过 |

## 5. 验收标准

| 编号 | 描述 |
|---|---|
| AC1 | 对一张主体居中的图执行 `split_layers`，文档层为 `background`、`subject`，当前图不变，修订号 +1 |
| AC2 | 重复执行 `split_layers` 不新增图层、不新增历史条目 |
| AC3 | 拆出的背景图在主体原位置不再含主体颜色 |
| AC4 | `include_text` 为真且 OCR 可用时，图层中出现 `text-n` 文字层 |

| AC8 | 拆层后执行 `replace_background`，主体层 `asset_id` 不变，背景层 `asset_id` 变化 |

| AC10 | 局部编辑未指定图层时命中选区覆盖到的最上层图像层；无交集时报「选区没有覆盖到该图层」 |

| AC12 | `move_layer` 支持绝对坐标与相对位移 |
| AC13 | 画布上点击图层可选中并描边，拖动松手后图层位置改变且可撤销 |
| AC14 | 画布上拖角缩放，松手后文档倍率改变，翻转方向保留 |
| AC15 | 裁剪/对比/选区模式下图层不可拖动 |
| AC16 | 图层面板显示缩略图，显隐开关生效 |
| AC17 | 拆层与成层为二次确认动作，未确认不执行 |
| AC18 | 空操作（如对已可见图层再设一次可见）不写历史、不截断重做分支；只产出候选图的工具仍写历史 |
| AC19 | 快速连点撤销或按住 ⌘Z 不产生连发请求 |
| AC20 | 创作页素材按会话分组，未归入会话的单独一组，遮罩不出现在列表中 |
| AC21 | 编辑器图片墙不展示遮罩与未采用的主体/背景中间产物 |
| AC22 | 画布摘要列出各图层名称与默认作用规则，模型可在有选区时直接提升为图层 |
| AC23 | `pytest` 全部通过；`npm run build` 与 `npm run lint` 通过 |

## 6. 范围与非范围

**本里程碑范围**：

- 后端：`Layer` 字段扩展；`set_visible` / `move`；`edits/split.py`（抠取、外扩、修补、打洞、文档构造）；`edits/ocr.py`；`tools/target.py`（按层读写与遮罩换算）；`tools/layers.py`（拆层与成层）；像素类工具改造；换背景按背景层处理；`split_layers` / `promote_object_to_layer` / `set_layer_visible` / `move_layer` 四个工具注册；空操作不写历史；`GET /api/assets/library` 与 `LibraryGroupOut`；画布摘要与规划提示词；`ocr_provider` 配置项。
- 前端：画布图层选中/拖动/缩放与文字层渲染；图层面板缩略图、显隐、拆层与成层入口；工具栏二次确认动作与图层透传；图片墙过滤；创作页素材库分组；撤销并发闸。
- 无数据库迁移：图层新增字段只落在 `edit_sessions.document` 的 JSONB 里；素材库复用 `edit_sessions` 与 `session_assets`。

**本里程碑非范围**：

- 文字层的编辑（改文案、重排版式、抠原字）
- 图层的删除、合并、重命名与分组
- 抠图算法的升级（当前仍是 rembg / 四角两档）
- 多选、对齐、分布等排版能力
- 图层样式的自由编辑（描边、阴影、混合模式）
- 前端组件测试（仍无单测框架，视觉与交互以手动核对为准）

## 7. 后续依赖

- 图层字段目前是**平铺**的（每层各自持有 transform/opacity），没有父子关系。要做编组需要先把 `LayerDocument` 改成树形。
- `fill_background` 只做「洞内修补」，不做「洞外一致性校验」。若模型修补结果在洞外产生偏移，当前靠 `apply_masked` 挡住，但没有像素级断言。
- 选区仍是画布级的一次性输入。拆层后「按图层反复调整同一区域」需要把选区也纳入图层模型。
- 素材库按会话分组依赖 `session_assets` 的完整性，工具产出若不走 `apply_edit` 挂载会落到「未归入会话」组，需要后续统一入口。

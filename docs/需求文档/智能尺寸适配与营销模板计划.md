# 智能尺寸适配与营销模板计划

> 日期：2026-10-21
> 状态：规划草案，尚未实施。
> 对应方向：智能改尺寸与营销图模板。

## 1. 目标与使用流程

用户选择一张产品素材，勾选多个目标用途，先预览构图，再选择模板、填写文案和价格，生成一组可以继续编辑的物料，最后按用途打包下载。

首期先保证「尺寸准确、主体完整、结果可预览」；随后增加「模板套版、文字可修改、品牌样式复用」。AI 扩图作为明确选择的增强方式，单独展示免费额度消耗。

## 2. 当前基础

| 已有能力 | 代码位置 | 边界 |
|---|---|---|
| 商品主图、场景、模特、海报四类生成 | `backend/app/tools/marketing.py` | 通过不同提示词调用图片编辑模型，结果是图片，不是结构化可编辑模板 |
| 投放比例适配 | 同文件 `prepare_delivery_sizes_exec()` | 使用 `letterbox()` 等比缩放并留白；不是主体检测裁剪，也没有真正调用 AI 扩图 |
| 画幅定义 | `backend/app/ratios.py` | 预定义 1:1、4:5、3:4、9:16、16:9；尚无平台/用途/安全区配置 |
| 扩图入口 | `backend/app/tools/enhance.py` 的 `expand_canvas` | 可复用 provider 能力，但需核验主体保护、蒙版和输出尺寸，不能直接承诺像素不变 |
| 营销页 | `frontend/src/pages/MarketingPage.tsx`、`lib/marketing.ts` | 已有分类生成、比例操作、结果选择和打包 |
| 批处理 | `services/batch.py` | 可复用流程，但新执行会重建 items，不能直接当作可靠的单目标恢复系统 |
| 图层与编辑 | `backend/app/layers.py`、前端 Konva 画布 | 已有图片、文字、形状枚举，文字文案/字号/填色和位置变换 |
| 导出 | `services/exports.py` | 已有 ZIP 与 manifest，可扩展目标用途、模板和版本元数据 |
| 服务端渲染 | `edits/render.py` | 已渲染图片和简单文字；当前跳过形状层，文字仅简单居中绘制，尚不支持完整排版 |

本次扩展现有营销工作区，不额外建立一套重复的生图页、素材库或画布编辑器。

## 3. 方案选择与范围

| 路线 | 价值 | 代价 | 选择 |
|---|---|---|---|
| 继续让模型一次生成整张海报 | 复用现有入口，场景风格自由 | 文案、价格与位置不稳定，后续难修改 | 保留为自由生成模式 |
| 结构化模板 + 本地排版 + 可选 AI 背景 | 文案准确，能编辑，输出稳定，成本可控 | 需补模板数据和统一渲染 | **推荐作为模板模式** |
| 完整设计工具与模板市场 | 自由度高 | 范围大，涉及复杂编辑、审核和市场机制 | 暂不纳入 |

首期不做通用模板设计器、公开模板市场、多页长详情自由编排、动画、用户上传字体。模板由项目维护的受控配置发布；后续再增加管理界面。

## 4. 平台与用途配置

平台名称不能单独决定尺寸，应按「平台 + 用途」管理，例如同一平台的商品主图与内容封面是不同 preset。

新增 `DeliveryPreset`：`id / version / platform / placement / display_name / width / height / safe_insets / formats / max_file_bytes / background_rule / enabled / reference_url / verified_at`。

- 尺寸是明确像素值，比例由尺寸推导，不继续只靠 Ratio 枚举表达。
- 安全区为四边归一化 inset，展示平台 UI 遮挡参考线；平台不存在统一标准时标记「项目建议值」。
- 允许同平台多个用途、同尺寸不同安全区；变更生成新版本，历史任务保留原 preset 快照。
- 前端从服务端读取，不维护另一套硬编码尺寸表。
- 已有 ratio 参数及历史任务继续解析；旧入口映射到通用 preset。新增自定义尺寸须限制长边、总像素、目标数量和导出体积。

建议初始内容为：通用方图 1080×1080、通用竖图 1080×1440、通用短视频封面 1080×1920、通用横图 1920×1080；这些仅为项目建议输出，不能据此宣称平台官方标准。淘宝主图、小红书封面、公众号封面等平台项在实施时逐项查证具体用途后发布，截图数字不直接写成生产规则。

## 5. 智能构图与尺寸适配

### 5.1 主体信息来源

优先复用已有主体图层、透明通道与遮罩；其次使用现有分割能力获取主体区域；必要时结合 OpenCV 的显著性/边缘等信号辅助。不能把 OpenCV 本身视为已具备可靠商品识别能力。

多个商品或低置信度时，显示检测框并允许用户调整焦点/保护区域。没有可靠主体区域时默认完整留白适配，不进行激进自动裁剪。

分析结果保存归一化主体框/遮罩引用、焦点、来源与置信度，绑定源素材内容哈希或会话 revision，源内容改变后失效。旋转、翻转、图层缩放后必须先转换到最终画布坐标。

### 5.2 三种明确策略

| 策略 | 处理 | 适用与限制 |
|---|---|---|
| 完整适配 `contain` | 等比缩放 + 背景留白/填色 | 默认策略，完整保留原图，不消耗 AI 次数 |
| 主体保护裁剪 `smart_crop` | 根据主体保护区域与目标比例选择裁剪窗口 | 只有保护区域完整落在窗口内才允许；否则退回 contain 并提示 |
| AI 扩展背景 `outpaint` | 保留受保护前景，生成目标画幅需要的外围背景 | 用户主动选择，显示额度；不支持可靠保护的 provider 不开放此模式 |

主体保护裁剪采用可解释的几何约束：候选窗口包含全部保护框与边缘留量，再按焦点距离、构图位置评分。无法同时满足目标比例和主体完整时不强裁。

AI 扩图尽量只生成背景并将原主体前景重新合成；具备蒙版协议时锁定保护区。只有整图编辑接口时不能承诺商品像素不变，需标记预览与人工确认。生成失败按目标展示错误，不自动转为另一项会消耗额度的调用。

### 5.3 预览与执行

1. 选择源图或固定会话快照，自动分析一次主体。
2. 勾选用途，在缩略图中展示真实裁剪/留白、安全区与策略；本地策略使用与导出相同的几何计算。
3. 调整主体框、焦点或单目标策略；修改后仅更新受影响目标。
4. 提交前展示目标数量与预计 AI 次数。AI 扩图只能展示布局草图，真实生成结果返回后才标记完成。
5. 按目标执行和保存；允许部分完成、只重试失败目标，成功目标不重算。
6. 结果先进入物料列表，用户主动选择才进入编辑器，不覆盖当前画布。

## 6. 营销模板系统

### 6.1 首批模板

先提供三类各一套、按常见横竖画幅设计的模板版本：

- 商品主图：完整商品、简短卖点、可选价格/促销标签。
- 社媒封面：商品区、标题区、品牌标识区。
- 促销海报：活动标题、商品、价格与辅助说明。

模板明确适用画幅。第一版每个画幅有维护好的布局变体，避免把一套坐标直接按比例拉伸造成文字拥挤。详情页多屏拼接作为后续阶段。

### 6.2 模板结构与编译

模板使用 Pydantic 模型定义并导出 JSON Schema，服务端始终校验。结构包括：

| 字段 | 作用 |
|---|---|
| `template_id / version / schema_version` | 模板身份、不可变版本与解析兼容 |
| `supported_presets / layout_variants` | 可用用途及对应布局 |
| `slots` | 商品、背景、Logo、标题、卖点、价格的资源或文本绑定 |
| `layers` | 有序的图片、文字、基础形状描述，位置、尺寸、对齐、层级 |
| `constraints` | 必填、最大字数、最大行数、最小字号、保护区和安全区 |
| `tokens` | 品牌色、字体 ID、字阶、间距与圆角 |

采用「模板配置 → 填充 slots → 排版求解 → LayerDocument → 现有画布/服务端导出」的单一编译路径。JSON Schema 负责结构校验，文字溢出和布局冲突还要做业务校验。

禁止模板执行脚本或直接拉取任意远程 URL；图片引用必须来自当前用户有权限的资产。模板版本发布后不可原地改写，历史作品保留版本和填充参数。

### 6.3 文案、价格与品牌

- 标题、卖点、价格采用确定性文字层，不交给生图模型绘制，保证内容可核对、可编辑。
- 价格按 decimal/格式化字符串校验，保留货币与显示格式；不能使用浮点运算拼接价格。
- 长文案先换行，再在允许区间缩小字号；仍放不下时给出明确溢出提示，禁止静默丢字。
- 每个用户可保存品牌名、Logo、主辅色，使用项目提供并许可使用的字体列表。选择品牌配置后复制其快照，修改品牌资料不改变历史图。
- 自动文案可作为后续可选能力，用户确认后才替换输入，不列为首期依赖。

### 6.4 补齐渲染差异

现有 LayerDocument 与渲染器不足以直接实现完整模板。需补字体 ID、字重、对齐、行高、换行、文字内边距，以及基础形状/圆角等模板实际需要的字段；前后端同步支持新文档 schema，并兼容旧文档默认值。

文字换行结果由共享排版约定生成：服务端返回行内容、字号和定位，前端按同样结果预览。开发与生产容器部署同一批字体文件，等待字体加载完成后展示模板预览。

正式下载以服务端合成为准；验收中文、多行、货币符号、透明 Logo、旋转图层及形状填色。不能把「前端 Konva 看着正确」当作导出正确的证据。

## 7. 任务、接口与导出

新增职责模块建议为 `services/delivery.py`、`services/templates.py`、模板编译/排版模块，不继续把所有逻辑堆到 `tools/marketing.py`。

建议新增接口：

| 接口 | 用途 |
|---|---|
| `GET /api/delivery-presets` | 已发布用途及版本 |
| `POST /api/sessions/{id}/delivery-previews` | 固定 revision，返回主体与构图预览 |
| `POST /api/sessions/{id}/delivery-jobs` | 提交所选用途、策略、模板和输入快照 |
| `GET /api/delivery-jobs/{id}` | 聚合状态与每个目标产物 |
| `POST /api/delivery-jobs/{id}/items/{item_id}/retry` | 只重试失败目标 |
| `GET /api/marketing-templates` | 可用模板、布局变体与填写约束 |
| `POST /api/marketing-template-previews` | 校验并预览填充后的 LayerDocument |

任务由父 ToolRun 聚合，目标用持久化 item 表记录 `source_snapshot / preset_version / template_version / strategy / status / attempt / output_assets / document / quota_reservation`。本地适配和 AI 操作也走统一工具执行入口；Agent 新工具按相同 schema 调用，不另建绕过额度的路径。

新增多目标任务复用既有资产、进度与导出服务；目标幂等键包含父任务、源快照、preset、模板版本与目标序号。同一目标重试沿用逻辑 item，新增 attempt。

ZIP 扩展已有 manifest，增加用途、尺寸、适配策略、模板版本、源素材、成功/失败清单；文件名包含用途与像素尺寸。全部失败时不生成空的成功包；部分成功允许下载并明确遗漏项目。导出大包设置数量、字节和内存上限，超过同步打包阈值时交后台生成可下载文件。

## 8. 分阶段交付

| 阶段 | 内容 | 阶段验收 |
|---|---|---|
| B1：配置化尺寸与预览 | 用途配置、前端动态读取、完整适配、固定源快照、安全区、旧 ratio 兼容 | 多用途预览与实际导出像素一致，完整保留主体 |
| B2：主体保护与目标任务 | 主体分析、手工保护框、安全裁剪、目标级进度/重试、可选 AI 扩图、额度预估 | 横竖转换不强裁商品；失败目标可单独恢复，成功目标不重复调用 |
| B3：可编辑模板 | Schema、编译器、三类模板、品牌配置、文字/形状渲染补齐、现有编辑器衔接 | 上传商品填文案后产出可改文字和位置的作品，中文导出正确 |
| B4：成套交付 | 同一商品多个用途与模板变体，扩展 manifest、失败清单、打包限额 | 一次生成整套物料，可预览、重试、编辑、按用途下载 |

推荐先交付 B1，验证需求；B2 的 AI 扩图应在免费额度预占可用后开放。B3 可先以本地排版独立交付，避免会员或外部生图服务阻塞模板价值。

## 9. 验收清单

1. 宽图转竖图、竖图转方图、透明商品、多商品、贴边主体、低置信度主体，均有明确策略与安全降级。
2. 选择 protect 区域后，smart_crop 输出窗口必须包含它；不满足则明确退回 contain。
3. 源图 revision 改变后旧预览不能直接提交；已开始任务使用固定源快照。
4. 导出检查实际像素、格式、文件体积和透明通道，不能通过强制拉伸满足尺寸。
5. 同一模板中中文长标题、不同价格位数、缺少 Logo、超长卖点有可预期结果；不溢出、不丢字。
6. 预览与服务端输出布局对应，字体/换行位置一致；新字段不破坏现有编辑和撤销流程。
7. 三个目标中一个失败，仍可下载其余目标；重试只处理失败项，重复请求不重复保存或消耗次数。
8. 未选择 AI 策略时不产生模型调用；AI 策略不足额时提交前拦截，已有成功素材仍可下载。
9. 跨用户素材、品牌、任务、下载均校验权限；上限配置阻止超大图与超大包占满内存。

本轮未实施或运行上述验收。建议用可控本地样例验证几何与排版，再用真实商品素材验证 AI 扩图和实际视觉效果。

## 10. 依赖、风险与业务决策

首批平台用途及尺寸需按最新官方素材规范确认；平台命名、素材审核和安全区规则分开记录，不宣称输出自动通过平台审核。AI 扩图需要逐 provider 验证，中文排版依赖字体部署；模板版本、目标项和 quota 均需迁移。

拟采用的默认范围：三类模板、四种通用画幅、本地适配优先。平台首批名单、品牌配置数量上限、最大目标数和自定义尺寸开放范围在实施前确定，不阻塞通用画幅原型。

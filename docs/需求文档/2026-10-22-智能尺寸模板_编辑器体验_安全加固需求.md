## 0. 本次检查结论

### 0.1 需求追踪

| 原始需求 | 本文编号 | 本期必须交付的内容 |
|---|---|---|
| 智能改尺寸和营销图模板 | `D1` | 平台用途配置、主体保护、三种适配策略、多目标生成、ZIP、模板编译和一键成套出图 |
| 前端体验优化 | `E1` | 快捷键、实时图层缩略图、标尺参考线吸附、移动端手势和底部工具栏 |
| 安全加固 | `S1` | Redis 原子限流、429 语义、认证防爆破、生产配置检查和安全响应头 |

### 0.2 检查后确认的关键约束

1. **智能尺寸不能继续只做 `letterbox`。** 现有 `prepare_delivery_sizes` 是本地留白缩放，能满足尺寸正确，但不满足主体保护裁剪、AI 扩图和平台用途管理。新流程应保留旧工具兼容，同时新增可追踪的目标任务。
2. **模板不能只做前端预览。** 模板必须编译成 `LayerDocument`，再由现有服务端渲染和编辑器共同消费。否则用户看到的文字层无法可靠导出，模板模式退化成第二次生图。
3. **Delete 快捷键必须补后端工具。** 当前工具注册表没有 `delete_layer`，纯前端删除无法保证撤销、重做、历史和多端一致。
4. **限流和额度必须分开。** 每日额度限制总消耗，限流限制瞬时请求；被限流的请求不能创建任务、预占额度或调用厂商。
5. **平台尺寸需要版本化。** 淘宝、小红书、抖音、公众号的用途和规范会变化，截图中的尺寸只能作为项目草案，发布前必须有来源和 `verified_at`。
6. **移动端首期只承诺基础可用。** 双指缩放、平移、选择图层和移动图层必须在手机上稳定，复杂模板编辑、标尺精调和多面板同时展示不作为首期要求。

### 0.3 建议的发布门禁

| 门禁 | 必须通过的检查 |
|---|---|
| 代码合并前 | 单元测试、类型检查、接口权限测试、旧 `ratio` 兼容测试 |
| P0 安全上线前 | 10 并发生成请求不超过配置阈值；429 不创建 `ToolRun`；Redis 故障策略可验证 |
| 尺寸功能上线前 | 真实像素尺寸、主体保护框、部分失败和 ZIP manifest 全部通过 |
| 模板功能上线前 | 中文换行、价格位数、形状层渲染、预览与导出对照通过 |
| 编辑器体验上线前 | 输入框/IME 不误触、缩略图不阻塞主画布、手机手势不误触 |

## 1. 背景与目标

当前产品已经具备一条可用的修图主链路：上传或生成素材、创建编辑会话、通过工具改画布、分层编辑、生成营销图、按比例投放并打包 ZIP。项目不再是“只有画布的空壳”，本次三组需求应该建立在现有链路上，而不是另起一套编辑器或营销页。

本次要解决三个问题：

1. **一张图适配多个平台仍然靠手工重复处理。** 当前投放尺寸只支持五种预设比例，执行方式是把整张画布等比缩小后留白，没有平台用途配置、主体保护裁剪、AI 扩图和多目标成套交付。营销图也只是模型生成整张图片，文案和价格无法稳定复用。
2. **编辑器有专业能力，但操作效率还停在“能点按钮”的阶段。** 画布、图层、选区、撤销/重做都已经存在，但快捷键不完整，图层缩略图只对图像层有效，没有标尺、参考线和吸附，移动端以聊天/画布切换为主，缺少画布手势与底部工具栏。
3. **模型调用已有每日额度，但没有请求频率保护。** 额度解决“一天能用多少次”，限流解决“短时间能打多少请求”。当前没有 Rate Limit 中间件或 Redis 限流器，账号、生成、编辑、上传和导出入口都可能在秒级被重复刷写，造成队列积压和模型费用风险。

### 1.1 产品目标

- 用户上传一张商品图后，能选择多个平台用途，预览主体保护策略，生成尺寸准确、不拉伸、不粗暴裁切的主体完整版本，并一次打包下载。
- 用户能通过结构化模板快速生成可继续编辑的电商主图、社媒封面和促销海报，文案、价格、品牌色不再依赖模型“画得准”。
- 用户能在编辑器里用熟悉的快捷键完成移动、笔刷、删除、撤销、重做和平移画布；图层列表能直接辨认可视内容；移动图层时能用标尺、参考线和吸附保持版式整齐。
- 在手机上至少能完成缩放、平移、选择图层和移动图层等基础修图操作，不要求把桌面端所有精细能力等比塞进小屏。
- 生成、编辑、上传、查询和认证入口具备可配置、可观测、跨实例一致的频率限制；超额请求返回统一 `429 RATE_LIMITED`，且不误扣每日免费额度。

### 1.2 成功标准

| 维度 | 目标 |
|---|---|
| 尺寸准确性 | 所有投放输出与配置的像素尺寸完全一致，不通过拉伸满足比例 |
| 主体完整性 | `smart_crop` 输出必须包含用户保护框；无法满足时回退 `contain` 并明确提示 |
| 模板可编辑性 | 模板产出的文字、价格和基础形状进入 `LayerDocument`，可在现有编辑器中继续修改 |
| 操作效率 | 常用编辑动作不依赖鼠标逐项点按钮；输入框、弹窗和中文输入法组合态不触发快捷键 |
| 移动端可用性 | 手机端可双指缩放、平移画布、切换工具并移动选中图层 |
| 安全性 | 高频入口按用户/ IP 双维度限流；并发请求不能突破配置阈值；限流与额度错误语义分离 |
| 可验证性 | 每项需求都有可执行验收用例，预览、导出、像素尺寸和权限边界能自动检查 |

## 2. 当前项目现状

### 2.1 技术栈与主链路

| 层级 | 当前实现 | 结论 |
|---|---|---|
| 前端 | React 19、Vite 8、TypeScript 6、Tailwind 4、Zustand 5、Konva 10 / react-konva | 可直接扩展画布和工具状态 |
| 后端 | FastAPI、SQLAlchemy async、PostgreSQL、Redis、arq worker | 已具备异步任务与 Redis，可接入限流 |
| 存储 | MinIO / S3 兼容对象存储，短时签名 URL | 已有素材权限与导出基础 |
| 模型调用 | 后台登记连接与模型，发布运行版本；工具执行时锁定版本 | 热更新和任务版本已经存在 |
| 额度 | 免费会员日桶、预占、结算、释放、管理员调整 | 已有“总量控制”，缺少“频率控制” |
| 事件 | Redis Pub/Sub 唤醒，数据库保存轮次事件 | 可复用 Redis 连接，不应把限流做成仅进程内计数 |
| 编辑器 | `LayerDocument` + Konva 画布 + 图层选择、变换、文字编辑、选区和撤销/重做 | 有能力继续加交互，但不能假设现有实现已满足全部手势 |

### 2.2 已有能力与缺口对照

| 能力 | 当前实现 | 缺口 |
|---|---|---|
| 平台尺寸 | `backend/app/ratios.py` 仅定义 1:1、4:5、3:4、9:16、16:9 | 没有“平台 + 用途”配置、像素尺寸、安全区、版本和来源核验 |
| 投放适配 | `prepare_delivery_sizes_exec()` 使用 `letterbox()` 等比缩放并留白 | 没有主体检测、智能裁剪、AI 扩图和多目标任务 |
| 营销模板 | `generate_marketing()` 通过提示词生成整张图片 | 没有 JSON Schema、slot 填充、确定性排版和可编辑文字层 |
| 服务端渲染 | 已能合成图片和简单居中的文字 | `shape` 层未绘制；文字缺换行、对齐、行高、溢出处理 |
| 前端营销页 | `/marketing` 已有四类营销图、比例按钮、结果选择和 ZIP | 没有平台预览面板、模板表单、目标级进度和失败重试 |
| 画布快捷键 | 已有 Esc、⌘/Ctrl+Z、⌘/Ctrl+Shift+Z、⌘/Ctrl+Y、0/1/+/- | 缺 V、B、Delete、Space 平移；快捷键逻辑散落在页面 `useEffect` |
| 图层删除 | 工具注册表没有删除图层工具 | Delete 不能直接实现为纯前端删数组，必须补一个可撤销的文档工具 |
| 图层缩略图 | 图像层显示素材 URL，文字层显示“文”占位 | 没有对变换后内容、文字层和形状层的实时缩略图 |
| 标尺与吸附 | 无 | 缺参考线、中心线、边缘吸附和视觉提示 |
| 触摸交互 | Konva `Stage` 支持拖拽和 `onWheel`；没有显式双指捏合处理 | 缺真正的双指缩放/拖拽、手机底部工具栏和小屏操作布局 |
| 认证安全 | bcrypt、JWT、HttpOnly Cookie、`auth_version` 撤销、SameSite=Lax | 没有登录/注册防爆破限流，缺生产启动配置校验和统一安全响应头 |
| 素材权限 | 会话、素材、任务大多按当前用户查询；越权统一 404 | 新平台配置、模板、品牌、目标任务和 ZIP 也必须沿用同样的权限边界 |
| 上传保护 | 单文件 20 MB、5000 万像素、PNG/JPEG/WebP 解码校验 | 缺上传频率限制和大批量请求保护 |
| 请求限流 | 未发现 `slowapi`、Rate Limit 中间件或 Redis 计数逻辑 | 第三项需求的核心缺口 |

- `docs/需求文档/智能尺寸适配与营销模板计划.md` 已经提出 `DeliveryPreset`、主体保护、`contain / smart_crop / outpaint`、模板 Schema 和分阶段方案。本需求沿用其技术判断，不另建一套重复流程。

## 3. 总体范围与用户故事

### 3.1 本期范围

**需求一：智能改尺寸与营销图模板**

- 平台用途配置和前端预览。
- 完整适配、主体保护裁剪、可选 AI 扩图。
- 多目标生成、部分失败、单目标重试和 ZIP 下载。
- 三类结构化模板：商品主图、社媒封面、促销海报。
- 模板编译到现有 `LayerDocument`，产出可继续编辑的文件。
- 品牌色、Logo、标题、卖点、价格等基础品牌配置。

**需求二：编辑器体验优化**

- V、B、Delete/Backspace、Space、撤销/重做快捷键。
- 图层实时缩略图。
- 顶部/左侧标尺、可拖参考线、移动图层吸附。
- 手机端双指缩放、画布平移和底部工具栏。

**需求三：安全加固**

- 用户/IP 双维度接口限流。
- 认证、生成、编辑、上传、查询和 SSE 分策略限流。
- Redis 原子滑动窗口、跨实例一致、统一 429 响应。
- 前端 429 提示与倒计时。
- 登录/注册防爆破、生产密钥启动检查、统一安全响应头和 Origin 校验作为同批安全基线。

### 3.2 明确不做

- 不做公开模板市场、用户上传脚本模板、任意 HTML/CSS 模板和模板审核后台。
- 不做完整 Photoshop 级矢量编辑、富文本排版和自由钢笔路径。
- 不做多页详情长图自动编排，首期只做单张模板和固定布局变体。
- 不做平台自动上传、审核代提交或“保证通过平台审核”。
- 不把限流当成 WAF / DDoS 防护，也不替代每日额度、并发任务上限和厂商侧配额。
- 不做移动端原生 App；手机端只保证浏览器内基础可用。
- 不做视频模板、动画导出、多人协同编辑。

## 4. 需求一：智能改尺寸与营销图模板

### 4.1 业务目标

把“手工裁剪、反复导出、文案重排”收敛为一条可控的物料生产流程：

1. 固定源图或当前会话 revision。
2. 分析主体和保护区域。
3. 选择平台用途和适配策略。
4. 选择模板，填写文案、价格、品牌。
5. 预览并提交多目标生成。
6. 对失败目标单独重试。
7. 选择成功结果打包下载，或进入现有编辑器继续修改。

结果默认进入图片墙或交付列表，不覆盖当前画布；只有用户主动选择“继续编辑”时才创建或更新编辑会话。

### 4.2 平台用途配置

平台不能只用一个名称表示，必须按“平台 + 用途 + 版本”建模。

#### 4.2.1 `DeliveryPreset` 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 配置主键 |
| `key` | string | 稳定业务键，如 `taobao.product_main` |
| `version` | int | 配置版本，发布后不可原地改写 |
| `platform` | string | 平台名称 |
| `placement` | string | 用途，如商品主图、竖版封面、视频封面 |
| `display_name` | string | 用户可见名称 |
| `width` / `height` | int | 明确输出像素，不接受只存比例 |
| `safe_insets` | object | 上右下左归一化安全区，用于参考线而不是硬裁切 |
| `default_strategy` | enum | `contain` / `smart_crop` / `outpaint` |
| `formats` | list | `png` / `jpg` / `webp` |
| `max_file_bytes` | int | 单文件体积上限 |
| `background_rule` | string | 白底、透明、品牌底色或由模板决定 |
| `source_url` | string | 规则来源链接 |
| `verified_at` | datetime | 人工核验时间 |
| `status` | enum | `draft` / `published` / `deprecated` |

#### 4.2.2 首批配置建议

| 平台用途 | 建议输出 | 默认策略 | 规则状态 |
|---|---|---|---|
| 淘宝商品主图 | 800 × 800（待官方复核） | `contain`，可选 `smart_crop` | 项目草案 |
| 小红书竖版封面 | 1080 × 1440（3:4，待复核） | `smart_crop` | 项目草案 |
| 抖音竖版封面 / 短视频封面 | 1080 × 1920（9:16，待复核） | `contain` 或 `smart_crop` | 项目草案 |
| 微信公众号封面 | 约 2.35:1，具体像素待复核 | `contain` | 项目草案 |
| 通用方图 | 1080 × 1080 | `contain` | 项目建议值 |
| 通用竖图 | 1080 × 1440 | `contain` | 项目建议值 |
| 通用横图 | 1920 × 1080 | `contain` | 项目建议值 |

**要求：**

- 前端不能维护另一份硬编码平台尺寸表，统一从 `GET /api/delivery-presets` 读取。
- 配置发布后版本不可变；历史任务保存 `preset_id + version` 快照。
- 没有官方依据的数值显示“项目建议值”，不得在文案中宣称“平台官方标准”。
- 支持同平台多个用途；自定义尺寸必须限制长边、总像素、目标数量和导出体积。
- 旧 `Ratio` 参数继续兼容，映射到通用 preset，不能破坏历史任务和旧接口。

#### 4.2.3 配置发布与后台管理

- preset 由运营或管理员维护，普通用户只能读取 `published` 版本。
- 至少提供草稿、发布、停用三个状态；发布后版本不可修改，只能创建新版本。
- 首期可以由迁移/脚本发布种子配置，但必须保留管理员接口，避免每次改尺寸都重新发版。
- 建议管理接口：
  - `GET /api/admin/delivery-presets`
  - `POST /api/admin/delivery-presets`
  - `POST /api/admin/delivery-presets/{id}/publish`
  - `POST /api/admin/delivery-presets/{id}/deprecate`
- 发布前校验尺寸、像素总量、格式、安全区、来源链接和 `verified_at`。
- 停用 preset 不删除历史版本；已有 job 继续能读取原快照。
- 管理后台不向普通用户暴露平台配置编辑和模型选择器。

### 4.3 源快照与主体分析

#### 4.3.1 源快照

- 预览和提交必须固定源：`session_id + revision` 或 `asset_id + content_hash`。
- 预览提交后若源图 revision 或内容哈希变化，旧预览失效，重新分析后才能提交。
- 任务执行使用提交时的快照，不随用户后续编辑漂移。
- 如果保存快照成本过高，至少保存源素材引用、会话 revision、图层文档快照和主体分析结果。

#### 4.3.2 主体信息来源

按以下优先级分析，不能把 OpenCV 当作可靠的商品识别器：

1. 已存在的 `subject` 图层或透明通道。
2. 现有抠图/分割能力生成的 alpha 遮罩。
3. OpenCV 显著性、边缘和连通域作为辅助信号。
4. 用户手工拖出的保护框或焦点。

分析结果必须保存：

- 归一化主体框或多个主体的保护框。
- 遮罩素材引用（如有）。
- 焦点位置。
- 来源类型和置信度。
- 绑定的源内容哈希或 revision。

低置信度、多个商品、贴边主体或没有可靠主体区域时，默认退回完整适配，不进行激进自动裁剪。

### 4.4 三种适配策略

| 策略 | 处理方式 | 是否调用模型 | 使用条件 |
|---|---|---|---|
| `contain` | 等比缩放后填充留白或品牌底色，完整保留源画面 | 否 | 默认安全策略 |
| `smart_crop` | 在目标比例窗口内选择裁剪区域，必须包含保护框和必要边缘留量 | 否 | 有可靠保护区域且窗口能容纳时 |
| `outpaint` | 保留主体前景，生成目标画幅需要的外围背景 | 是，消耗额度 | 用户主动选择；provider 支持指定画幅/蒙版时开放 |

#### 4.4.1 智能裁剪规则

- 候选窗口必须包含全部保护框和外扩安全边距。
- 同时满足目标比例和主体完整后才允许裁剪。
- 有多个可行窗口时，按焦点距离、主体面积、三分法/中心构图评分。
- 无法满足时退回 `contain`，并提示“主体无法在目标画幅内完整裁剪，已改为完整适配”，禁止静默裁掉商品。
- 旋转、翻转、缩放后的图层必须转换为最终画布坐标后再计算。
- 文字层和模板形状层默认视为受保护内容，不允许被裁掉。

#### 4.4.2 AI 扩图规则

- 只能在用户明确选择 `outpaint` 时调用。
- 提交前显示预计 AI 次数和目标数量。
- 优先只生成外围背景，再把受保护前景合成回目标画布；具备蒙版协议时必须锁定保护区。
- provider 只有整图编辑能力时，必须提示“AI 扩图可能轻微改变商品细节”，不能承诺逐像素不变。
- AI 失败不得自动改用另一个消耗额度的策略；失败目标可以单独重试。
- 不选择 AI 策略时不得产生模型调用和额度预占。

#### 4.4.3 智能裁剪几何规则

输入：

- 源画布宽高：`(sw, sh)`。
- 目标宽高：`(tw, th)`；`r = tw / th`。
- 保护区域集合：`protect_rects`，由主体框、文字层、形状层和用户手动画框取并集后得到。
- 用户焦点：`focus = (fx, fy)`，可以是画布归一化坐标；没有时使用保护区域中心。
- 安全边距：按画布短边归一化，默认 0.02，可配置。

基本流程：

```text
if protect_rects 为空:
    return contain
if protect_rects 超出源画布或没有可靠主体:
    return contain with warning

if sw / sh > r:
    crop_h = sh
    crop_w = sh * r
else:
    crop_w = sw
    crop_h = sw / r

在剩余可移动范围内生成候选窗口：
    candidate_x in [protect.left, protect.right - crop_w]
    candidate_y in [protect.top, protect.bottom - crop_h]

如果没有候选窗口:
    return contain with "主体无法完整裁剪"

按以下加权分数选择窗口：
    score = w1 * 焦点距离
          + w2 * 主体中心与画布中心距离
          + w3 * 边缘留白不平衡
          + w4 * 构图规则偏离

返回 crop_rect，并生成与目标像素尺寸一致的输出
```

实现规则：

- 候选窗口必须能覆盖全部保护区域，任何一个保护区域越界即淘汰该窗口。
- 只在候选窗口内评分，不能先裁后判断。
- 多商品场景取全部主体框的并集，不允许只保护最大商品。
- 保护区域贴近画布边缘时，允许按安全边距向画布外扩展候选窗口，但最终裁剪不能产生越界像素。
- 文字层和形状层没有独立 bbox 时，使用其变换后的几何 bbox。
- 评分参数必须是可配置常量，不能写死在 JS 和 Python 两套实现中。
- 前端预览和后端任务执行必须调用同一份几何定义；前端可以用同一组参数做本地计算，但提交时后端必须重新计算。

#### 4.4.4 主体置信度与降级

| 情况 | 默认处理 |
|---|---|
| 分割/保护框置信度高且保护框完整 | 允许 `smart_crop` |
| 置信度中等，存在多个候选主体 | 显示保护框和选择控件，等待用户确认 |
| 置信度低或没有可靠主体 | 自动使用 `contain`，提示“已采用完整适配” |
| 保护框超出源画布 | 截断到画布内并提示，不进行猜测性扩展 |
| provider 不支持画幅/蒙版 | 只开放 `contain` 和 `smart_crop`，隐藏 `outpaint` |

建议初始阈值：`high >= 0.75`、`medium 0.45–0.75`、`low < 0.45`。阈值和主体检测 provider 能力必须集中配置，不写散落在各个组件中。

### 4.5 多目标预览、生成与重试

#### 4.5.1 预览面板

在现有 `/marketing/:sessionId` 工作区内新增“适配平台”区域，不新建重复页面。

- 展示平台用途卡片或缩略图列表，包含尺寸、比例、策略、是否消耗 AI 次数。
- 每个缩略图使用与导出相同的几何计算，展示真实裁剪/留白和安全区参考线。
- 支持多选目标，显示已选数量和预计总成本。
- 允许调整主体保护框、焦点和单目标策略。
- 源 revision 改变时清空过期预览并提示重新分析。

#### 4.5.2 目标任务

- 一次提交可以包含多个目标，目标数量设置上限。
- 每个目标独立状态：`queued / running / succeeded / failed / canceled`。
- 父任务聚合总进度；前端显示目标级进度和失败原因。
- 成功目标不因其他目标失败而丢失。
- 重试只创建失败目标的新 attempt，不重复保存成功目标，不重复扣成功目标额度。
- 幂等键包含父任务、源快照、preset 版本、模板版本和目标序号。
- 作用域内所有素材、任务、模板、品牌和下载都必须校验当前用户归属；越权统一 404。

#### 4.5.3 打包下载

复用现有 ZIP 和 `manifest.json`，扩展以下字段：

- 平台、用途、preset 版本。
- 输出宽高、格式、适配策略。
- 模板 ID/版本。
- 源素材 ID、会话 ID、源 revision。
- 成功/失败目标清单。
- 是否使用 AI 扩图及对应额度单位。

ZIP 文件名应包含会话标题、日期和用途摘要；每张图片命名包含用途、尺寸、序号。全部目标失败时不生成空包；部分成功时允许下载并明确遗漏项。同步打包必须有数量、总字节和内存上限，超过阈值时转为后台生成。

#### 4.5.4 页面状态

| 状态 | 页面表现 | 可用操作 |
|---|---|---|
| 无源图 | 说明需要先选择素材或会话，展示上传入口 | 返回创作页、选择历史素材 |
| 分析中 | 目标卡片显示骨架/加载态，主体框暂不可编辑 | 取消分析 |
| 可预览 | 目标卡片显示真实缩略图、尺寸、策略和安全区 | 勾选目标、调整保护框、切换策略、提交 |
| 源已过期 | 旧缩略图加遮罩，提示“源图已更新，请重新分析” | 重新分析、放弃旧预览 |
| 提交中 | 提交按钮锁定，显示目标数量和预计额度 | 不允许重复提交 |
| 部分成功 | 成功目标可下载，失败目标显示原因和重试按钮 | 下载成功项、重试失败项、继续编辑成功项 |
| 全部失败 | 不显示空 ZIP，展示失败原因和排查建议 | 重试、调整策略、返回编辑 |
| 限流中 | 显示 `RATE_LIMITED` 和倒计时 | 等待后重试，不创建新任务 |
| 额度不足 | 显示 `QUOTA_EXHAUSTED` 和重置时间；本地 `contain` 仍可用 | 关闭 AI 扩图、只生成本地适配 |

前端不能只根据 `run.status === failed` 展示统一错误。目标卡要显示分类：源问题、主体问题、模板问题、额度问题、限流问题、存储问题。

#### 4.5.5 额度与计价规则

- `contain`、`smart_crop` 和本地模板排版默认不消耗 AI 图片次数。
- `outpaint` 每成功输出 1 张建议计 1 个 AI 单位；具体数值由运营确认。
- 每个目标单独预占额度，任务进入执行前再次校验；不要在父任务上预占一个无法对应到输出的模糊总额。
- 成功输出后结算对应 item；确定失败或未发送请求释放预占；结果未知时沿用现有 unknown 机制并进入人工核查。
- 部分成功只结算成功项，成功目标重试不重复预占。
- 额度不足时仍允许生成不消耗 AI 的 `contain` 结果；前端要区分“本地适配可用”和“AI 扩图不可用”。

### 4.6 营销模板系统

#### 4.6.1 首批模板

| 模板类 | 内容区域 | 适用目标 |
|---|---|---|
| 商品主图 | 商品区、标题/卖点、价格标签、Logo | 方图、淘宝主图 |
| 社媒封面 | 左图右文或上图下文、标题、品牌标识 | 小红书、抖音、公众号 |
| 促销海报 | 活动标题、商品、价格、辅助说明、背景色块 | 通用方图、竖图和横图 |

首期每个模板至少提供一个与目标画幅匹配的布局变体，禁止把同一套坐标按比例拉伸。详情页多屏拼接放到后续版本。

#### 4.6.2 模板结构

模板由 Pydantic 模型定义并导出 JSON Schema，服务端始终校验。

| 字段 | 作用 |
|---|---|
| `template_id` / `version` / `schema_version` | 模板身份和不可变版本 |
| `supported_presets` | 可用平台用途 |
| `layout_variants` | 每个画幅/用途对应的布局 |
| `slots` | 商品图、Logo、标题、卖点、价格、背景等占位 |
| `layers` | 有序的图片、文字、基础形状描述 |
| `constraints` | 必填、最大字数、最大行数、最小字号、安全区 |
| `tokens` | 品牌色、字体 ID、字阶、间距、圆角和默认边框 |

统一编译路径：

`模板配置 -> 校验 slot 输入 -> 排版求解 -> LayerDocument -> Konva 预览 / 服务端导出`

JSON Schema 只负责结构校验，文字溢出、字号下限、价格格式和布局冲突必须再做业务校验。

#### 4.6.3 排版与内容规则

- 标题、卖点、价格和品牌名使用确定性文字层，不交给模型绘制。
- 价格使用 decimal 或规范化字符串，禁止用浮点拼接价格。
- 长文案先换行，再在允许区间缩小字号；仍放不下时明确提示溢出，禁止静默丢字。
- 文本需要支持对齐、行高、最大行数、换行策略和裁剪策略。
- 图片、Logo 和背景必须来自当前用户有权限的资产。
- 模板不能执行脚本、不能请求任意远程 URL、不能读取服务端文件系统。
- 模板版本发布后不可原地改写；历史作品保留模板版本和填充参数。
- 品牌配置修改不能反向改变已生成作品，任务保存品牌快照。

#### 4.6.4 渲染一致性

- 前端 Konva 预览和服务端 Pillow 导出必须使用同一份模板几何、同一套文字约束和字体列表。
- 当前 `edits/render.py` 只绘制简单居中文字，且跳过 `shape` 层。实施模板前必须补齐：形状绘制、文字换行、对齐、行高、透明背景和字体回退。
- 前端画布当前也只渲染文字和图片；模板产出的形状层必须在编辑器中可见、可选中、可调整，否则“可编辑”不成立。
- 服务端导出必须用实际像素检查，不能只凭前端看起来正确。

#### 4.6.5 模板配置示例

以下仅为结构示意，真实字段以 Pydantic 模型导出的 JSON Schema 为准：

```json
{
  "template_key": "ecommerce.main_image.v1",
  "version": 1,
  "schema_version": 1,
  "supported_presets": ["general.square", "taobao.product_main"],
  "variants": {
    "general.square": {
      "width": 1080,
      "height": 1080,
      "layout": {
        "background": "#F6F2E8",
        "product_slot": {"x": 90, "y": 120, "width": 900, "height": 680, "fit": "contain"},
        "title": {"x": 90, "y": 820, "width": 650, "max_lines": 2, "min_font_size": 42, "align": "left"},
        "price": {"x": 760, "y": 820, "width": 230, "align": "right"},
        "logo": {"x": 900, "y": 60, "width": 100, "height": 60}
      }
    }
  },
  "slots": {
    "product": {"type": "asset", "required": true},
    "title": {"type": "text", "required": true, "max_length": 40},
    "price": {"type": "text", "required": false, "max_length": 24},
    "logo": {"type": "asset", "required": false}
  },
  "constraints": {
    "safe_area": {"top": 0.04, "right": 0.04, "bottom": 0.04, "left": 0.04},
    "max_layers": 40,
    "forbid_overlap": ["title", "price"]
  }
}
```

模板校验至少覆盖：

- `template_key + version` 唯一且不可变。
- `supported_presets` 只能引用已发布 preset。
- 每个 layout variant 的坐标和尺寸必须在画布内。
- 文本槽位超出最大长度、最大行数或最小字号时，返回可定位到字段的错误。
- 图片槽位只能引用当前用户可访问的资产；禁止 `http://`、`file://`、`data:` 等任意远程或本地资源。
- 价格只允许规范化字符串或 decimal，不允许浮点格式化。
- 模板层级数、形状数、文本数和输出像素总量有上限。

### 4.7 一键成套出图

对电商场景提供组合入口：

1. 上传或选择一张商品素材。
2. 选择“主图 + 详情头图 + 社媒投放图”组合。
3. 选择模板和品牌配置。
4. 填写标题、卖点、价格。
5. 生成整套物料，展示每个目标的尺寸、状态和失败原因。
6. 打包下载或逐张进入编辑器。

“一键”表示一次配置完成多个目标，不表示跳过预览、授权和额度提示。

| `GET /api/delivery-jobs/{id}` | 返回目标任务、逐项状态和产出 |
| `POST /api/delivery-jobs/{id}/items/{item_id}/retry` | 只重试失败目标 |
| `GET /api/delivery-jobs/{id}/export` | 下载成功目标 ZIP |
| `GET /api/marketing-templates` | 返回可用模板、布局变体和约束 |
| `POST /api/marketing-template-previews` | 校验填充参数并返回 `LayerDocument` 预览 |

所有写接口都要有幂等策略和实体级权限校验。预览接口不应创建可下载成品；生成任务必须走统一工具/额度外壳，不能让新接口绕过 `quota.reserve()`。

**错误码建议**

| 错误码 | HTTP 状态 | 含义 |
|---|---|---|
| `SOURCE_REVISION_STALE` | 409 | 预览后源 revision 变化，需要重新预览 |
| `PRESET_NOT_FOUND` | 404 | preset 不存在、未发布或已停用 |

| `TEMPLATE_VALIDATION_FAILED` | 422 | 模板 slot、文字或价格校验失败 |
| `EXPORT_TOO_LARGE` | 413 | 导出包超过同步处理上限 |
| `RATE_LIMITED` | 429 | 请求频率超限，不创建任务 |
| `QUOTA_EXHAUSTED` | 409 | 已无可用 AI 次数 |

#### 4.8.4 数据约束与索引

| 表 | 唯一约束/索引 | 关键约束 |
|---|---|---|
| `delivery_presets` | `(key, version)` 唯一；`(status, platform, placement)` 索引 | 发布后版本不可改；宽高为正整数 |
| `delivery_jobs` | `id` 主键；`(user_id, created_at)` 索引 | 源快照、模板版本和品牌快照必须持久化 |
| `delivery_job_items` | `(job_id, item_key)` 唯一 | item 只能属于一个 job；状态机不可逆跳转 |
| `marketing_template_versions` | `(template_key, version)` 唯一 | schema/layout JSON 发布后不可改 |
| `brand_profiles` | `(user_id, name)` 建议唯一 | Logo 必须是当前用户可访问资产 |

- 任务和 item 使用 UUID 主键；金额/价格使用规范化字符串或 decimal，不使用浮点持久化。
- 所有业务表带创建时间、更新时间；终态记录 `finished_at`、`error_code` 和可读错误。
- 任务表不保存签名 URL，按需重新签发；快照只保存 storage key/asset id 和内容哈希。
- 删除用户时，任务和产出按现有删除策略处理；首期至少保证不再返回给其他用户。

### 4.9 需求一验收标准

1. 平台配置来自服务端，前端刷新后能拿到相同版本；旧 `ratio` 调用仍然可用。
2. `contain` 输出像素尺寸完全正确，图片不拉伸，背景规则符合配置。
3. `smart_crop` 在宽转竖、竖转方、透明商品、多商品、贴边商品等样例中都能给出明确结果；保护框不完整时回退 `contain`。
4. 未选择 `outpaint` 时不产生模型调用；选择后提交前展示预计额度，失败不会自动二次扣费。
5. 一次选择三个以上目标生成，任意一个失败不影响其他目标下载；失败目标重试不重算成功目标。
6. ZIP 内每张图实际尺寸、格式、文件名和 manifest 记录一致；部分成功包包含失败清单。
7. 模板生成的标题、价格、品牌名是文字层，进入编辑器后可以修改；形状层在前后端都能正确显示。
8. 长标题、长价格、缺少 Logo、超长卖点都有可预期结果，不出现静默截断或服务端导出与预览明显错位。
9. 非当前用户素材、模板、品牌、任务和下载请求均被拒绝，且不泄露资源是否存在。

### 4.10 幂等、并发与恢复规则

- `delivery_jobs` 和 `delivery_job_items` 必须持久化，不能只存在前端 store 或 Redis。
- 状态机：

```text
job:    queued -> running -> partial_succeeded | succeeded | failed | canceled
item:   queued -> running -> succeeded | failed | canceled
retry:  failed -> queued (attempt + 1)
```

- 父任务的终态根据所有 item 推导：全部成功为 `succeeded`，部分成功且部分失败为 `partial_succeeded`，全部失败为 `failed`。
- 同一 `job_id + item_id + attempt` 只能有一个活跃执行；worker 重复领取时按状态和租约去重。
- 重试只允许 `failed` 或可重试的 `canceled` item；`succeeded` item 不能再次进入队列。
- 任务提交时必须快照 `source_revision`、preset 版本、模板版本、品牌快照和额度预占，执行期不读取“当前最新配置”。
- 源图过期、模板下架或品牌被删除时，已提交任务仍使用快照执行；新任务必须重新校验。
- 部分成功时允许下载成功结果；失败目标必须在 manifest 中列出，不得用成功目标覆盖失败状态。
- 前端不得通过轮询 `GET /delivery-jobs/{id}` 修改任务状态；所有状态变化由后端任务执行结果驱动。

### 4.11 交付数量与资源上限

以下为建议初始值，全部放进配置，实施时可按压测调整：

| 限制 | 建议值 | 超出处理 |
|---|---|---|
| 单次投放目标数 | 8 | 422 `TARGET_LIMIT_EXCEEDED` |
| 单次模板变体数 | 4 | 422 |
| 单张输出最大像素 | 5000 万 | 422 |
| 同步 ZIP 最大字节 | 128 MB | 413，提示拆分下载 |
| ZIP 最大文件数 | 32 | 413 或后台打包 |
| 源图最大文件 | 20 MB | 413 |
| 模板最大层数 | 40 | 422 |

同步打包先保留现有内存 ZIP 实现，但必须增加数量、字节和内存检查；超过阈值时应返回可操作错误，不能把 API 进程打满内存。

## 5. 需求二：编辑器体验优化

### 5.1 快捷键系统

#### 5.1.1 目标快捷键

| 快捷键 | 行为 |
|---|---|
| `V` | 切到移动工具，可拖动当前图层或画布 |
| `B` | 切到笔刷工具，进入现有选区涂抹模式 |
| `Delete` / `Backspace` | 删除当前选中图层，可撤销 |
| `Ctrl/Cmd + Z` | 优先撤销当前选区历史；没有选区历史时撤销文档历史 |
| `Ctrl/Cmd + Shift + Z` | 重做；保留 `Ctrl/Cmd + Y` 兼容 |
| 按住 `Space` + 拖拽 | 临时平移画布，松开 Space 后恢复原工具 |
| `Escape` | 依次退出文字编辑、裁剪、对比、选区、面板 |
| `0` / `1` / `+` / `-` | 适应窗口、实际像素、放大、缩小 |

`Delete` 不能只在前端删数组。当前工具注册表没有删除图层能力，需新增 `delete_layer`：

- 输入 `layer_id`。
- 锁定层（如背景层）不可删除，返回明确中文错误。
- 删除后文档 revision 更新，写入编辑历史，可撤销/重做。
- 已删除图层的素材不立即做不可逆物理删除，至少保留到撤销窗口或历史清理策略执行。

#### 5.1.2 工具状态

- 在 `editorUi` 或独立 `editorTools` store 中维护 `activeTool: 'move' | 'brush' | 'select' | 'pan' | 'text'`。
- `Space` 是临时平移态，不覆盖用户原来的工具选择；松键后恢复。
- 工具按钮、画布光标、快捷键提示和实际交互必须读取同一份状态，避免按钮显示移动但键盘仍是笔刷。
- 任何模态框、裁剪、对比、文字输入和选区识别期间，快捷键按当前模式收敛，不允许穿透到画布。

#### 5.1.3 焦点与输入法保护

快捷键监听必须满足：

- `input`、`textarea`、`select`、`contenteditable` 内不响应单键工具快捷键。
- `event.isComposing` 为真时不响应，避免中文输入法组合态误删图层或切工具。
- 带修饰键的快捷键不能与浏览器自带缩放、保存、刷新冲突；确需接管时调用 `preventDefault()`。
- 长按产生的 `event.repeat` 不应重复触发删除、撤销、重做等有副作用动作。
- 工具栏、弹窗打开或后端任务执行中，禁用状态与快捷键状态一致。

建议把快捷键逻辑从 `EditorPage` 的单个 `useEffect` 抽成 `useEditorShortcuts`，使用最新 refs 或 store selector，避免闭包读到旧 session/tool 状态。

#### 5.1.4 快捷键优先级

事件处理顺序必须是：

```text
文字输入/IME
  > 弹窗或确认框
  > 选择/裁切/对比模式
  > 画布工具快捷键
  > 全局编辑器快捷键
```

具体规则：

- `event.isComposing` 为真时直接返回。
- 当前焦点在 `input`、`textarea`、`select` 或 `contenteditable` 时，除了明确绑定的 Esc/Enter 外，不响应单键快捷键。
- 打开二次确认框、模板表单、导出弹窗时，不响应画布快捷键。
- 按住 Space 时不触发工具切换；松开 Space 后恢复按住前的 `activeTool`。
- Delete/Backspace 只在有选中图层且该层可删除时触发；没有选中层时只显示提示，不改变文档。
- 任务执行中允许界面浏览，但不允许对正在被像素工具修改的图层发起删除或移动。
- 事件监听应在编辑器挂载时注册、卸载时清理；切换会话后不得继续使用旧 session 闭包。

#### 5.1.5 `delete_layer` 工具契约

| 项目 | 规则 |
|---|---|
| 工具名 | `delete_layer` |
| 输入 | `layer_id` |
| 前置校验 | 图层存在、属于当前会话、未锁定 |
| 结果 | 从 `LayerDocument.layers` 移除该层，revision 递增 |
| 历史 | 写入编辑历史，记录被删图层快照或可恢复引用 |
| 撤销 | 恢复图层内容、顺序、位置和属性 |
| 共享素材 | 不立即删除 `assets` 记录和对象存储文件 |
| 错误 | 图层不存在、当前图层不可删除、没有可编辑会话 |

删除快捷键只负责调用 `tools.invoke('delete_layer', { layer_id })`，不在 Zustand 中直接 splice。

### 5.2 图层实时缩略图

#### 5.2.1 目标

图层面板每一行都显示当前图层内容的真实缩略图，而不是只显示源素材图或固定占位文字。

- 图像层：显示当前缩放、旋转、透明度和滤镜预览后的近似内容。
- 文字层：显示当前文案、字号、颜色和排版。
- 形状层：显示当前形状、填充和边框。
- 隐藏层仍然生成缩略图，但列表整体降低透明度并显示显隐状态。
- 空文字层显示可辨认的空状态，不显示错误的图片。

#### 5.2.2 生成策略

- 使用 Konva 离屏渲染或节点导出能力生成小图，建议尺寸 40–64 px，输出透明背景或棋盘格底。
- 以图层内容哈希缓存 `dataURL / blobURL`，文案、字号、颜色、尺寸、形状或图片引用变化时失效。
- 变换拖动过程中不必每一帧重算；在拖动结束或内容稳定后 80–150 ms 内更新，既跟手又避免阻塞主画布。
- 缩略图生成失败不能影响图层面板使用，回退到现有素材缩略图或文字/形状图标，并记录一次前端错误。
- 离开图层或卸载列表时释放 `ObjectURL` 和离屏节点，避免长时间编辑造成内存增长。
- 图片来自签名 URL 时必须确认 Canvas 未被跨域污染；若 `toDataURL()` 抛错，应使用同源图片代理或服务端缩略图方案，不能静默显示白块。

#### 5.2.3 缩略图缓存与性能预算

建议缩略图键：

```text
thumb:{layer.id}:{kind}:{content_hash}:{width}:{height}:{transform_hash}:{opacity}:{visibility}
```

- `content_hash` 覆盖图片资产 id、文字内容、字号、颜色、形状属性。
- `transform_hash` 覆盖位置、旋转、缩放；若缩略图只展示层内内容、不展示画布位置，可以不把 `x/y` 放进缓存键。
- 缩略图默认为 48×48 或 64×64，最多 1 个 `requestAnimationFrame` 内生成一批，不逐像素实时重绘整个画布。
- 缩略图生成期间显示上一次成功的图，不能闪成空白。
- 生成失败时显示可辨认的降级图标，并在开发环境输出错误；不要把异常抛出到图层面板之外。
- 缩略图不应触发网络重新下载；图片加载失败和跨域污染要与“层本身为空”区分。

调试可观测字段：生成耗时、缓存命中率、失败类型、当前图层数量。生产环境不记录缩略图内容。

### 5.3 标尺、参考线与吸附

#### 5.3.1 标尺

- 画布顶部和左侧显示标尺，单位默认 px。
- 标尺随画布缩放和平移更新刻度，鼠标移动时显示当前位置。
- 画布左上角为 0,0，标尺坐标必须是画布坐标，不是屏幕坐标。
- 标尺可开关；手机端默认隐藏，避免挤压画布。

#### 5.3.2 参考线

- 用户从顶部标尺向下拖出水平参考线，从左侧标尺向右拖出垂直参考线。
- 参考线可拖动、删除和“清除全部”。
- 参考线使用画布坐标保存，缩放和平移后位置不漂移。
- 第一版参考线保存在前端本地状态或按会话存入 `localStorage`，不要求跨设备同步；如后续需要持久化，再扩展会话文档字段。
- 参考线不能被导出到最终图片。

#### 5.3.3 吸附

移动图层时自动吸附到：

- 画布四边。
- 画布水平/垂直中心线。
- 已建立的参考线。
- 其他可见图层的边缘和中线。
- 必要时包括文字层和形状层的包围盒。

规则：

- 吸附阈值按屏幕像素计算，建议 6 px；转换为画布坐标时除以当前 zoom，避免放大后吸附过强或过弱。
- 吸附触发时显示高亮参考线或短线，让用户知道“吸到了哪里”。
- 按住 Alt/Option 临时关闭吸附。
- 吸附不能把图层永久限制在参考线上，移动超过阈值必须立即脱离。
- 只吸附当前拖动图层，不吸附到自身；不可见图层默认不参与。
- 第一版至少覆盖图层移动；缩放和旋转吸附可作为后续增强，不作为首期阻塞项。

#### 5.3.4 吸附算法

吸附坐标应统一使用画布坐标，显示时再转换到屏幕坐标：

```text
screen_to_canvas(screen) = (screen - view.offset) / view.scale
canvas_to_screen(canvas) = canvas * view.scale + view.offset
```

对当前拖动层计算变换后的 bbox：

```text
left, center_x, right
top, center_y, bottom
```

候选吸附位置：

- 画布：`0 / canvas.width / 2 / canvas.width`。
- 参考线：每条水平或垂直参考线的画布坐标。
- 其他可见图层：left/center/right 和 top/center/bottom。
- 当前图层自身的对应位置不参与候选。

对每个候选判断屏幕距离：

```text
distance_px = abs(candidate - current_edge) * view.scale
if min(distance_px) <= SNAP_THRESHOLD_PX and not altKey:
    将当前层移动到候选位置
    高亮候选参考线
```

规则补充：

- `SNAP_THRESHOLD_PX` 默认 6，配置化。
- 多个候选同时满足时选屏幕距离最小者；距离相同优先参考线，其次画布中心，再次其他图层。
- 吸附只在 `onDragMove` 的稳定帧应用，不能在每一帧重新排序导致抖动。
- 拖动超过阈值后立即解除吸附，不把图层锁死在线上。
- 吸附结果只影响交互中的边界，松手后仍通过现有 move 工具提交文档，保证撤销/重做和多人刷新一致。
- 参考线只存在前端时，导出和后端不受影响。

### 5.4 移动端适配

#### 5.4.1 布局

- 保留现有“对话 / 画布”切换，不强迫手机用户同时看两块。
- 画布模式底部增加工具栏，放置移动、笔刷、撤销、重做、图层和适应窗口等高频动作。
- 单按钮触控区域不小于 44 × 44 px，工具提示文案可缩短但不能只靠图标猜含义。
- 右侧图层面板在手机上改为抽屉，不再固定挤压画布。
- 底部工具栏不能被软键盘、安全区或浏览器地址栏遮挡。

#### 5.4.2 手势

- 单指拖动图层：仅在移动工具且命中图层时生效。
- 单指拖动空白区域：按当前工具决定平移或建立选区。
- 双指捏合：缩放画布，以两指中心为锚点。
- 双指拖动：平移画布。
- 双指手势结束后，不应误触发图层拖动、选区点击或文字双击。
- 画布容器使用适当的 `touch-action`，阻止页面在画布手势期间滚动，但面板和输入框仍应可滚动。
- 手势写入 `canvasView` 时只改视图，不写回 `LayerDocument`，不产生撤销历史。

#### 5.4.3 断点与手势状态

| 宽度 | 布局 |
|---|---|
| `<= 599px` | 对话/画布切换、底部工具栏、图层面板抽屉、标尺默认关闭 |
| `600–900px` | 画布优先，图层面板可覆盖在右侧，保留主要工具 |
| `> 900px` | 当前桌面布局，标尺可默认开启 |

手势状态机：

```text
idle
  -> pointer_down(1) -> single_drag
  -> pointer_down(2) -> pinch_pan
pinch_pan
  -> pointer_up(1) -> single_drag_or_idle
  -> all_up -> idle
single_drag
  -> pointer_down(2) -> pinch_pan
  -> pointer_up -> idle
```

- 从单指进入双指时必须取消当前图层拖动和选区绘制，不能把双指手势的第一根手指算成一次移动提交。
- 双指结束后的 150–250 ms 内忽略单击和双击，避免误选中。
- 双指缩放只改变 `canvasView`；图层缩放只在移动工具结束并调用后端工具时写文档。
- 移动端工具按钮使用 `aria-label` 和可见短标签；不能只显示图标。
- 浏览器软键盘弹出时，隐藏底部工具栏或将其移到安全区域，不让输入框被遮挡。
- `prefers-reduced-motion` 下禁用不必要的过渡，不把动画当成功能反馈。

### 5.5 需求二验收标准

1. 在输入框、弹窗和中文输入法组合态按 V/B/Delete/Space 不会误触发。
2. V/B 切换后工具按钮、光标和行为一致；Space 松开恢复原工具。
3. Delete 删除选中图层后写入历史，⌘/Ctrl+Z 能恢复；锁定背景层被拒绝删除。
4. 图层缩略图覆盖图片、文字和形状三种类型，内容变化后 150 ms 内更新，列表滚动不明显卡顿。
5. 从标尺拖出参考线后，移动图层可吸附到画布边、中心、参考线和其他图层边缘；Alt 可临时取消吸附。
6. 手机端双指缩放和双指平移可用，手势结束不误触发点击或拖动；底部工具栏在 375 px 宽度下不横向溢出。
7. 所有新增交互不改变导出的像素结果，不把标尺、参考线或选中框写入成图。

## 6. 需求三：安全加固

### 6.1 限流与每日额度的关系

| 机制 | 解决的问题 | 计费单位 | 超额错误 |
|---|---|---|---|
| 每日额度 | 一天内总共能成功生成多少 AI 图片 | AI 图片次数 | `409 QUOTA_EXHAUSTED` |
| 接口限流 | 一分钟或一小时能发多少请求、能占多少队列 | HTTP 请求或并发连接 | `429 RATE_LIMITED` |

两者必须同时存在：

- 限流不预占、不扣减每日额度。
- 额度不足不能靠限流绕过，反之亦然。
- 先完成认证与限流，再创建任务和额度预占；被限流的请求不得产生 `ToolRun`、队列任务或厂商调用。

### 6.2 限流维度

#### 6.2.1 用户维度

对已登录用户，主限流键为：

`rl:{policy}:{user_id}`

同一用户即使更换 IP、并发开多个标签页，也受同一用户阈值约束。

#### 6.2.2 IP 维度

对未登录入口和公共入口，使用：

`rl:{policy}:ip:{normalized_ip}`

- 登录、注册、管理员登录必须同时限制 IP 和用户名/账号指纹。
- 生成、编辑等已登录入口同时应用用户限流和较宽松的 IP 限流，防止单个 IP 快速切号。
- 反向代理部署只信任显式配置的代理层解析转发头；未配置时禁止直接信任任意 `X-Forwarded-For`，避免伪造 IP 绕过。
- IPv6 需要使用规范化地址或前缀，避免同一用户用不同表示绕过。
- 阈值要允许同一公司/校园 NAT 下的正常用户，IP 策略不能过严。

### 6.3 建议策略

以下为初始建议值，实施后依据压测和真实流量调整；管理员与普通用户使用独立策略，不允许通过请求参数或前端开关绕过限流。

| 入口 | 策略 | 用户维度 | IP 维度 |
|---|---|---|---|
| `POST /api/auth/login` | auth-login | 按用户名 5 次/分钟 | 20 次/分钟 |
| `POST /api/auth/register` | auth-register | — | 3 次/小时 |
| `POST /api/auth/admin/login` | admin-login | 按用户名 5 次/分钟 | 10 次/分钟 |
| `POST /api/generations` | ai-generate | 5 次/分钟 | 20 次/分钟 |
| `POST /api/batches` | ai-batch | 3 次/分钟 | 10 次/分钟 |
| `POST /api/sessions/{id}/messages` | agent-plan | 10 次/分钟 | 30 次/分钟 |
| `POST /api/sessions/{id}/tools/invoke` | editor-write | 30 次/分钟 | 120 次/分钟 |
| `POST /api/assets` | upload | 10 次/分钟 | 30 次/分钟 |
| `GET /api/delivery-jobs/{id}/export` | export | 5 次/分钟 | 20 次/分钟 |
| `GET /api/*` 普通查询 | read | 120 次/分钟 | 300 次/分钟 |
| `GET /events/*` | sse-connect | 5 个并发连接 | 20 个并发连接 |

实施时允许把同一工具族合并成策略，例如所有画布数字修改共用 `editor-write`，但不能只按完整 URL 计数导致用户改 UUID 就获得新配额。

### 6.4 Redis 滑动窗口

- 使用 Redis 有序集合实现滑动窗口，必须通过 Lua 脚本原子完成清理、计数、拒绝/写入和过期时间设置。
- 不能采用“GET 后 Python 判断再 SET”的非原子流程，否则并发请求可突破阈值。
- 多 API 实例共享同一 Redis 计数；本地内存只作为 Redis 故障时的应急降级，不作为主限流器。
- 每个策略配置 `limit`、`window_seconds`、作用域和是否同时检查 IP。
- 计数键要带策略名，避免普通查询和生成互相占用额度。
- 不把提示词、密码、完整 Cookie 或原始文件内容写入 Redis 限流键。

#### 6.4.1 原子限流脚本要求

建议使用一个 Lua 脚本一次检查所有需要的 scope，避免“用户维度已计数、IP 维度拒绝”造成计数污染。脚本返回：

```text
allowed: boolean
scope: user | ip | username | anonymous
limit: number
remaining: number
reset_at_ms: number
retry_after_ms: number
```

伪代码：

```text
now = server_time_ms()
for each key in keys:
    remove scores < now - window_ms
    count = ZCARD key
    if count >= limit:
        earliest = ZRANGE key 0 0 WITHSCORES
        retry_after = earliest_score + window_ms - now
        return denied(scope, retry_after)

for each key in keys:
    ZADD key now member
    PEXPIRE key window_ms + safety_ms
return allowed
```

关键约束：

- 使用 Redis 服务端时间或所有 API 实例同步时间，不依赖单台机器的本地时钟。
- 多 scope 一次 Lua 调用完成；不能先检查用户再检查 IP，避免部分写入。
- member 使用随机请求 ID，避免同一毫秒多请求去重。
- key 必须带策略名和窗口，不能使用完整 prompt 或 URL。
- 对成功请求和失败请求都要计数；认证失败也计入认证策略。
- 登录失败的用户名指纹使用稳定哈希，不存明文用户名。
- Redis 返回异常时进入 `degraded` 模式并记录告警，不伪装成正常放行。

#### 6.4.2 请求处理顺序

```text
1. 解析 Cookie / JWT，得到可信用户身份（若已登录）
2. 解析真实客户端 IP（仅在可信代理配置正确时）
3. 选择路由策略，计算归一化 key
4. 原子检查用户/IP/账号指纹限流
5. 参数校验（Pydantic）
6. 权限检查与源 revision 检查
7. 创建任务、额度预占、入队
8. 返回 202 / 结果
```

被步骤 4 拒绝的请求不能进入步骤 5 之后。上传请求在读取大文件前应尽量完成限流；即使 FastAPI 已解析 multipart，也不能在读完 20 MB 后才第一次检查。

#### 6.4.3 配置示意

```text
rate_limit.enabled=true
rate_limit.mode=shadow|enforce
rate_limit.trusted_proxy_ips=127.0.0.1,::1
rate_limit.fallback=local

policy.ai_generate:
  limit=5
  window_seconds=60
  scopes=user,ip
policy.editor_write:
  limit=30
  window_seconds=60
  scopes=user,ip
policy.read:
  limit=120
  window_seconds=60
  scopes=user,ip
```

`shadow` 模式只计数、记录和返回可观测头，不实际 429；正式启用前至少观察一组真实流量。

### 6.5 错误响应与前端行为

统一返回 429，示例：

```json
{
  "detail": {
    "code": "RATE_LIMITED",
    "message": "请求过于频繁，请稍后重试",
    "scope": "user",
    "limit": 30,
    "window_seconds": 60,
    "retry_after_seconds": 12
  }
}
```

要求：

- 响应头包含 `Retry-After`；可选返回 `X-RateLimit-Limit`、`X-RateLimit-Remaining`、`X-RateLimit-Reset`。
- 前端 `api/client.ts` 通过 `code === 'RATE_LIMITED'` 做逻辑判断，不匹配中文文案。
- 生成按钮在 429 后显示倒计时或“请稍后再试”，但不应把整个编辑器永久锁死。
- 限流错误与额度耗尽错误分别展示，不能把 429 显示成“今日免费次数已用完”。
- 请求被 429 拒绝时不得留下孤立的 running/queued 任务。

### 6.6 安全基线加固

限流是本次安全主项，但当前项目还需要同批补齐以下低风险高收益项：

| 优先级 | 项目 | 验收方式 |
|---|---|---|
| P0 | 生成/编辑/认证/上传限流 | 并发请求与跨实例测试 |
| P0 | 生产默认密钥检查 | 生产配置启动失败测试 |
| P1 | 登录失败锁定和账号枚举收敛 | 失败响应、锁定恢复测试 |
| P1 | 统一安全响应头 | 浏览器响应头和 CSP 检查 |
| P2 | Origin / Sec-Fetch-Site 校验 | 跨站 POST 被拒绝 |
| P2 | 资源与导出上限 | 大文件、多目标和大 ZIP 测试 |


1. **登录防爆破**
   - 同一用户名连续失败达到阈值后短时锁定或指数退避。
   - 不存在用户名与密码错误对外返回同一文案，减少账号枚举。
   - 注册入口按 IP 限流，防止批量建号。

2. **生产配置校验**
   - `APP_ENV=production` 时禁止使用默认 JWT 密钥和默认对象存储凭证。
   - 未配置 `SECRET_ENC_KEY`、`JWT_SECRET` 等必要密钥时启动失败，不能带默认值上线。
   - 管理员初始化凭证不得写入前端构建产物或公开文档示例。

3. **请求来源与响应头**
   - 对修改状态的请求校验 `Origin` / `Sec-Fetch-Site`，保留现有 `SameSite=Lax` 与 HttpOnly Cookie。
   - 生产环境增加 `Content-Security-Policy`、`X-Content-Type-Options: nosniff`、`Referrer-Policy` 和 `frame-ancestors` 策略；HTTPS 下增加 HSTS。
   - 不新增通配符 CORS；工作台和管理后台继续同源访问。

4. **资源边界**
   - 保留现有上传 20 MB、5000 万像素和格式解码校验。
   - 为多目标生成、ZIP 打包、模板预览设置目标数量、图片数量、总字节和内存上限。
   - SSE 连接数纳入并发限制，避免长连接无限堆积。

5. **权限回归**
   - 新增的 preset、template、brand、job、item、export 接口全部按当前用户校验。
   - 管理员接口只认后台会话或既有管理员依赖，不能被普通工作台会话提升权限。
   - 限流和日志不泄露密码、Cookie、厂商密钥和签名 URL。

### 6.7 可观测性

至少记录以下结构化字段：

- 时间、请求 ID、路由策略名、限流 scope、是否命中、当前计数、阈值、窗口。
- 用户 ID 可记录内部 UUID；IP 按部署安全要求脱敏或仅记录哈希。
- 429 计数按策略聚合，便于判断阈值过严还是异常刷量。
- 记录 Redis 限流脚本错误、降级模式启用和恢复时间。
- 不把完整 prompt、图片内容或访问令牌写入限流日志。

### 6.8 限流失败策略

- 生成、批量、Agent 规划等可能产生费用的入口：Redis 不可用时采用保守的本地应急限流；无法判断时优先拒绝重任务，返回可重试错误，而不是无限放行。
- 普通查询：可采用本地保守计数维持基本可用，但必须记录降级告警。
- 限流组件自身异常不能导致全站所有请求 500；应区分“限流拒绝”和“服务不可用”。
- 部署恢复后，Redis 计数重新建立；不要求补记故障期间的每一次请求，但不能把降级当成永久关闭限流。

#### 6.8.1 失败分类

| 故障 | 生成类接口 | 查询类接口 |
|---|---|---|
| Redis 超时 | 保守拒绝，返回可重试错误 | 本地应急计数，优先保持只读可用 |
| Redis 脚本异常 | 记录告警并保守拒绝重任务 | 本地应急计数 |
| 限流配置缺失 | 启动失败，不使用“无限放行”兜底 | 启动失败 |
| 单实例本地桶溢出 | 按 LRU 限制内存，超限直接拒绝 | 按 LRU 限制内存 |
| 用户身份解析失败 | 401，不按匿名无限重试 | 401 |

限流故障不能伪装为普通 429；如果无法确定限流状态，应使用明确的 `503` 或内部错误码，并记录 request id。

#### 6.8.2 测试观测要求

- 每次限流拒绝记录 `request_id`、policy、scope、retry_after。
- 生成入口的 429 计数应能与未创建的 `ToolRun` 数量对上。
- 灰度期间观察总请求、429 数、429 用户分布、Redis 延迟和降级次数。
- 不记录密码、Cookie、Authorization、签名 URL、完整 prompt 和图片字节。

### 6.9 需求三验收标准

1. 同一用户 1 分钟内第 6 次提交生成请求返回 429，前 5 次最多创建 5 个任务。
2. 10 个并发生成请求中，最终创建的 `ToolRun` 不超过 5 个；被拒请求没有额度预占和队列任务。
3. 两个不同用户各自拥有独立限流桶，互不影响。
4. 登录、注册、生成、编辑、上传和查询分别命中各自策略，修改 URL 中的 UUID 不能绕过。
5. 429 响应包含 `RATE_LIMITED`、`retry_after_seconds` 和 `Retry-After`；前端能显示倒计时且不误报额度耗尽。
6. 不使用可信代理配置时伪造 `X-Forwarded-For` 不能绕过 IP 限制。
7. Redis 暂停后生成类接口进入保守拒绝或本地应急限流，不会无限放行；恢复后正常计数。
8. 生产环境使用默认 JWT 密钥或缺失加密主密钥时启动失败，并给出明确部署错误。
9. 所有新增接口的跨用户访问测试通过，不能通过 job/item/asset ID 读取他人结果。

| P0 安全基线 | Redis 限流、429 语义、认证防爆破、生产配置检查、安全响应头 | 先挡住费用和队列滥用 | 现有 Redis、认证、额度链路 |
| P1 编辑器快赢 | V/B/Delete/Space、统一工具状态、实时缩略图、标尺参考线吸附 | 用户立刻感受到编辑效率提升 | `delete_layer` 工具、前端 store 重构 |
| P2 平台适配 | preset、主体分析、contain/smart_crop、多目标任务、预览和打包 | 上线“多平台一键适配”核心价值 | P0 限流、目标 item 数据表、额度预估 |
| P3 AI 扩图 | outpaint 策略、蒙版/主体保护、失败重试和成本提示 | 横竖转换和补边质量提升 | P2、provider 能力核验 |
| P4 模板出图 | JSON Schema、三类模板、品牌配置、形状/换行渲染、成套出图 | 从“生成图片”升级为“可编辑物料” | P2、服务端渲染补齐 |
| P5 移动端完善 | 双指手势、底部工具栏、抽屉图层面板、小屏回归 | 手机浏览器可完成基础修图 | P1 |

P0 和 P1 可以并行；P2 在 P0 后开放，避免无频率保护的多目标任务放大成本；P4 不应阻塞 P2 的本地尺寸适配价值。

### 8.1 实现影响清单

| 区域 | 建议新增/修改 |
|---|---|
| 数据库 | `delivery_presets`、`delivery_jobs`、`delivery_job_items`、`marketing_template_versions`、`brand_profiles` 及 Alembic 迁移 |
| 后端 schema | DeliveryPreset、SourceSnapshot、DeliveryPreview、DeliveryJob、DeliveryItem、Template Schema、BrandProfile、RateLimitPolicy |
| 后端服务 | `delivery.py` 负责预览、主体分析、任务编排；`templates.py` 负责模板校验、排版和 LayerDocument 编译 |
| 后端工具 | 保留 `prepare_delivery_sizes`；新增多目标投放工具和模板渲染工具；新增 `delete_layer` |
| 后端安全 | Redis 限流器、策略注册表、429 错误、可信代理解析、生产配置校验、安全响应头 |
| 前端页面 | 在 `MarketingPage` 增加适配平台、模板、交付三个区域；不新增重复营销页 |
| 前端状态 | 扩展 `editorUi`，增加工具状态、参考线、吸附、缩略图缓存；请求错误增加 `RATE_LIMITED` 分支 |
| 前端画布 | 手势、吸附、标尺、参考线、形状层渲染、缩略图导出 |
| 测试 | 几何/模板纯单元测试、API 权限与幂等测试、Redis 多实例并发测试、浏览器交互测试 |

### 8.2 迁移与兼容要求

- 新增表只做增量迁移，不修改已有 `ToolRun`、`Asset`、`EditSession` 的语义字段。
- 旧 `ratios` 参数继续由旧工具处理，新投放目标通过新接口和新表执行。
- 模板和 preset 使用 `schema_version`，前端遇到不认识的更高版本应提示刷新，而不是崩溃。
- 新旧任务并行存在时，前端按 `tool`/`job_type` 路由展示，不把旧 `prepare_delivery_sizes` 结果强制转换成新 job。
- 旧会话的 `LayerDocument` 缺少 `shape` 或模板字段时使用默认值；不得因新增字段导致历史会话打不开。
- 迁移失败可回滚；数据种子可重复执行且幂等。

## 9. 测试与验收矩阵

### 9.1 尺寸与模板

- 800 × 800、1080 × 1440、1080 × 1920 和 2.35:1 边界尺寸输出准确。
- 横图转竖图、竖图转方图、透明商品、多商品、贴边主体、低置信度主体。
- `contain` 不裁切；`smart_crop` 保护框完整；`outpaint` 未授权不调用。
- 模板长标题、长价格、缺 Logo、超长卖点、中文换行、不同 DPI/导出格式。
- 预览与导出逐像素几何对照，至少完成一张人工视觉复核。

#### 9.1.1 详细用例

| 用例 | 输入 | 期望 |
|---|---|---|
| T1-01 | 不同源图比例，`contain` 输出 | 输出像素与 preset 完全一致，无拉伸 |
| T1-02 | 横图转竖图，保护框完整 | `smart_crop` 输出包含保护框且主体不被切边 |
| T1-03 | 保护框超出可裁剪范围 | 回退 `contain`，返回明确 warning |
| T1-04 | 多商品、贴边商品、透明商品 | 保护框并集正确，不裁掉任一商品 |
| T1-05 | 用户未选 `outpaint` | 不产生模型调用、不预占额度 |
| T1-06 | 三个目标中一个 provider 失败 | 其余成功可下载，manifest 包含失败项 |
| T1-07 | 重试失败目标 | 成功目标不重建、不重复扣额度 |
| T1-08 | 预览后修改源 revision 再提交 | 返回 409 `SOURCE_REVISION_STALE` |
| T1-09 | 模板长标题/长价格/缺 Logo | 有字号下限、换行或明确校验错误 |
| T1-10 | 模板预览和导出对照 | 几何、字体、换行和颜色一致或误差可解释 |
| T1-11 | 非本人 preset/job/asset 访问 | 404 且不泄露资源信息 |
| T1-12 | 大体积 ZIP | 达到上限返回 413，不把 API 内存打满 |

#### 9.1.2 自动化测试建议

- 几何函数使用固定源图、保护框、目标尺寸做纯单元测试。
- 模板编译器做快照测试，保存 `LayerDocument` JSON。
- ZIP 测试检查文件名、manifest 字段、图片实际像素和 MIME。
- 幂等测试使用同一 `Idempotency-Key` 发两次请求。
- 任务状态测试覆盖 queued/running/partial/succeeded/failed 和 worker 重入。

### 9.2 编辑器

- 快捷键在输入框、弹窗、菜单、中文输入法组合态不误触。
- 快速连按撤销/重做不产生重复请求。
- 删除图层可撤销；锁定层不可删除。
- 图层缩略图在图片、文字、形状、隐藏层和切换会话时正确更新。
- 标尺缩放/平移坐标正确；参考线拖动、删除和吸附阈值正确。
- 手机双指手势不误触图层拖动；软键盘出现时工具栏不遮挡。

#### 9.2.1 详细用例

| 用例 | 输入 | 期望 |
|---|---|---|
| T2-01 | 在输入框按 V/B/Delete | 不切工具、不删图层、不写历史 |
| T2-02 | 中文输入法组合态按 Delete | 不触发图层删除 |
| T2-03 | 按住 Space 拖动后松开 | 画布平移，工具恢复，不生成撤销记录 |
| T2-04 | V/B/Delete 在无选中层 | 不报错、不产生空操作 |
| T2-05 | 删除锁定背景层 | 被拒绝并给出中文原因 |
| T2-06 | 快速连按撤销/重做 | 请求最多一个在途，不产生重复历史 |
| T2-07 | 文案、字号、颜色变化 | 对应文字层缩略图更新 |
| T2-08 | 图片层旋转/缩放 | 缩略图反映变换后的内容，不白屏 |
| T2-09 | 跨域图片加载 | 缩略图失败时有降级，不抛出未处理错误 |
| T2-10 | 移动层靠近画布中心、参考线、其他层边缘 | 吸附并高亮，Alt 临时取消 |
| T2-11 | 手机双指缩放/平移 | 画布缩放平移正确，结束不误触图层 |
| T2-12 | 软键盘弹出 | 输入框可见，底部工具栏不遮挡 |

#### 9.2.2 手工验收环境

- Chrome/Edge 桌面至少各一次。
- 375 × 667、390 × 844、768 × 1024 三种小屏尺寸。
- 真实触控设备至少一台；仅用 DevTools 触摸模拟不能替代物理手势验证。
- 至少使用一张带透明通道图片和一张跨域签名 URL 图片。

### 9.3 安全

- 单用户、双用户、同 IP 多用户、同用户多 IP 的限流隔离。
- 并发脚本同时打生成、编辑、上传、登录和查询入口。
- 代理头伪造、Redis 宕机、Redis 恢复、跨实例多 API 实例。
- 429 响应结构、前端提示、无任务残留、无额度误扣。
- 新增资源和下载的越权访问。
- 生产环境默认密钥启动检查。

#### 9.3.1 详细用例

| 用例 | 输入 | 期望 |
|---|---|---|
| T3-01 | 单用户 6 次/分钟生成 | 前 5 次正常，第 6 次 429 |
| T3-02 | 单用户 10 个并发生成 | 最多 5 个任务，无超额预占 |
| T3-03 | 两个用户同 IP 并发 | 用户桶独立，IP 桶按配置生效 |
| T3-04 | 同一用户换 IP 继续请求 | 仍受用户桶限制 |
| T3-05 | 伪造 `X-Forwarded-For` | 未配置可信代理时不能绕过 |
| T3-06 | 修改 URL 中 job UUID 连续请求 | 不能获得新的策略桶 |
| T3-07 | Redis 停止 | 生成类保守拒绝，查询类降级可观测 |
| T3-08 | Redis 恢复 | 计数重新建立，接口恢复 |
| T3-09 | 429 + `Retry-After` | 前端显示倒计时且无孤立任务 |
| T3-10 | 额度耗尽后再生成 | 返回 409 而不是 429 |
| T3-11 | 跨用户访问 job/item/export | 统一 404 |
| T3-12 | production 使用默认 JWT 密钥 | 启动失败并给出部署错误 |

#### 9.3.2 压测建议

- 至少 2 个 API 实例共享同一 Redis，验证多实例一致性。
- 使用固定请求数、并发数、窗口边界（59.9 秒、60.1 秒）测试滑动窗口。
- 检查 429 响应时间不会因全局锁显著放大。
- 监控 Redis 命令延迟、脚本错误和本地降级情况。

### 9.4 回归

- 现有 `/create`、`/editor`、`/candidates`、`/marketing`、`/batch` 主链路不回退。
- 旧会话文档缺少新字段时能加载；旧 `ratio` 工具调用仍可用。
- 现有撤销/重做、选区失效、只上墙语义、ZIP manifest 兼容。
- 浏览器控制台无新增未处理异常，画布图片无 CORS 污染导致的导出失败。

## 10. 风险与待确认事项

| 风险/决策 | 影响 | 处理建议 |
|---|---|---|
| 平台尺寸和安全区会变 | 配置过期导致输出不符合平台要求 | 建 `verified_at` 和来源链接，发布前人工复核 |
| AI 扩图可能改商品细节 | 用户误以为商品像素不变 | 明确提示、优先蒙版合成、真实样例审核 |
| 前端预览与服务端导出不一致 | 模板看似正确但成品错位 | 单一模板编译器，前后端共享约束，实际像素验收 |
| 图层缩略图导致性能下降 | 多图层编辑卡顿 | 离屏渲染、内容哈希缓存、稳定后更新、释放资源 |
| 跨域签名 URL 污染 Canvas | `toDataURL` 失败、无法导出缩略图 | 检查存储 CORS，必要时同源代理或服务端缩略图 |
| 限流阈值过严误伤 NAT 用户 | 正常用户无法使用 | 先观察/灰度，IP 策略宽于用户策略，按策略配置 |
| 伪造代理头绕过 IP 限流 | 安全边界失效 | 只信任显式代理，未配置时使用直连地址 |
| Redis 故障 | 限流不可用或全站不可用 | 重任务保守拒绝，轻查询本地降级，记录告警 |
| 管理员是否豁免限流 | 影响运营和安全 | 建议管理员有独立较宽策略，不做无限豁免 |

需要在实施前确认的业务参数：

1. 首批平台清单和每个用途的官方尺寸、格式、文件上限、安全区。
2. AI 扩图每次消耗的额度单位，是否按目标张数计。
3. 单次最多生成多少个投放目标、单次模板生成多少张。
4. 单用户并发运行任务上限和 SSE 最大连接数。
5. 参考线是否需要跨设备保存；首版建议只本地保存。
6. 限流阈值是否需要后台可视化编辑；首版可先配置文件和环境变量。

### 10.1 待确认参数及建议默认值

| 编号 | 待确认问题 | 建议默认值 | 如果暂不确定 |
|---|---|---|---|
| O1 | 首批平台用途 | 淘宝主图、小红书封面、抖音封面、公众号封面 + 三种通用画幅 | 先只开放通用画幅 |
| O2 | 平台尺寸来源 | 每个 preset 必填 `source_url` 和 `verified_at` | 标为“项目建议值”，不宣称官方 |
| O3 | `outpaint` 计费 | 每成功输出 1 张计 1 个 AI 单位 | 先关闭 `outpaint` |
| O4 | 单次目标上限 | 8 个 | 先用 4 个灰度 |
| O5 | 同步 ZIP 上限 | 128 MB / 32 文件 | 超出返回 413 或转后台 |
| O6 | 限流阈值 | 采用 6.3 建议值 | 先 shadow 观察 1–2 天 |
| O7 | 管理员限流 | 独立较宽策略，不无限豁免 | 保留审计日志 |
| O8 | 参考线持久化 | 只存当前浏览器本地 | 首期不做跨设备 |

### 10.2 不能带着上线的假设

- 不能假设 OpenCV 能可靠识别所有商品。
- 不能假设所有 provider 都支持指定画幅或 mask outpaint。
- 不能假设前端 Konva 看到的文字就是服务端 Pillow 导出的文字。
- 不能假设每日额度能拦住秒级刷接口。
- 不能假设 Redis 故障时默认放行是安全的。

## 11. 上线、灰度与回滚

### 11.1 上线顺序

1. 数据库迁移与 preset/template 种子数据发布，但功能开关保持关闭。
2. 先启用限流 `shadow`，确认计数、日志和 429 响应不会误伤正常链路。
3. 启用 `contain` 尺寸适配和预览，验证尺寸与 ZIP。
4. 启用 `smart_crop`，用受控样例和少量用户灰度。
5. 启用模板模式，先只开放商品主图模板。
6. 启用 `outpaint`，按用户灰度并核对额度与失败率。
7. 最后开放移动端底部工具栏和完整手势。

### 11.2 功能开关

建议至少保留以下开关：

```text
delivery_presets_enabled
delivery_smart_crop_enabled
delivery_outpaint_enabled
marketing_templates_enabled
editor_guides_enabled
rate_limit_mode=off|shadow|enforce
```

- 关闭功能不删除已完成任务和素材。
- 关闭 `outpaint` 不影响 `contain` / `smart_crop`。
- 关闭模板不影响现有四类营销图和普通投放尺寸。
- 关闭编辑器标尺/吸附不影响图层移动和导出。

### 11.3 回滚策略

- 限流回滚到 `shadow`，仍记录计数但不拦截；不能直接删除 Redis 或重置所有用户计数而不留记录。
- 模板回滚到普通营销图模式，已生成任务保留只读结果。
- `smart_crop` 回滚时新任务改用 `contain`，旧任务仍可查看和下载。
- 任务表和 preset/template 版本不删除；只切换读取开关。
- 数据库迁移保持向后兼容，旧代码读取新列时必须有默认值或忽略未知字段。

## 12. 交付判定

本需求不以“页面有入口”作为完成标准，而以以下结果判定：

- 用户能从同一张商品图完成多平台预览、生成和 ZIP 下载，输出尺寸正确且主体保护策略可解释。
- 用户能用模板生成可编辑文字和形状，且前端预览与服务端导出没有明显错位。
- 用户能用快捷键、缩略图、标尺和吸附完成常见图层移动，不需要频繁切换鼠标操作。
- 手机端能完成双指缩放、平移和基础图层移动。
- 限流在单实例、多实例和并发场景下都不能突破阈值，429、额度不足和权限错误语义互不混淆。
- 现有上传、编辑、生成、营销导出和批量链路没有业务语义回退。

### 12.1 每个需求的完成定义

**D1 完成：**

- preset 接口和版本表可用。
- `contain` 输出尺寸、背景和 ZIP 通过。
- `smart_crop` 对边界样例有可解释结果。
- 目标任务、失败重试、幂等和权限测试通过。

**E1 完成：**

- 快捷键不穿透输入框和 IME。
- Delete 有后端工具和撤销链路。
- 缩略图覆盖三类图层并有性能保护。
- 标尺/参考线/吸附通过桌面交互测试。
- 手机手势和底部工具栏通过真机测试。

**S1 完成：**

- 用户/IP 限流在单实例和多实例下都不超额。
- 429 不创建任务、不扣额度。
- 登录防爆破、生产密钥检查和安全响应头通过。
- 限流灰度和回滚流程可执行。

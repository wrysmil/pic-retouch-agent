# 前端 UI 高阶方案：品牌影像工作室

状态：调研后的第二版设计提案，尚未修改业务页面。

## 设计判断

当前产品已经具备生成、单图编辑、图层、选区、导出和批量处理。问题不是功能少，而是这些能力仍以“页面与按钮集合”出现，缺少一个能统领整条链路的产品形象。

第二版把产品重新定义为“品牌影像工作室”：用户不是来点某个 AI 工具，而是带着商品、品牌要求和投放目标进入一个项目，从视觉方向开始，经过精修与版本选择，最后交付一组统一的渠道物料。

## 三种设计方向

### A. 品牌影像工作室（推荐）

深墨色外壳、暖灰工作区、酸橙色信号强调。首页像一个正在运作的创意工作室，项目卡直接展示主视觉和渠道变体。编辑器进入克制的暗房框架，画布最大，AI 指令贴近正在编辑的内容。

优点是辨识度强，现有品牌色可以保留，既有专业感又不落入常见的蓝紫 AI SaaS 风格。它也最适合商品图、营销图和批量物料这三条现有链路。

### B. 象牙白编辑部

暖白背景、黑色排版、较大的作品图和杂志式不对称网格。视觉高级，首页表现力强，适合作品展示和轻量编辑。

不足是长时间编辑的聚焦感弱；工具和状态一多，容易退化成普通白色后台。

### C. 黑曜石专业暗房

全深色、紧凑工具条、细分属性面板，接近专业图像软件。画布对比度和沉浸感最好。

不足是对电商运营和非设计用户偏重，创作首页、素材管理和空状态容易显得冷。

最终采用 A：页面间允许明暗切换，但保持同一套材料、圆角、文字和信号色。

## 视觉系统

### 核心色

| 角色 | 色值 | 说明 |
| --- | --- | --- |
| 墨黑外壳 | `#101311` | 导航、编辑器外框、强调区域 |
| 暖石工作区 | `#ECE9E2` | 首页与项目页底色 |
| 象牙面板 | `#F8F6F1` | 输入、项目、设置面板 |
| 主文字 | `#18201D` | 浅色区标题与正文 |
| 暗色文字 | `#F4F5F0` | 深色区标题与操作 |
| 辅助文字 | `#66706A` | 时间、尺寸、说明 |
| 信号酸橙 | `#D9FF6E` | 主动作、当前状态、处理完成 |
| 工作青绿 | `#6FB4A5` | 选区、AI 运行状态、链接 |
| 边线 | `#D7D9D2` | 控件和内容分区 |

酸橙色只用于关键动作和状态，不铺大面积背景。AI 状态使用青绿，成功与主动作不会混淆。

### 字体与排版

- 中文沿用本地系统字体，避免新增字体下载和首屏闪动。
- 页面标题 28–36px，项目标题 18–22px，正文 14–16px，辅助信息不低于 12px。
- 数字、尺寸、版本号使用等宽数字；不引入装饰性英文衬线字体硬造“奢华感”。
- 首页使用不对称 12 栏网格；编辑器和交付中心使用严格功能网格。

### 材料与动态

- 主要面板使用 16px 圆角和细边线；只有浮动命令条、菜单和模态框使用阴影。
- 首页允许作品图轻微层叠，形成工作台深度；编辑器不使用装饰性卡片。
- 悬停 140–180ms，仅改变底色、边线和图标，不缩放布局。
- AI 执行时在命令条内显示阶段文字与细进度；画布不覆盖大面积 Loading。
- 尊重 `prefers-reduced-motion`。

## 信息架构

全局导航调整为：

1. 项目台：新建项目、最近项目、最近交付。
2. 编辑室：当前项目与最近编辑会话。
3. 交付中心：渠道物料、批量任务、导出包。
4. 素材库：上传素材、生成结果、品牌资产。

“创作、编辑、导出、批量”从四个平级功能页，变成项目生命周期里的阶段。路由可以在第一版继续沿用，先调整导航文案和页面组织，后续再决定是否合并路由。

## 核心页面

### 项目台

首屏不再只有一个大输入框，而是由三部分组成：

- 项目简报：商品图、目标渠道、视觉描述。默认“基于商品图创作”，也支持“从描述开始”。
- 视觉方向板：显示主视觉、细节图、竖版物料的构图示意；正式页面使用真实候选图。
- 最近项目：按项目而不是按零散素材展示，卡片显示当前主图、版本数、物料数和最后编辑时间。

提示词预设升级为视觉方向，例如“纯净棚拍”“自然晨光”“高级礼赠”，点击只填入，不自动提交。

### 编辑室

编辑器采用“工具轨 + 画布 + 导演面板”的三栏结构：

- 左侧工具轨：选择、裁剪、去背景、场景、调色、更多。图标与文字均可发现，不依赖悬停展开。
- 中央画布：画布占最大区域；顶部只保留项目标题、版本、撤销重做和导出；缩放与版本胶片条位于底部。
- 右侧导演面板：在“AI 导演、图层、属性”之间切换。选择物体后自动展示对象名称、保护约束和可用动作。
- 浮动命令条：位于画布底部，输入“让背景更暖一些”等指令；发送前显示当前作用范围，例如“背景层”或“当前选区”。

现有多步计划、确认、进度、撤销、重做和错误处理继续作为事实来源。界面不会制造假的完成百分比。

### 交付中心

交付中心是一张“发布桌面”：

- 左侧选择项目中的主图与版本。
- 中部按渠道展示 1:1、4:5、9:16 等真实预览。
- 右侧显示一致性检查：主体安全区、尺寸、分辨率、背景规则、文案溢出。
- 底部提供生成缺失物料和导出全部；批量任务也在这里显示进度和失败重试。

第一版只实现已有能力能够支持的检查项，不虚构平台合规结论。

### 首页

未登录首页采用编辑部式的大作品布局：左侧一句定位，右侧为一组真实产品能力预览。输入入口降低为次级，避免首屏像另一个聊天机器人。

页面叙事顺序：真实效果 → 工作方式 → 保真与可控 → 多尺寸交付 → 开始使用。演示图必须标记为示例。

## AI 交互原则

- 用户面向目标说话，系统把选区、图层、尺寸和工具变成上下文，不要求用户记命令。
- 每次执行前明确作用范围和会发生的步骤；涉及多个会改变画面的动作时继续使用现有确认机制。
- 商品标签、形状和颜色等“保真约束”在项目级保存并在编辑器中可见。
- 普通用户不出现底层模型选择器，模型继续由管理员统一发布；界面只表达能力和任务状态。
- 结果必须能继续编辑、对比、撤销和导出，AI 不能成为一次性黑盒。

## 响应式策略

- 1440px：完整导航、画布和 300px 导演面板。
- 1024px：导航收窄为带短标签的工具轨，导演面板可折叠。
- 768px：导演面板以底部抽屉打开，工具分组为两行；画布保持可操作。
- 375px：项目台单列；编辑器以画布为主，工具与面板按需打开；交付预览纵向排列。

关键触控区域至少约 44px；焦点状态不能只靠颜色；抽屉关闭后焦点回到触发按钮。

## 实施边界

第一阶段调整工作台设计 token、全局导航、项目台和创建流程。第二阶段调整编辑室布局和导演面板。第三阶段统一首页、候选页、交付中心和批量页。

不会在 UI 重构中修改后端模型配置、任务协议、计费逻辑或数据表；不会给普通用户增加模型选择；不会将静态示意中的项目、渠道检查或品牌数据写入正式业务。

## 验收标准

- 375、768、1024、1440px 无主操作截断和页面级横向溢出。
- 首页、项目台、编辑室和交付中心形成同一套视觉语言。
- 从上传或生成进入编辑，再进入导出的主链路不增加多余步骤。
- 编辑器常用动作无需横向滚动查找；作用范围、运行状态和错误可见。
- 键盘焦点、Esc 关闭、输入快捷键、撤销重做和减少动态效果保持有效。
- 后端可用后再验证真实生成、上传、编辑、确认、导出和批量链路；视觉预览不计为功能验证。

## 0. 结论与开工建议

三组需求不是同一风险等级，不建议合并成一次大改：

- **S1 是安全边界**：不做，投放入口越多，模型费用和队列被刷的风险越大。
- **E1 是局部交互改造**：改动集中在编辑器和图层工具，可独立上线、可独立回滚。
- **D1 是新产品链路**：涉及新表、新接口、新任务模型和渲染一致性，必须等限流可用后再开放。

建议顺序：

1. **A 安全基线（P0）与 B 编辑器快赢（P1）并行**，两者代码路径几乎不重叠。
2. **A 完成后做 C 尺寸适配（P2）**，先只开放 `contain + smart_crop`，`outpaint` 保持关闭。
3. **C 的数据模型稳定后做 D 模板与渲染（P4）**，按模板类灰度。
4. **最后做 E 扩图与移动端完善（P3/P5）**，真机验收后再全量。

如果只能先做一个批次：**做 A**。它挡的是真实费用和账号风险，回滚成本最低，且不改用户主链路。
如果更看重业务卖点：A 完成后立即做 C 的本地适配（不接 `outpaint`），B 并行推进。

|---|---|---|---|---|---|

## 2. 实施原则

1. **只做增量迁移**：不改 `ToolRun`、`Asset`、`EditSession` 的已有语义；新表和新字段都带默认值。
2. **旧入口继续可用**：`prepare_delivery_sizes`、`ratio` 参数、旧营销图不改；新能力走新接口。
3. **单一几何源**：`contain/smart_crop` 的窗口和评分只在服务端计算；前端只按返回的 `crop_rect/content_rect` 画预览。这样避免 Python/TS 两套几何实现漂移。
4. **单一任务外壳**：每个交付目标创建一个 `ToolRun`，复用现有额度预占、SSE、进度、失败释放、重试；父 job 只做聚合。
5. **统一请求顺序**：认证 → 限流 → 参数校验 → 资源归属 → 额度预占 → 入队。被限流的请求不产生 `ToolRun`、不扣额度。
6. **一切可开关**：preset、`smart_crop`、`outpaint`、模板、参考线、限流模式都进配置；关闭不删数据。
7. **不碰“明确不做”**：不做模板市场、自由脚本模板、完整矢量编辑、多页长图、平台自动上传。

## 3. 批次 A：安全基线（S1 / P0）

### A1 限流核心

新增目录 `backend/app/security/rate_limit/`：

| 文件 | 职责 |
|---|---|
| `policies.py` | 策略注册表与配置校验：`name / limit / window_seconds / scopes / fallback / enabled` |
| `lua.py` | 滑动窗口 Lua 脚本常量与返回值解析 |
| `identity.py` | 用户身份、IP 归一化、可信代理、用户名指纹 |
| `limiter.py` | Redis 调用、原子检查、本地降级、SSE 并发槽 |
| `errors.py` | `RateLimited`、`RateLimitUnavailable` 及统一响应 |
| `deps.py` | `rate_limit("policy-name")` 依赖工厂 |

**原子脚本**

- 一个 Lua 脚本一次检查本次请求涉及的所有 key（用户、IP、用户名指纹）。
- 脚本内用 `redis.call('TIME')` 取服务端时间，避免各实例时钟漂移。
- 流程：逐个 `ZREMRANGEBYSCORE` → `ZCARD` → 任一超限立即返回拒绝（不写入任何 key）→ 全部通过后逐 key `ZADD` + `PEXPIRE`。
- member 使用 `request_id`，避免同毫秒多请求被 ZSET 去重。
- 返回 `allowed / scope / limit / remaining / reset_at_ms / retry_after_ms`。

**身份与 IP**

- 已登录用户：从 JWT 直接取 `user_id` 作为桶键，不额外查库；令牌被撤销的用户仍计入原用户桶，安全侧可接受。
- 未登录：`anonymous + ip`。
- 登录/注册：IP + `sha256(归一化用户名)[:16]`，不存明文用户名。
- IP 归一化：`ipaddress.ip_address`；IPv6 默认按 /64 聚合；去掉端口和方括号。
- 只有 `request.client.host` 命中 `trusted_proxy_ips` 时才解析 `X-Forwarded-For`，并从右向左取第一个非可信地址；未配置时完全忽略转发头。

**降级**

| 故障 | 重任务（生成/批量/交付/上传） | 查询 |
|---|---|---|
| Redis 超时/脚本异常 | 返回 `503 RATE_LIMIT_UNAVAILABLE`，带 `Retry-After` | 进程内滑动计数，记录告警 |
| 本地桶溢出 | 按 LRU 淘汰，重任务直接拒绝 | 淘汰后放行并记录 |
| 策略配置缺失 | 启动失败 | 启动失败 |
| `shadow` 模式 | 只计数、写日志、加响应头，不拒绝 | 同左 |

**SSE 并发槽**

- 与请求频率分开：用 Redis ZSET 记录连接 ID + 心跳时间，连接建立时写入，断开时删除，超过 90 秒未心跳的成员清理。
- 限制的是“同时连接数”，不是每分钟请求数；超限返回 429。
- 在 SSE 生成器的 `finally` 中释放槽位。

### A2 路由接入

用依赖工厂逐个挂到路由，不按完整 URL 计数，因此改 UUID 不会获得新桶。

| 路由 | 策略 | 维度 | 备注 |
|---|---|---|---|
| `POST /api/auth/login` | `auth-login` | 用户名 + IP | 失败也计数 |
| `POST /api/auth/register` | `auth-register` | IP | 3 次/小时起步 |
| `POST /api/auth/admin/login` | `admin-login` | 用户名 + IP | 独立策略 |
| `POST /api/generations` | `ai-generate` | 用户 + IP | 5 次/分钟起步 |
| `POST /api/batches` | `ai-batch` | 用户 + IP | 3 次/分钟起步 |
| `POST /api/sessions/{id}/messages` | `agent-plan` | 用户 + IP | 10 次/分钟起步 |
| `POST /api/sessions/{id}/tools` | `editor-write` | 用户 + IP | 30 次/分钟起步 |
| `POST /api/assets` | `upload` | 用户 + IP | 读取 body 前先看 `Content-Length` |
| `POST /api/delivery-previews` | `delivery-preview` | 用户 + IP | 新增，10 次/分钟起步 |
| `POST /api/delivery-jobs` | `delivery-job` | 用户 + IP | 新增，3 次/分钟起步 |
| `POST /api/delivery-jobs/{id}/items/{item_id}/retry` | `delivery-retry` | 用户 + IP | 5 次/分钟起步 |

| `GET /events/*` | `sse-connect` | 用户 + IP | 并发槽，不是频率窗口 |
| `/api/health`、静态资源、`/api/docs` | 不挂 | — | 避免探活和文档被误伤 |

**接入顺序**：限流依赖放在端点参数之前；FastAPI 先解依赖再解析 body，所以上传可以在读 20 MB 之前拒绝。登录需要读用户名时，依赖里 `await request.json()`，Starlette 会缓存 body，后续参数解析不会重复读流。

### A3 认证防爆破

- `services/auth.py`：用户名不存在时也执行一次固定 dummy bcrypt 校验，减少时间侧信道；错误文案保持“用户名或密码错误”。
- 新增 Redis 失败计数：`auth:fail:user:{hash}` 和 `auth:fail:ip:{ip}`，15 分钟窗口；达到阈值返回 `429 AUTH_LOCKED`，并带 `Retry-After`。
- 不存在用户名同样计数，避免“只有真实账号才会被锁”造成枚举。
- 登录成功清空该用户名计数；管理员登录使用独立策略键。
- 注册只按 IP 限流；不引入邀请码或验证码，首期范围外。

### A4 生产配置与安全响应头

新增 `backend/app/security/http.py`（或 `middleware.py`），在 `main.py` 注册：

1. **Request ID**：优先读 `X-Request-ID`，否则生成 UUID；写入 `request.state.request_id`，响应头回传，限流日志和 5xx 日志都带它。
2. **安全响应头**：`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、`Content-Security-Policy`（`default-src 'self'; img-src 'self' data: blob: https:; connect-src 'self'; style-src 'self' 'unsafe-inline'; font-src 'self'; frame-ancestors 'none'`）、生产 HTTPS 下加 HSTS。
3. **Origin 校验**：只对 `POST/PUT/PATCH/DELETE`；`Sec-Fetch-Site: cross-site` 直接 403；`Origin` 存在且不属于同源/白名单时 403；浏览器不发送 `Origin` 的非浏览器客户端放行并记录。保留现有 `SameSite=Lax + HttpOnly`。
4. **生产配置校验**：在 `lifespan` 启动阶段、建桶之前执行；`APP_ENV=production` 时：
   - `JWT_SECRET` 不得等于默认值，长度 ≥ 32；
   - `SECRET_ENC_KEY` 必须存在且是合法 Fernet key；
   - `S3_ACCESS_KEY/S3_SECRET_KEY` 不得是开发默认值；
   - 限流策略必须全部可解析；
   - 任一项不满足直接启动失败，错误信息列出缺失项，不打印密钥值。

### A5 前端 429 体验

- `frontend/src/api/client.ts`：扩展 `StructuredDetail`，增加 `scope/limit/window_seconds/retry_after_seconds`；新增 `isRateLimited()`、`retryAfterSeconds()`。
- 新增 `frontend/src/stores/rateLimit.ts`：按“动作键”保存 `until` 时间戳；提交按钮显示倒计时，只锁当前动作，不锁整个编辑器。
- 生成、批量、投放提交、上传、登录分别处理；429 不得显示成“今日免费次数已用完”，额度错误仍走 `isQuotaExhausted()`。
- 429 后移除乐观任务卡；不要留下 running/queued 的假任务。

## 4. 批次 B：编辑器快赢（E1 / P1）

### B1 工具状态与快捷键

### C2 源快照与主体分析

新增表 `delivery_snapshots`（不新增 `AssetKind`，避免污染图片墙）：

| 字段 | 说明 |
|---|---|
| `id / user_id / session_id / revision` | 快照归属和源版本 |
| `content_hash` | 拍平 PNG 的 sha256 |
| `storage_key` | 对象存储 key，按需签发 URL |
| `width / height` | 快照尺寸 |
| `analysis` | 主体框、置信度、来源、遮罩引用、用户焦点 |
| `expires_at` | 预览快照默认 24 小时；任务快照保留到 job 清理 |

- 预览时：`flatten_session()` → 计算 hash → 查同 `(session_id, revision, hash)` 复用 → 写对象存储和快照行。
- 主体来源优先级：
  1. 已有 `subject` 图层或带 alpha 的图层的透明区域；
  2. 用户手动画的保护框；
  3. 降采样后的 rembg 分割（按内容哈希缓存）；
  4. OpenCV 显著/边缘仅作辅助。
- 置信度阈值集中配置：`high >= 0.75`、`medium 0.45–0.75`、`low < 0.45`；低置信度默认 `contain`，不激进裁剪。
- 多主体取全部框的并集，不只保护最大商品；文字层和形状层用变换后的几何 bbox，默认视为受保护内容。
- rembg 失败不阻塞预览：记录 warning，回退到全画面保护 + `contain`。

### C3 几何与预览

新增 `backend/app/services/delivery_geometry.py`（纯函数、可单测）：

- `contain_geometry(source_size, target_size)`：返回缩放后的 `content_rect` 和背景。
- `smart_crop_geometry(source_size, target_size, protect_rects, focus, margin)`：
  - 保护框先取并集并外扩安全边距；
  - 源比例宽于目标时 `crop_h = sh, crop_w = sh * r`，否则 `crop_w = sw, crop_h = sw / r`；
  - 正确约束：`left ∈ [protect.right - crop_w, protect.left]`，`top ∈ [protect.bottom - crop_h, protect.top]`，再夹到画布内；区间为空 → `contain + warning`；
  - 候选窗口只评估少量确定性位置：焦点居中、画布居中、左/右/上/下对齐，全部 clamp 到合法区间；
  - 评分权重和阈值集中为常量，禁止散落在组件里。
- 输出 `crop_rect`、`content_rect`、`strategy`、`warnings`、`quota_units`。

**预览接口** `POST /api/delivery-previews`：

- 请求：`source {session_id, revision}`、`targets [{preset_key, strategy}]`、`protect_boxes`。
- 响应：`snapshot {id, source_url, hash, revision}`、`analysis`、`targets [{preset_key, version, width, height, strategy, crop_rect/content_rect, warnings, quota_units}]`。
- **不做每目标预览图**：前端用 `source_url + 几何` 在本地画缩略图，减少对象存储和签名 URL；几何决策仍只在服务端。
- 源 revision 变化后旧快照失效，返回 `SOURCE_REVISION_STALE`，前端提示重新分析。

前端新增 `frontend/src/components/marketing/DeliveryTargetCard.tsx`，用小 canvas 按 `crop_rect/content_rect` 绘制；`outpaint` 只显示布局草图并标注“结果以生成为准”。

### C4 目标任务与重试

新增表：

- `delivery_jobs`：`user_id / status / source_snapshot_id / source_session_id / source_revision / source_hash / brand_snapshot / idempotency_key`。
- `delivery_job_items`：`job_id / item_key / preset_id / preset_version / preset_snapshot / strategy / template_key / template_version / inputs / status / attempt / tool_run_id / output_asset_id / error_code / error_message / quota_units`。
- 唯一约束：`(user_id, idempotency_key)`、`(job_id, item_key)`、`(item_id, attempt)`。

**执行模型**：

- 新增隐藏工具 `deliver_item`（`backend/app/tools/delivery.py`），`ToolSpec.agent_visible = False`，并在 `backend/app/agent/llm.py` 过滤，避免模型直接调用。
- 每个 item 通过 `tools.submit()` 创建独立 `ToolRun`，`quota_units`：`contain/smart_crop = 0`，`outpaint = 1`。
- `ToolSpec` 增加 `task: str = "run_tool"`；交付 item 使用新任务 `backend/app/tasks/delivery.py::run_delivery_item`，任务内部调用 `tools.execute()`，结束后更新 item/job 聚合状态。
- `tools.submit()` 增加逻辑：零额度本地任务不强制解析运行配置版本（见 R1）。
- 状态机：

```text
job:  queued -> running -> partial_succeeded | succeeded | failed | canceled
item: queued -> running -> succeeded | failed | canceled
retry: failed -> queued (attempt + 1)
```

- 父 job 由所有 item 推导：全成功 `succeeded`；部分成功 `partial_succeeded`；全失败 `failed`。
- 重试只允许 `failed`/可重试 `canceled` item；成功 item 不再入队、不重复预占。
- 幂等：创建 job 用 `Idempotency-Key` + 数据库唯一约束；重复请求返回同一 job；retry 用 `(item_id, attempt)` 去重。
- 额度：提交前预检总需求，创建时逐 item 预占；中途额度不足时已成功 item 不回滚，剩余 item 标为 `QUOTA_EXHAUSTED`，允许额度恢复后单独重试。
- 恢复：新增 cron 扫描“`queued` 但没有 `tool_run_id`”的 item，补投递或标失败，避免 API 在 job 创建后崩溃留下孤儿。

状态覆盖：无源图、分析中、可预览、源已过期、提交中、部分成功、全部失败、限流中、额度不足。错误按“源/主体/模板/额度/限流/存储”分类，不只显示 `run.status === failed`。

## 7. 批次 E：扩图与移动端完善

### E1 `outpaint`

- 只在用户明确选择时调用；提交前显示 AI 次数和目标数量。
- 当前 provider 只有整图编辑能力，没有 mask 协议：v1 生成目标画幅整图，并强制提示“AI 扩图可能轻微改变商品细节”，不做硬蒙版回贴（避免对不齐造成更差结果）。
- 生成结果如果与目标比例不一致，使用留白适配到精确像素并记录 warning，不拉伸、不静默裁切。
- 每成功输出 1 张计 1 个 AI 单位；失败释放预占；不自动切换到另一个消耗额度的策略。
- provider 不支持指定画幅时，隐藏 `outpaint` 或在提交前返回 `PROVIDER_UNSUPPORTED`。

### E2 移动端

- 断点：`<= 599px` 对话/画布切换 + 底部工具栏 + 图层抽屉 + 标尺默认关闭；`600–900px` 画布优先；`> 900px` 桌面布局。
- 底部工具栏：移动、笔刷、撤销、重做、图层、适应窗口；按钮 ≥ 44×44 px，带 `aria-label` 和短标签；`env(safe-area-inset-bottom)`；软键盘弹出时隐藏或上移。
- 图层面板：小屏改为右侧抽屉 + 背景遮罩，不再固定挤压画布。
- 手势状态机：

```text
idle
  -> pointer_down(1) -> single_drag
  -> pointer_down(2) -> pinch_pan
pinch_pan
  -> pointer_up(1) -> single_drag_or_idle
  -> all_up -> idle
single_drag
  -> pointer_down(2) -> pinch_pan
  -> pointer_up -> idle
```

- 第二根手指按下时取消当前图层拖动/选区绘制；临时关闭 Konva listening，防止双指手势被算成图层拖动。
- 双指缩放以两指中心为锚点，双指拖动平移；只写 `canvasView`，不写 `LayerDocument`，不产生撤销历史。
- 双指结束后的 150–250 ms 忽略单击/双击。
- 画布容器在画布模式使用 `touch-action: none`；面板和输入框保持可滚动。
- `prefers-reduced-motion` 下减少过渡。

### E3 验收

- T2-11/12：双指缩放/平移正确，结束不误触图层；软键盘不遮挡工具栏。
- 真机至少一台；375×667、390×844、768×1024 三种尺寸。
- 至少一张透明通道图片和一张跨域签名 URL 图片。

## 8. 数据模型与迁移顺序

| 迁移 | 内容 | 说明 |
|---|---|---|
| M1 | `delivery_presets` | `(key, version)` 唯一；`(status, platform, placement)` 索引 |
| M2 | `delivery_snapshots` | `(session_id, revision, content_hash)` 唯一；`expires_at` 索引 |
| M3 | `delivery_jobs` | `(user_id, idempotency_key)` 唯一；`(user_id, created_at)` 索引 |
| M4 | `delivery_job_items` | `(job_id, item_key)` 唯一；`(item_id, attempt)` 唯一；`tool_run_id` 索引 |
| M5 | `marketing_template_versions` | `(template_key, version)` 唯一 |
| M6 | `brand_profiles` | `(user_id, name)` 唯一 |

- 全部增量迁移，不改旧表字段；`LayerDocument` 新字段在 JSONB 内，读取时由 Pydantic 默认值兜底。
- 种子脚本幂等：preset 和模板按 `(key, version)` upsert，重复执行不产生新版本。
- 快照清理：预览快照 24 小时；job 快照按保留策略（建议 30 天）清理对象存储和行；不删除已完成任务记录。
- 回滚：迁移保留旧列和旧表读取路径；新功能关闭时不依赖新表。

## 9. 接口与错误码

| 方法与路径 | 用途 | 限流 | 幂等/权限 |
|---|---|---|---|
| `GET /api/delivery-presets` | 已发布 preset | `read` | 登录用户；只返回 published |
| `POST /api/delivery-previews` | 固定源快照并返回分析/几何 | `delivery-preview` | 会话归属；不创建成品 |
| `POST /api/delivery-jobs` | 提交多目标 | `delivery-job` | `Idempotency-Key`；逐项额度预占 |
| `GET /api/delivery-jobs/{id}` | 读取 job 和逐项状态 | `read` | 当前用户；越权 404 |
| `POST /api/delivery-jobs/{id}/items/{item_id}/retry` | 只重试失败项 | `delivery-retry` | `(item, attempt)` 去重 |
| `GET /api/delivery-jobs/{id}/export` | 下载成功项 ZIP | `export` | 当前用户；上限检查 |
| `GET /api/marketing-templates` | 模板和变体 | `read` | 只返回 published |
| `POST /api/marketing-template-previews` | 校验并返回 `LayerDocument` | `delivery-preview` | 填充参数校验 |
| `GET/POST /api/brands` | 品牌配置 | `read/editor-write` | 当前用户；Logo 归属校验 |
| `GET/POST/PATCH /api/admin/delivery-presets` | 管理 preset | `read/editor-write` | 管理员依赖；发布不可变 |

| 错误码 | HTTP | 前端行为 |
|---|---|---|
| `RATE_LIMITED` | 429 | 显示倒计时，不创建任务 |
| `RATE_LIMIT_UNAVAILABLE` | 503 | 提示服务繁忙，可重试 |
| `AUTH_LOCKED` | 429 | 显示重试时间 |
| `ORIGIN_REJECTED` | 403 | 提示请求来源无效 |
| `SOURCE_REVISION_STALE` | 409 | 重新分析源图 |
| `SOURCE_SNAPSHOT_EXPIRED` | 410 | 重新预览 |
| `PRESET_NOT_FOUND` | 404 | 刷新用途列表 |
| `SUBJECT_UNCERTAIN` | 422 | 改用 `contain` 或手工保护框 |
| `TARGET_LIMIT_EXCEEDED` | 422 | 减少目标 |
| `TEMPLATE_VALIDATION_FAILED` | 422 | 定位到具体字段 |
| `EXPORT_TOO_LARGE` | 413 | 拆分下载 |
| `QUOTA_EXHAUSTED` | 409 | 区分“本地适配可用/AI 扩图不可用” |
| `DELIVERY_ITEM_NOT_RETRYABLE` | 409 | 只允许失败项重试 |

## 11. 测试计划

### 11.1 后端

- **纯单元**：几何（横转竖、竖转方、多主体、贴边、不可行区间）、模板编译金样、`remove()`、价格格式化、换行/字号下限。
- **接口**：权限（跨用户 404）、幂等（同 key 两次）、目标上限、源 revision 过期、部分失败、重试、ZIP manifest/尺寸。
- **限流**：策略隔离、并发、滑动窗口边界（59.9s/60.1s）、代理头伪造、Redis 停止/恢复、shadow/enforce。
- **认证**：不存在用户名与错误密码同文案、锁定与恢复、生产默认密钥启动失败。
- **任务**：worker 重入、租约去重、`attempt` 递增、恢复 cron 补投递。

### 11.2 前端

- 纯函数：快捷键守卫、吸附、几何展示参数转换、429 倒计时。
- 建议引入 `vitest` 只测纯逻辑，不引入完整浏览器测试框架；交互和真机用手工清单。
- 手工：Chrome/Edge/Safari 桌面各一次；375×667、390×844、768×1024；一台真实触控设备；一张透明通道图、一张跨域签名 URL 图。
- 重点：输入法组合态、快速连按撤销、跨域缩略图降级、双指结束不误触、软键盘不遮挡、参考线不导出。

### 11.3 回归

- `/create`、`/editor`、`/candidates`、`/marketing`、`/batch` 主链路。
- 旧会话缺少新字段仍可加载；旧 `ratio` 工具仍可用。
- 现有撤销/重做、选区失效、只上墙语义、ZIP manifest 兼容。
- 浏览器控制台无新增未处理异常；画布图片无 CORS 污染导致导出失败。

## 12. 上线、灰度与回滚

建议开关：

```text
rate_limit.mode=off|shadow|enforce
delivery_presets_enabled
delivery_smart_crop_enabled
delivery_outpaint_enabled
marketing_templates_enabled
editor_guides_enabled
```

上线顺序：

1. 迁移和 preset/template 种子发布，功能开关全关。
2. 限流 `shadow` 观察 1–2 天，确认计数、日志、429 结构不误伤。
3. 开放 `contain` 预览和 ZIP，验证尺寸与权限。
4. 开放 `smart_crop`，受控样例 + 少量用户灰度。
5. 开放商品主图模板，再扩到社媒封面和促销海报。
6. 开放 `outpaint`，按用户灰度并核对额度与失败率。
7. 开放移动端底部工具栏和完整手势。

回滚：

- 限流回 `shadow`，仍计数但不拦截；不删除 Redis 计数。
- `smart_crop` 回退时新任务改用 `contain`，旧任务仍可查看下载。
- 模板回退到普通营销图模式，已生成任务保留只读结果。
- 任务表、preset/template 版本不删除，只切读取开关。
- 数据库迁移保持向后兼容，不要求回滚迁移。

## 13. 风险与待确认

### 13.1 业务参数（实施前确认）

| 编号 | 问题 | 建议默认 | 未确认时 |
|---|---|---|---|
| O1 | 首批平台用途 | 通用方图/竖图/横图/4:5 先发；淘宝、小红书、抖音、公众号先 draft | 只开放通用画幅 |
| O2 | 平台尺寸来源 | 每个 preset 必填 `source_url + verified_at` | 标为“项目建议值” |
| O3 | `outpaint` 计费 | 每成功 1 张计 1 个 AI 单位 | 先关闭 |
| O4 | 单次目标上限 | 8 个 | 先灰度 4 个 |
| O5 | 同步 ZIP 上限 | 128 MB / 32 文件 | 超限 413 |
| O6 | 限流阈值 | 采用需求 6.3 建议值 | 先 shadow 1–2 天 |
| O7 | 管理员限流 | 独立较宽策略，不无限豁免 | 保留审计日志 |
| O8 | 参考线持久化 | 只存当前浏览器 | 首期不做跨设备 |

### 13.2 技术风险

| 风险 | 影响 | 处理 |
|---|---|---|
| 限流阈值过严误伤 NAT 用户 | 正常用户不可用 | IP 策略宽于用户策略；先 shadow；按策略配置 |
| Redis 故障 | 重任务不可用或全站 500 | 重任务 503、查询本地降级，明确区分 429/503 |
| 主体检测不稳定 | 裁剪结果不可解释 | 低置信度回退 `contain`；保护框可手工调整；不承诺 OpenCV 识别 |
| provider 不支持 mask | 扩图改商品细节 | 强制提示；不做硬蒙版回贴；按用户灰度 |
| 前端/后端字体与换行不一致 | 模板预览导出错位 | 统一字体文件；服务端实际像素验收；金样测试 |
| 跨域签名 URL 污染 Canvas | 缩略图失败、导出异常 | 复用 `useCanvasImage.safe` 降级；必要时同源代理 |
| ZIP 内存 | API 进程被打满 | 构建前长度/数量/像素上限；超限转 413 |
| 预览快照存储增长 | 对象存储成本 | 24 小时 TTL；任务快照 30 天保留；cron 清理 |
| 模板价格格式 | 浮点误差、显示错误 | `Decimal`/规范化字符串；禁止浮点拼接 |
| 旧会话缺新字段 | 历史会话打不开 | Pydantic/TS 全部默认值；回归测试 |

### 13.3 不能带着上线的假设

- 不能假设 OpenCV 能可靠识别所有商品。
- 不能假设所有 provider 都支持指定画幅或 mask。
- 不能假设前端 Konva 看到的文字就是服务端 Pillow 导出的文字。
- 不能假设每日额度能拦住秒级刷接口。
- 不能假设 Redis 故障时默认放行是安全的。

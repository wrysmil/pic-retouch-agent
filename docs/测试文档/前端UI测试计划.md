> 覆盖工作台（7301）与管理后台（7303）两个前端的全部现有能力。
> 全程使用 **mock 模式**：生图走本地占位图、规划走本地桩，**不产生任何厂商调用费用**。

> 配套材料：
> - 能力盘点（工作台，含逐组件细节）：[UI测试清单-工作台前端.md](../UI测试清单-工作台前端.md)

## 3. mock 模式准备

### 3.1 为什么 mock 模式仍需要两个桩

`MockImageProvider` 只覆盖**图像** provider（生图 / 图编辑 / 超分）。智能体对话走的是文本规划模型，
`ChatOpenAI` 必须连一个真实的 OpenAI 兼容端点，所以额外提供了 `scripts/mock_llm_server.py`
——一个本地 OpenAI 协议桩，把用户指令按关键词映射成工具调用。

| 槽位 | 适配器 | 连接地址 | 说明 |
| --- | --- | --- | --- |
| 生图 | `mock` | `mock://local`（占位，不连网） | 后台新建连接时**地址与密钥都可留空**，不受白名单约束 |
| 文本规划 | `openai_compat` | `http://127.0.0.1:7300/v1` | 真实本地地址，需 `ALLOWED_PROVIDER_HOSTS=allow-localhost` |

### 3.2 准备步骤

```bash
# 1) 中间件
docker compose up -d

# 2) 后端依赖与迁移
cd backend && uv sync --all-extras && uv run alembic upgrade head

# 3) 启动本地 mock 规划桩（后台窗口 A）
cd backend && uv run python scripts/mock_llm_server.py --port 7300

# 4) 放行本地地址（仅规划桩需要；mock 生图连接不需要）
#    .env 里改一行：ALLOWED_PROVIDER_HOSTS=allow-localhost

# 5) 启动后端与 worker（后台窗口 B / C）
cd backend && uv run uvicorn app.main:app --port 7302
cd backend && uv run arq app.worker.WorkerSettings

# 6) 启动两个前端（后台窗口 D / E）
cd frontend && npm run dev        # 7301
cd frontend && npm run dev:admin  # 7303
```

### 3.3 登记 mock 模型（两种方式，二选一）

**方式 A：后台 UI（推荐，顺带验证后台能力）**

1. 打开 http://127.0.0.1:7303/login，用管理员登录
2. 「模型配置 → 厂商连接 → 新建连接」
   - 标识 `mock-image`、厂商 `mock`、适配器 `mock`、显示名称「Mock 本地生图」
   - **Base URL 与 API Key 留空即可**（选 mock 后会自动填 `mock://local`）
3. 「模型清单 → 登记模型」：类型选「生图模型」、连接选上面那条、厂商模型 ID `mock` → 登记并启用
4. 「厂商连接 → 新建连接」：标识 `mock-planner`、适配器 `openai_compat`、
   Base URL `http://127.0.0.1:7300/v1`、API Key `mock`
5. 「模型清单 → 登记模型」：类型选「文本模型」、连接选上面那条、厂商模型 ID `mock-planner` → 登记并启用
6. 「运行版本 → 发布新版本」：文本选 Mock 规划模型、生图选 Mock 生图模型 → 确认发布

**方式 B：脚本（幂等）**

```bash
cd backend && uv run python scripts/register_mock.py
```

> 登记脚本会**停用**原先启用的真实模型（每类只允许一个启用模型）。
> 切回真实厂商时，在后台把 `qwen-image-3.0` 与 `MiniMax-M3.1-Flash` 重新启用并发布新版本即可。

### 3.4 验证 mock 就绪

```bash
cd backend && uv run python scripts/check_mock_mode.py   # 端到端：生图 + 智能体规划
cd backend && uv run python scripts/check_providers.py    # 基础设施 + 规划/生图/抠图自检
```

后台「运行版本 → 连通性测试」三项应全绿：`text` / `image.generate` / `image.edit`。

### 3.5 测试账号

```bash
# 管理员
cd backend && uv run python scripts/init_admin.py create admin Admin@123456
# 普通用户：走工作台 /auth?mode=register 公开注册
```

| 角色 | 账号 | 密码 | 用途 |
| --- | --- | --- | --- |
| 管理员 | `admin` | `Admin@123456` | 后台全部功能 |
| 普通用户 | `uitest` | `uitest123` | 工作台全部功能；后台应 403 |

> **不落盘的凭据**：会话只存在于 `httpOnly` Cookie `session`，前端 JS 读不到。
> 每次开新浏览器上下文都要重新登录。改密码 / 撤销会话 / 停用账号都会让旧 token 立即作废。

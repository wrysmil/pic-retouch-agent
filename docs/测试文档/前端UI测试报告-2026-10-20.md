## 4. 本轮新发现的缺陷（已登记到计划第 8 章）

### D25 拆层在大画布上永久卡死，编辑器被锁死 —— 已修复

- **现象**：`split_layers` 在 2160×3840 画布上进度停在 **55%「修复背景」超过 11 分钟**；
  `tool_runs` 状态永远 `running`；`arq` 的 `job_timeout=300` 没有生效；
  前端因为 `tools.busy` 把工具条、撤销、重做、图层面板全部禁用，**且 UI 上没有任何取消入口**。
- **对照**：同一套代码在 600×600 画布上 46 秒正常完成，产出背景/主体/文字 4 个图层。
- **卡点**：`app/tools/layers.py:90` → `_fill_hole()` → `cv2.inpaint` 在 8MP 图上耗时不可控，
  且跑在 `asyncio.to_thread` 里，arq 无法中断。
- **影响**：用户在真实使用中（生图默认出 1080×1920 / 2160×3840）点一次「拆层」就会把编辑器废掉。
- **修复**：OpenCV 补洞工作图限制在 150 万像素以内，完成后只把遮罩区域回贴原图，洞外像素不重采样。
- **复验**：2160×3840 输入的本地补洞耗时约 **1.06 秒**；对应回归测试通过。

### D26 工作台与后台共用同一个 Cookie —— 已修复

- **现象**：Cookie 名同为 `session`、同 host `127.0.0.1`，而 **Cookie 不区分端口**，
  所以 7301 与 7303 共享登录态。
  实测：普通用户（uitest01）打开后台 `http://127.0.0.1:7303/` 直接落到 **403 页**而不是登录页；
  在后台登录 admin 会把工作台的登录态顶掉。
- **影响**：普通用户无法在后台自行登录（只能先回工作台登出），与 D04/D05 叠加后体验断裂。
- **修复**：后台改用独立 `admin_session` 与 `/auth/admin/*` 接口；工作台仍使用 `session`。
- **浏览器复验**：同一浏览器中工作台保持普通用户 `uitest`，后台同时保持管理员 `admin`，互不覆盖。

### D27 后端校验错误直出英文 —— 已修复

- **现象**：提示词 2000 字 → 页面显示 `String should have at most 1500 characters`；
  后台建号密码 65 位 → 弹窗显示 `String should have at most 64 characters`。
- **原因**：`api/client.ts` 的 `formatDetail` 只剥掉 `Value error,` 前缀，
  pydantic 的 `msg` 原文直接渲染。
- **修复**：服务端统一本地化 Pydantic 常见校验错误，前端继续消费标准 `detail` 结构。
- **浏览器复验**：后台建号输入 65 位密码时显示「密码最多允许 64 个字符」。

### D28 图层缩放滑杆上限 3，后端允许 0.1–8 —— 已修复

- **现象**：图层面板「图层缩放」滑杆 `max=3`，但后端 `scale_layer` 允许 0.1–8，
  UI 侧永远调不到后端允许的上限（0.1–3 段被滑杆步长 0.05 覆盖，>3 不可达）。
- **修复与复验**：滑杆上限统一为 8；右侧浏览器读取到实际属性 `min=0.1, max=8`。

## 8. 复现方式

```bash
# 1) 中间件
docker compose up -d

# 2) mock 规划桩
cd backend && uv run python scripts/mock_llm_server.py --port 7300

# 3) 后端 + worker
cd backend && uv run uvicorn app.main:app --port 7302
cd backend && uv run arq app.worker.WorkerSettings

# 4) 两个前端
cd frontend && npm run dev        # 7301 工作台
cd frontend && npm run dev:admin  # 7303 后台

# 5) 登记并发布 mock 运行版本（幂等）
cd backend && uv run python scripts/register_mock.py

# 6) 自检
cd backend && uv run python scripts/check_mock_mode.py
```

测试账号：管理员 `admin`；普通用户 `uitest01`（本轮新建）、`uitest`。密码仅保存在本地测试环境，不写入仓库。
